## 四、文件修正的原句與新句

### 4.1 原句（含糊，第 159 行）

```markdown
- **Python 端要傳真正的型別。** `as_of_date` 必須是 `date` 物件，`matured_at` 必須是 aware `datetime` 物件——ISO 字串與 `datetime`（即使是午夜）都會被拒絕，不會被靜默轉型。
```

### 4.2 新句（第 159–160 行，主詞明確）

```markdown
- **`as_of_date` 的 Python 型別規則。** Python constructor 只接受真正的 `date` 物件；ISO 日期字串與任何 `datetime`（包含午夜及 aware `datetime`）都會被拒絕，不會被靜默轉型。
- **`matured_at` 的 Python 型別規則。** Python constructor 接受 `None` 或 aware `datetime`；naive `datetime` 與 ISO 時間字串都會被拒絕，不會被靜默轉型。
```

採用 §6.1 提供的文字，未自行改寫。

### 4.3 為什麼新句不再矛盾

| 面向 | 原句 | 新句 |
|---|---|---|
| 主詞 | 一句同時談兩個欄位，句尾的「`datetime` 都會被拒絕」**沒有指明是哪個欄位** | 兩條各自只談一個欄位，主詞寫在開頭 |
| `as_of_date` | 讀者需自行推斷 | 明寫「任何 `datetime`（**包含午夜及 aware `datetime`**）都會被拒絕」 |
| `matured_at` | 可被誤讀為連 aware `datetime` 也被拒絕 | 明寫「**接受** `None` 或 aware `datetime`」，只拒絕 naive 與字串 |
| 與第 153 行的關係 | 互相衝突 | 一致——第 153 行「`matured_at` 只接受 aware datetime」得到呼應而非否定 |

**逐字人工確認（§8 第 7 項）：**

- `as_of_date` → 拒絕字串 ✅、拒絕所有 `datetime`（含午夜與 aware）✅
- `matured_at` → 接受 `None` ✅、接受 aware `datetime` ✅、拒絕 naive `datetime` ✅、拒絕 ISO 字串 ✅

以上四項與 `research.py` 的實際行為一致（該行為已於工作報告 014 §四 4.3、4.5 以獨立探針驗證，本輪未改程式）。
