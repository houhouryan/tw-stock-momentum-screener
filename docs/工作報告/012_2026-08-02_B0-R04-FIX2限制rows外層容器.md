## 三、修復內容

### 3.1 `_canonical_rows()` 改為精確 type identity（§5.2）

**修改前：**

```python
if isinstance(value, str | bytes) or not isinstance(value, Sequence):
    raise ValueError(...)
return tuple(_canonical_json_object(row, ...) for index, row in enumerate(value))
```

**修改後：**

```python
rows_input: list[object] | tuple[object, ...]
if type(value) is list:
    rows_input = cast(list[object], value)
elif type(value) is tuple:
    rows_input = cast(tuple[object, ...], value)
else:
    msg = f"rows 必須是 built-in list 或 tuple，收到 {type(value).__name__}"
    raise ValueError(msg)
return tuple(
    _canonical_json_object(row, f"rows[{index}]")
    for index, row in enumerate(rows_input)
)
```

每個 row 仍交給既有的 `_canonical_json_object()`，**內層 canonical 邏輯完全未動**。

### 3.2 容器對照表

| outer container | 結果 | 說明 |
|---|---|---|
| built-in `list` | **ACCEPT** → runtime `tuple` | JSON round-trip 會把 outer array 解成 list，必須能接受 |
| built-in `tuple` | **ACCEPT** → runtime `tuple` | 直接建構的正常輸入 |
| 自訂序列型別 | **ValidationError** | 即使實作完整介面且元素為合法 dict row |
| `list` 子類別 | **ValidationError** | type identity 不符 |
| `tuple` 子類別 | **ValidationError** | type identity 不符 |
| generator | **ValidationError** | 非 list／tuple |

### 3.3 production 清理（§5.2）

- 移除 `from collections.abc import Mapping, Sequence`。
- 移除檔尾 `_ = Mapping` 與其註解。
- docstring 內提及該兩個名稱的字句改寫為「自訂對映型別」「自訂序列型別」「廣義的抽象介面判斷」，使 §6.2 residual search 真正無命中。

### 3.4 未改動（§3 已通過項目）

public fields、schema、serializer、`__getattribute__` fresh-copy、`_canonical_json_value()`、canonical key ordering、strict scalar、timezone 與 Raw contract **全部維持**。§四 4.3 附不回歸探針。

## 五、問題、偏差與風險

### V-1　我的 docstring 說了一件程式沒做的事

報告 011 §3.3 與程式 docstring 都寫「只對最外層接受 list 或 tuple」，但實作用的是廣義 `isinstance(value, Sequence)`。**敘述與行為不一致**，而我的測試沒有任何一項會抓到這個差距。

`test_rows_must_be_array_of_objects` 測的是 dict、整數 list 與字串 list——這些會因 **row 內容**不是 object 而被拒絕，**完全沒有證明 container 型別本身被檢查**。

本輪的負向 fixture 因此一律提供**合法的 dict rows**，這樣拒絕就只可能來自 outer type。§四 4.2 另加一項 `test_rejection_is_at_container_boundary_not_row_content`：同一批 rows 換成 built-in list 就通過，直接證明邊界位置。

### V-2　風險評估：這次不是 secret 漏洞

與 FIX1 的 snapshot bypass 不同，自訂序列型別的內容**會被重新 canonicalize**，custom object 不會留在 model 內，也沒有 mutable reference 洩漏。實際風險是「未核准的 lazy container 被靜默 materialize 進 domain boundary」與「契約敘述不真實」，屬精確性問題而非安全問題。這與檢查報告 §4.2 的裁定一致。

### V-3　測試檔 `Sequence` import 曾被 ruff 移除，需補回

我在 FIX1 加入 `Iterator, Mapping` import 時，`Sequence` 未被使用而遭 ruff 移除；本輪新增負向 fixture 需要它，collection 因 `NameError` 失敗一次。補回 import 後 202 passed。

這是 lint 自動清理與後續需求的時序問題，**不影響任何契約行為**，據實記錄。

修復輪且範圍由檢查報告精確界定，未另行估算。
