## 二、報告 004 證據更正

> 依檢查報告 R02-F02 要求，本章為獨立更正章節。三類錯誤各含：**原錯誤敘述／實際值／取得實際值的命令／對第一次決策的影響／防止重犯的固定檢查**。

### 2.1 【最嚴重】Ruff 字元清單錯誤——直接導致專案經理核准了不足的方案

**原錯誤敘述**（報告 004 §3.3）：

> 10 項全部同一規則、同一成因：docstring 內的中文全形標點（`，`、`。`、`、`）。

**實際值：** `，`（U+FF0C）、`：`（U+FF1A）、`（`（U+FF08）、`）`（U+FF09）

**取得實際值的命令與輸出：**

```console
$ set +e
$ uv run --frozen ruff check src/hotstock tests --output-format json > /tmp/hotstock-r02-before.json
$ before_exit=$?
$ set -e
$ printf 'BEFORE_EXIT=%s\n' "$before_exit"
BEFORE_EXIT=1

$ uv run --frozen python -c 'import json,sys; data=json.load(sys.stdin); chars=sorted({item["message"].split(chr(96))[1] for item in data}); print("diagnostics",len(data)); print("characters",chars)' < /tmp/hotstock-r02-before.json
diagnostics 10
characters ['（', '）', '，', '：']
```

逐字元與逐檔案分布：

```console
  （  1 筆
  ）  1 筆
  ，  6 筆
  ：  2 筆
  合計 10
按檔案:
  __init__.py  7 筆
  test_package_smoke.py  3 筆
```

**錯在哪：** 我當時只看了終端機**被截斷的前幾筆** diagnostics，看到都是 `FULLWIDTH COMMA`，就**憑「中文常見標點」推想**補上 `。` 與 `、`。實際上 `。` 與 `、` **一筆都沒有出現**，而真正出現的 `：`（2 筆）、`（`（1 筆）、`）`（1 筆）我完全沒看到。這不是抄寫失誤，是**沒有讀完原始輸出就寫摘要**。

**對第一次決策的影響：** 審查者依我的摘要向專案經理建議三字元白名單 `["，","。","、"]`，專案經理據此核准。該清單實測**仍剩 4 個錯誤**（2×`：`、1×`（`、1×`）`）。檢查因此中止並二次請示，專案經理才改核准正確的四字元清單。**我的錯誤證據使一次決策作廢，並多消耗一輪請示。**
