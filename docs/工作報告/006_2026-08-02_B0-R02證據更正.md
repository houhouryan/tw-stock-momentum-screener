## 三、關卡為何只部分有效

### 3.1 實際發生的事

| 時點 | 事件 |
|---|---|
| FIX1 步驟 16 | 核對關卡執行，發現 §一 摘要寫「16」而實際 17 |
| FIX1 步驟 16 | 修正 §一 第 120 行為 17／17／0 |
| FIX1 步驟 16 | **未搜尋全文其他引用「16」之處** |
| FIX1 步驟 18 | 寫入 marker，報告凍結 |
| 檢查報告 005 §3 | **審查者**發現第 239 行仍為「16」、第 240 行步驟引用錯誤 |

### 3.2 關卡設計的缺陷

FIX1 步驟 16 的核對命令是：

```bash
sed -n '/^## 一、Checklist/,/^### §0.2/p' 005_...md | rg -c '^- \[x\]'
```

**這個命令只掃描 §一 的區段範圍。** 它能驗證「§一 的摘要是否等於 §一 的實際勾選數」，但**完全看不到文件其他位置對同一數字的引用**。

換句話說：關卡驗證的是**單一位置的內部自洽**，不是**全文的一致性**。修正一個位置後，其他位置的回指值不會被檢出。

### 3.3 正確的做法

修正任何數值後，必須**對全文搜尋舊值字串**，而非重算單一區段：

```bash
rg -n '16 項|16 勾選' <報告檔>
```

本輪已依此執行（§六 6.5），並將其列為步驟 10 的獨立關卡。

### 3.4 誠實結論

- **不能說**「防重犯流程已完整攔截本次錯誤」。
- **可以說**「防重犯流程攔下了主要摘要的錯誤，但因核對範圍限於單一區段，未攔下次要引用；殘留部分由審查者發現」。
- 這是我在 FIX1 收尾時的第二次同類疏漏——**第一次是寫錯數字，第二次是修正得不徹底**。
