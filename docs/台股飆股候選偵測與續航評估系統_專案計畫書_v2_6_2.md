# 1. 執行摘要

本專案建置一套每日收盤後自動執行的台股候選標的偵測與佐證系統。

系統採**兩輪評分**：

**第一輪**以規則式價量與籌碼訊號計算個股分數；若 M0 證明 MOPS 公告量與品質足夠，再加入公告分數。第一輪取前 30 名；新聞只作探索性分析與風險警示，不為新聞另開正式候選入口。

**第二輪**以「族群共同公式、個股 LOO 調整乘數」重新排序，取前 10 名為正式候選。乘數由族群啟動天數、排除該股後的龍頭強度、廣度變化與法人流向計算。

**產品主張不是預測，而是縮減、佐證與追蹤：**

> 把全市場約 1,800 檔壓縮成當日值得關注的候選，說明每一檔的入選依據，並自動追蹤與公開後續表現。任一歷史日期可重播當時可得的價量、籌碼與族群計算；主題分類屬回顧式資料，新聞只從合法來源實際啟用日起可用。

最終成果包含：可運作的每日系統、可回溯的重播介面、歷史回測與消融比較報告、LLM 抽取品質的人工標註驗證，以及誠實揭露的限制清單。

# 2. 專案背景與問題定義

台股中部分個股會在短期內出現顯著高於市場的漲幅。這類走勢通常涉及價格突破、成交量放大、法人資金流入，以及訂單或營收等公開催化劑的組合。且台股飆股極少單獨發動，多為整個族群同步啟動、由龍頭向外擴散。

單純使用技術分析會忽略催化劑；單純閱讀消息又可能在資訊已反映後才追價；只看個股會錯過族群擴散的時間差。本專案將三者整合，建立可系統化驗證的候選偵測機制。

本專案不試圖證明任何方法必然獲利，而是要可信地回答：

> 公開的價量、籌碼、族群動能與消息資訊，經規則式計算與 LLM 事件抽取後，能否使候選股票未來成為高品質超額動能事件的比例，顯著高於隨機選股或簡單動能規則？

**本專案事前承認：** 新聞來源、啟用日與樣本量目前未定，因此新聞版 `D-news` 只作 exploratory 分析，不作顯著性判定。**H4 只指公告增益**，且僅在 M0 證明 MOPS 可穩定回補、樣本量達檢定力門檻時才啟動；否則標記為「資料不足，未檢定」。

# 3. 專案目標

## 3.1 核心目標

1. 建立具明確數學定義、且統計上可評估的候選標籤。
2. 建立每日收盤後可自動執行的兩輪候選偵測流程。
3. 將價量、籌碼、族群與條件式公告資訊整合為可解釋的排序分數。
4. 使用現成 LLM 將合法取得的公告或消息文字轉為結構化欄位，並以人工標註驗證其可靠度。
5. 以歷史回放、時間切分及前瞻追蹤驗證系統。
6. 產生可追溯的候選清單，清楚呈現入選原因與原始證據連結。
7. 提供可操作的使用者介面；歷史日期重播以該日期實際可得的資料面向為準。
8. 建立完整報告，無論結果正面或負面皆形成可信結論。

## 3.2 次要目標

1. 比較三個主要版本：純價量／＋籌碼／＋族群；資料充分時另做公告版，新聞版只作探索性比較。
2. 分析系統在多頭、空頭與盤整市場的差異。
3. 建立候選股後續 5、10、20 日表現成績單並自動公開。
4. 比較固定權重、條件式學習權重與等權排名三種融合方式。
5. 在 gold set 上量化 LLM 抽取品質；不同規模模型比較為 P1。

## 3.3 非目標

本期不追求：保證找到所有飆股、保證獲利、預測未公開資訊、盤中即時交易、自動下單、智慧停利停損、投資組合最佳化、自行訓練或微調大型模型、多代理人自主交易、社群輿情分析、提供投資建議。

# 4. 專案關鍵決策

## 4.1 不自行訓練大型模型

年底前資源投入於資料正確性、時點控制、標籤定義、訊號計算、回測可信度、每日自動化與使用者介面。LLM 採現成服務或現成可部署模型。

**本項排除的是大型語言模型的訓練與微調，不包含統計模型。** 本案以固定權重作產品預設；資料量與時間切分均通過門檻時，才以邏輯迴歸學習第一輪三面向權重（§13.6）。梯度提升樹僅為 P1 效果上限參考。

## 4.2 LLM 不是決策者，出現在三個位置

| | LLM ⓪ 主題成分表 | LLM ① 消息抽取 | LLM ② 敘述生成 |
|---|---|---|---|
| 位置 | 系統建置期 | 第一輪之前 | 第二輪之後 |
| 輸入 | 公司產品資料 | 單則消息文字 | `candidate_card` |
| 輸出 | `{theme, members[], evidence, confidence}` | §12.3.1 JSON | 2–4 句中文 |
| 進入分數 | 間接（決定族群歸屬） | **公告條件式進入；新聞不進正式模型** | **絕對不進入** |
| 驗證 | 人工抽驗 precision／recall | 依欄位型態使用 κ、macro-F1 與數值誤差 | 數字一致性自動檢查 |
| 頻率 | 建置期一次 ＋ 季度檢查 | 公告每日；新聞自合法來源啟用日起 | P1；模板為 P0 |
| 溫度 | 0 | 0 | 0 |

**核心原則：LLM 讀文字填表格，程式算分數，LLM 再把算好的結果講成人話。**

程式碼層面必須物理隔離：`narrative` 欄位存放於獨立資料表並標記 `display_only`，不得被融合引擎讀取。

## 4.3 抽取可驗證，評分不可驗證

這是本案所有 LLM 設計的判準：

| | 抽取任務 | 評分任務 |
|---|---|---|
| 例 | 「原文有沒有寫金額？寫多少？」 | 「這則消息值 1.8 倍乘數」 |
| 有標準答案 | **有**，翻開原文即知 | **沒有**，除非知道未來 |
| 記憶污染會否改變答案 | 不會（原文寫 12 億就是 12 億） | 會，且無法察覺 |
| 可否用 gold set 驗證 | 可 | 不可 |

因此：**LLM 只做抽取與分類，不做影響力評分，且不得單獨驅動任何硬性決策。** 硬否決只能由 MOPS 原文、明確詞組與否定語境檢查共同觸發；LLM 欄位只作定位與警示。

### 4.3.1 主觀評分欄位的定位（v2.6 釐清）

v2.5.2 一方面宣稱「LLM 不做影響力評分」，另一方面保留 `materiality`（重大性 0–5）並讓 LLM 判斷結果影響風險否決，**此為內部矛盾**。修正如下：

| 欄位 | 是否保留 | 用途 | 禁止用途 |
|---|---|---|---|
| `specificity`（具體性） | 保留 | 作為**軟性特徵**進入分數 | 不得驅動硬規則 |
| `materiality`（重大性） | 保留 | 同上 | **不得作為風險否決依據** |

**風險否決一律由程式規則決定**（見 §13.1.1），並直接比對 MOPS 原文；不以 LLM confidence、`specificity`、`materiality` 或新聞內容刪除候選。

**理由：** 硬否決會直接移除一檔候選，屬不可逆決策，必須可稽核、可重跑、可解釋。以無標準答案的主觀評分驅動不可逆決策，違反本節「抽取可驗證、評分不可驗證」的判準。

`materiality` 與 `specificity` 是否保留，由 M0 的序數一致性實驗決定；兩欄即使保留，也只能作軟性證據欄位。

## 4.4 聚焦「續航」與「擴散」

系統偵測兩種情境：

1. **個股續航**：已出現價量、籌碼或消息異常後，未來 10 個交易日是否維持超額強勢。
2. **族群擴散**：龍頭已發動、族群啟動初期，同族群中已有自身確認訊號但尚未充分反映的個股。

系統不主張能預知尚未公開消息造成的突然起漲。

## 4.5 結論可信優先於結論漂亮

即使結果顯示消息模組無顯著增益、系統只在多頭有效、或扣除成本後無法勝過基準，只要資料、回測與比較方法可信，仍為有效成果。

**但「不顯著」必須能被解釋。** 因此本案於 §14.6 事前計算最小可偵測效果，使報告能區分「效果不存在」與「樣本不足以判定」。

## 4.6 法律定位（v2.6 修正）

### 4.6.1 用詞迴避不等於免責

v2.5.2 稱「不使用建議二字」為法規考量，此理解不正確。

依金管會法規資料庫之[證券投資信託及顧問法第 4 條](https://law.fsc.gov.tw/LawContent.aspx?id=FL030633)，證券投資顧問係指直接或間接取得報酬，並就特定投資或交易事項提供分析意見或推介建議。

構成要件有二，**與頁面上出現什麼字眼無關**：

1. **取得報酬**（直接或間接）
2. **對特定證券提供分析意見或推介建議**

**本系統輸出的正是「個別有價證券之結論」**，因此第 2 項要件實質上已成立。**真正的保護因素是第 1 項不成立——本期無任何報酬。**

本節僅作專題範圍管理，不構成法律意見；若未來改為公開營利服務，須在上線前另行取得正式法律意見。

### 4.6.2 本期定位與紅線

| 情境 | 風險評估 |
|---|---|
| 校內專題、口試展示、非營利、封閉使用 | **本期定位**，因無報酬，不構成第 4 條之證券投資顧問 |
| 對外公開但完全免費、無任何直接或間接收益 | 風險較低，但仍應審慎 |
| **收費、訂閱、廣告分潤、以此招攬客戶、換取任何形式對價** | **已可能構成第 4 條，須先取得正式法律意見與主管機關許可** |

**紅線（寫入專案守則）：** 本系統於取得正式法律意見前，**不得以任何形式收費或換取對價**，包括訂閱、贊助、廣告、導流分潤、或以系統作為招攬其他服務之工具。

### 4.6.3 用詞規範仍然保留

UI、推播與報告中不得出現買進、賣出、目標價、建議部位、勝率預測等字眼。

**但須理解其定位已改變：這是降低誤解與管理使用者期待的產品規範，不是法律豁免。** 兩者不可混為一談，此區分亦為 §22 口試之必答內容。

# 6. 核心研究問題與假設

## 6.1 主要研究問題

在每日固定決策時間，僅使用當時已公開的價量、法人籌碼、融資融券、族群動能與消息資訊，透過規則式量化訊號及現成 LLM 之事件抽取，能否提高未來 10 個交易日高品質超額動能事件的偵測精確率？

## 6.2 次要研究問題

1. 籌碼資訊加入價量訊號後，是否提高 Precision 與 PR-AUC？
2. 族群乘數是否在個股訊號之外提供額外增益？
3. 若 MOPS 公告資料量足夠，公告抽取特徵是否在價量、籌碼、族群之外提供額外增益？
4. 系統是否只在多頭市場有效？
5. 候選分數是否與未來超額報酬呈現單調關係？
6. 學習權重是否優於先驗權重與等權排名？
7. 現成 LLM 對台股消息的結構化抽取，與人工標註的一致程度為何？
8. LLM 建立的主題成分表，與人工分類的一致程度為何？

## 6.3 研究假設

| 編號 | 假設 | 可判定性 |
|---|---|---|
| H1 | 價量規則可使正樣本率高於隨機基準 | ✅ |
| H2 | 加入籌碼後優於只有價量 | ✅ |
| H3 | 加入族群乘數後優於個股訊號 | ✅ |
| H4 | 加入 MOPS 公告特徵後優於 B+ | ⚠️ **條件式**：M0 與 MDE 門檻均通過才檢定 |
| H5 | 系統在多頭市場表現優於空頭市場 | ✅ |
| H6 | MOPS 明確否認／取消規則的人工抽驗 precision ≥ 95% | ⚠️ 受實際觸發案例數限制 |
| H7 | LLM 消息抽取在 gold set 達預先註冊的欄位別門檻 | ✅ 但受 180 則規模與類別分布限制 |
| H8 | LLM 主題分類在所選主題達 precision、recall 各 ≥ 85% | ✅ 但不可推論至未抽驗主題 |
| H9 | 未套用族群乘數的事件級樣本中，啟動天數與續航呈倒 U 形 | ✅ 以 holdout 一次檢驗 |
| H10 | 未套用延伸度加權的事件級樣本中，延伸天數與續航呈倒 U 形 | ✅ 以 holdout 一次檢驗 |

**H4 為條件式假設**：資料門檻未通過時直接標示「未檢定」，不得改以短期新聞資料替代。H7、H8 不依賴市場正樣本率，但仍受 gold set 規模、類別分布與主題代表性限制。

**基準必須使用報酬指數（含息），不可使用價格指數。** 不含息價格指數會忽略股息，使個股相對報酬偏高；實際偏差須由本案以兩種指數在研究期間的差額實測，不預先承諾固定年化百分比。

## 8.2 Point-in-time 原則

每筆資料保存：`event_date`、`published_at`、`first_seen_at`、`retrieved_at`、`updated_at`、`available_from`、`source`、`revision_number`。

每日決策時間：**台北時間 21:30**。只有 `available_from <= decision_timestamp` 的資料可進入當日判斷。

**擷取截止時間為 21:25。** 21:25 之後到達的資料一律計入隔日。資料未到時標記缺值，**不得沿用前一日數值**，也**不得延後決策時間**。

## 8.3 PIT 分級（誠實揭露）

| 期間與來源 | PIT 等級 | 說明 |
|---|---|---|
| 2019–2026/7 價量籌碼（第三方彙整） | **準 PIT** | 已控制未來資料洩漏，但無法還原「當時公布的原始版本」 |
| 合法新聞來源實際啟用日後 | **嚴格 PIT** | `first_seen_at` 即實際取得時間；來源別記錄啟用與中斷區間 |
| 2026/11 上線後全流程 | **嚴格 PIT** | 自建擷取器逐日累積 |

準 PIT 的已知偏差：

- 三大法人：部分成交（盤後定價、鉅額配對）可能於初次公布後才被補計進當日統計
- 月營收：公司事後更正時，第三方來源多半只保留最新值

此揭露為 AC-23（誠實揭露）的必要內容。

## 8.4 原始價與還原價分離

- **原始價**：成交判斷、漲跌停、10 元門檻、成交金額、交易成本
- **還原價**：報酬率、均線、相對強度、標籤計算

欄位命名強制區分：`close_adj` / `close_raw`，不得使用 `close`。

**還原價必須驗證：** 抽 20 檔（含 5 檔已下市、3 檔有減資或面額變更），與證交所除權除息計算結果表自行推算的結果對照，誤差需可解釋。此為 8/31 關卡項目。

## 8.5 消息面資料策略（本版核心改動）

### 8.5.1 為什麼不回補歷史新聞

2019–2025 的財經新聞無可信 `published_at`：網站分頁只回溯數月至一兩年、舊 URL 大量失效、時間戳多為「最後更新時間」而非首次發布時間、覆蓋率不明。**覆蓋率不明的語料無法支撐任何覆蓋率相關的研究結論。**

### 8.5.2 先確認使用權，再啟動擷取

新聞資料具時效性，但資料損失不能凌駕來源條款。每個來源依下列順序處理：

1. 記錄使用條款、著作權聲明、`robots.txt`、RSS／API 授權範圍與檢查日期。
2. 判定可保存的欄位、是否可交由 LLM 處理、是否可於 UI 顯示；不確定者先排除或取得書面許可。
3. 以 3–7 日 pilot 驗證穩定度、重複率、時區、公司對應率與限速。
4. 通過後才標記 `license_status = approved` 並啟用正式排程。

`robots.txt` 是爬蟲存取規則，不是著作權或 AI 使用授權（[RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html)）。UDN 的[著作權聲明](https://udn.com/page/topic/495)與[robots.txt](https://udn.com/robots.txt)明示未經書面同意不得將內容用於 AI／軟體用途，因此**未取得書面同意不得納入**。自由時報的[著作權聲明](https://service.ltn.com.tw/copyright)亦限制未授權重製與利用，未確認授權範圍前不得保存全文或送入 LLM。

新聞樣本量不預先承諾。各來源的實際啟用日、日均則數、去重率與中斷區間於 M6 統計後寫入報告。

| D-ann vs B+（公告增益，H4） | 視 M0 回補結果 | ⚠️ 通過 MDE 門檻才檢定 |

| LLM 抽取品質（H7） | gold set 180 則 | 受類別分布限制 |

報告寫法：

> 新聞資料來自通過條款檢查之來源，各來源期間與中斷區間如實列示。新聞同時參與 prompt、Schema 與展示開發，因此 D-news 只屬探索性分析，不構成樣本外驗證，也不用於支持 H4。

## 8.6 公司重大訊息：待八月統計後定案

### 8.6.1 v2.0–v2.4 的認知錯誤（本版修正）

前版 §12.4 稱「取得或處分資產（重大訂單常走此類）」，**此為錯誤**。該準則規範的是公司取得或處分**資產**（不動產、設備、有價證券、無形資產），有明確的公告格式與金額標準。**客戶下訂單屬營業收入合約，不在該條射程內。**

### 8.6.2 實際規定

證交所[上市公司重大訊息處理程序第 4 條](https://twse-regulation.twse.com.tw/TW/law/DOC01_print.aspx?FLCODE=FL007111&FLNO=4)現行共有 51 個款次，包含發生即須發布、達金額或比例標準及概括條款等情況；申報時限依同程序[第 6 條](https://twse-regulation.twse.com.tw/TW/law/DOC01.aspx?FLCODE=FL007111&FLNO=6)判定。

**⚠️ 上市與上櫃的款次編號不同（v2.5.1 補充，影響實作）：** 上櫃適用櫃買中心之對應處理程序；櫃買中心[2026 年重訊問答集](https://dsp.tpex.org.tw/storage/co_download/%E4%B8%8A%E8%88%88%E6%AB%83%E5%85%AC%E5%8F%B8%E9%87%8D%E5%A4%A7%E8%A8%8A%E6%81%AF%E7%99%BC%E5%B8%83%E6%87%89%E6%B3%A8%E6%84%8F%E4%BA%8B%E9%A0%85%E5%8F%83%E8%80%83%E5%95%8F%E7%AD%94%E9%9B%86.pdf?t=20260114)所示，第 4 條第 1 項為 **53 個款次**（52 款明確內容 ＋ 1 款概括條款）。**兩市場的款次編號無法直接對應**，故 §8.6.3 之白名單必須維護 TWSE 與 TPEx 兩套對照表，不可共用一組編號。此為 M0 統計實驗須一併確認的項目。

**申報時限（影響 PIT，v2.5.1 補充）：**

| 情境 | 時限 |
|---|---|
| 一般各款情事 | 事實發生日起**次一營業日交易時間開始二小時前**（約次日 07:00 前） |
| 暫停或恢復交易（第 40 款） | 公告後 1 小時內 |
| 媒體報導符合第 6 條第 2 款觸發條件 | **立即輸入，至遲不得逾發現後 2 小時** |

**對本系統的實際影響：** 多數重訊之法定時限為「次一營業日開盤前」，代表 T 日發生的事件，其公告可能要到 **T+1 日清晨**才出現在公開資訊觀測站——**晚於 T 日 21:30 的決策時間**。因此該則公告會自然落在 T+1 日的判斷中，而非 T 日。

此行為由 §8.2 的 `available_from` 機制自動處理，無須額外邏輯，但有兩個必須知道的後果：

1. **回測與實盤一致**，不會產生洩漏；
2. 重訊可能晚於媒體報導，也可能由公司先行發布；實際先後順序須以 `first_seen_at` 與公告時間量測，不預設新聞一定先到。

**M0 須驗證：** 抽樣 30 則 2025 年重訊，比對 `事實發生日` 與 `公告時間`，量化實際落後幅度並寫入報告。

| 事項 | 是否強制公告 |
|---|---|
| 一般客戶訂單 | **不用** |
| 達重大標準之重要契約 | 要，有金額門檻 |
| **澄清媒體報導** | 僅在符合適用規章的觸發條件時須公告；時限依公司所屬市場與當時規章判定，不概括宣稱每篇報導皆須於 2 小時內回應 |
| 減產、停工 | 要（達影響比例標準） |
| 財務預測公布或更新 | 要 |
| 增資、可轉債、董事會重大決議 | 要 |

「取得 X 億訂單」可能屬自願性揭露，因此覆蓋率與公司規模分布不可假設均勻；M0 必須實測公司家數、市值分布與重複揭露情形。

### 8.6.3 若採用，白名單須改為雙軌

1. **條件式強制類別**：符合適用規章觸發條件的澄清媒體報導、財測更新、減產停工、董事會重大決議、重大訴訟、主管機關調查
2. **主旨關鍵字**：訂單、合約、擴產、認證、量產、客戶

單靠類別編號無法涵蓋訂單類（散在概括條款）。

### 8.6.4 為什麼這是關鍵決策點

**若八月統計顯示公告可穩定取得、公司分布可接受，且依實際事件數計算之 MDE 足以回答 H4，才回補至 2022。** 這是 H4 成為可判定假設的唯一正式路徑；門檻由檢定力決定，不使用任意的固定 2,000 則／300 家規則。

因此 §18 M0 的公告統計實驗必須在八月完成。

### 8.6.5 澄清媒體報導的特殊價值

公司發現足以影響行情或與事實不符的媒體報導時，應於規定期限內輸入重大訊息說明；這不代表公司必須回應每一篇媒體報導，也不代表內容已由第三方獨立查證。

系統取得的是**公司透過官方平台發布的正式說明**。其中明確否認或取消者可進 §13.1.1 的原文規則；其餘僅作證據與風險警示。

## 8.7 歷史標的池

**實作要點：資料一律以「日期」為單位擷取全市場檔案，不以「股票代號」為單位擷取歷史。** 逐日期擷取會自然包含當日交易但日後下市的股票，存活偏誤自動解決。

**已知限制：** 警示、處置與全額交割股的歷史狀態序列無乾淨公開時序資料，本期不回補。歷史期不套用此過濾並列為限制；前瞻期套用當期資料。

# 10. 標籤定義

## 10.0 三層分離原則（v2.6 新增，最重要的結構修正）

外部審查指出 v2.5.2 將「可成交性」寫入標籤與硬規則層，造成兩個問題：T 日 21:30 無法得知 T+1 之開盤與最低價（**未來資料洩漏**）；且將 T+1 鎖死者事後剔除，會使評估樣本排除掉最強的一批結果（**選擇偏誤**）。

本版明確分為三層，各層時點規則不同，**不得互相混用**：

| 層 | 內容 | 可用資訊 | 位置 |
|---|---|---|---|
| **L-A 決策層** | Gate、風險否決、評分排序 | 僅 T 日 21:30 前已公開者 | §13 |
| **L-B 標籤層** | DEF-RANK 等標籤計算 | 允許使用未來資料（標籤的定義即如此） | §10.1 |
| **L-C 成交模擬層** | T+1 進場、no-fill、成本、滑價 | 允許使用未來資料 | §10.4、§14.2 |

**關鍵規則：可成交性判定只存在於 L-C，不得出現在 L-A，也不作為 L-B 的樣本篩選條件。**

## 10.1 主標籤：DEF-RANK（v2.6 修正）

> T 日收盤後出現訊號，該股 **T 日收盤至 T+10 收盤**之相對市場超額報酬，是否落在當日標的池的**前 5%**。

**正樣本 Label = 1**，同時符合：

1. 自 **T 日收盤**至 **T+10 收盤**之報酬，減去同期對應市場報酬指數之報酬（**同為收盤對收盤**），其排名落在當日標的池前 5%
2. 資料完整（見 10.1.2）
3. 符合 T 日標的池資格

**v2.6 移除的條件：** 原第 1 項「T+1 存在合理成交可能」已刪除。理由見 §10.0 與 §10.4。

### 10.1.1 為什麼改為收盤對收盤

v2.5.2 以「T+1 開盤價進場」計算個股報酬，卻以收盤值計算市場指數報酬，**兩者時間口徑不一致**，超額報酬因此混入一段無法對應的隔夜跳空。

改為收盤對收盤後：

- 個股與指數口徑一致，超額報酬定義乾淨
- 標籤與「能不能買到」完全脫鉤，L-B 與 L-C 責任分明
- T+1 開盤進場之實務落差，全部由 §14.2 交易模擬層呈現，且該落差本身即為研究發現

### 10.1.2 前 5% 的精確定義（v2.6 補齊）

v2.5.2 稱「正樣本率精確等於 5%」為過度簡化。實際規則：

| 項目 | 規則 |
|---|---|
| 取樣數 | 當日有效樣本數 N，正樣本數 = `ceil(0.05 × N)` |
| 有效樣本 | 須符合 T 日標的池資格，**且 T→T+10 之報酬序列完整可計算** |
| 並列處理 | 以超額報酬降冪排序；並列時取 `method='min'` 之排名，若因並列導致超出 `ceil(0.05×N)`，**並列者全數列為正樣本**（寧可略高於 5%，不以任意規則切斷相同報酬者） |
| 停牌 | T→T+10 期間停牌但最終有收盤價者，以實際可得之收盤價計算，標記 `has_halt=1` |
| 期間下市或長期停牌 | 無法計算 T+10 報酬者，標籤為 **NaN**，排除於分類評估之外，並統計其比例寫入報告 |
| 缺值 | 任一價格缺失導致報酬不可計算者，同上標記 NaN |

**因此實際正樣本率接近但不保證等於 5%。** `ceil`、並列與 NaN 都會使實際比例變動；每年實際值須由資料計算並列於報告，不預先承諾固定上限。

**採用理由（修正後表述）：** 正樣本率穩定在約 5%，跨期可比；事件數為絕對門檻標籤的 3–5 倍；不受市場整體漲跌影響。**注意：此 5% 為「全標的池」之基準，不等於模型評估集合之基準，見 §14.1.1。**

## 10.2 副標籤

**DEF-CONTINUATION**：未來 10 日超額報酬 ≥ 20%，期間最大回撤 ≤ 15%，8%–20% 為緩衝帶標記 NaN。

**報告中須同時呈現「緩衝帶視為負樣本」的版本**，因為排除緩衝帶會虛增 precision，此為必問項。

**DEF-SURGE**：未來 20 日內最高可實現漲幅 ≥ 30%，超額報酬 ≥ 20%，最大回撤 ≤ 15%。

## 10.3 標籤的正當性

標籤 y 使用未來資料計算，**這不是洩漏，這是標籤的定義**。y 由版本化行情資料與固定函式確定性算出，不涉及模型判斷；原始資料修訂或缺漏仍須保留版本與驗證紀錄，不能宣稱資料本身永遠 100% 正確。

洩漏的定義是特徵 X 使用了決策時點之後的資訊。X 與 y 的時點規則不同，不可混淆。

## 10.4 成交模擬與 no-fill 處理（v2.6 修正）

**v2.5.2 的錯誤：** 將 T+1 鎖死者「樣本剔除」。系統在 T 日確實選中了該股，事後刪除等同假裝當時沒選到，會使評估樣本系統性排除最強的一批結果，**precision 與報酬同時失真**。

**修正後規則：**

| 判定 | 定義 | 處理 |
|---|---|---|
| **assumed no-fill（保守）** | T+1 開盤價 = 漲停價 **且** T+1 最低價 = 漲停價 | 標記 `filled = false`；**樣本保留** |
| filled | 其餘情形 | 以 T+1 開盤價進場 |

**兩層分別報告，不得合併：**

1. **訊號品質（分類層）**：所有被選中的候選皆納入，含 no-fill 者。此層回答「系統選得準不準」。
2. **實際成交率與交易績效（模擬層）**：no-fill 者記為未成交。`fill_rate` 的分母包含所有候選；交易報酬另分為 `return_filled_only`（只含成交交易）與 `return_opportunity`（no-fill 記 0）兩種口徑，兩者不得混寫。

**交易時點固定：** T+1 開盤進場、T+10 收盤出場；若中間下市、長期停牌或資料不足，依預先註冊的最後可得價處理並列入例外表。最大回撤與累積報酬以「每日新候選等權、每筆名目金額相同、持有期重疊可並存」的研究帳戶計算；不進行部位最佳化。

日線 OHLCV 無法知道委託進入漲停排隊的先後，因此 `filled=false` 是**保守代理值，不是假裝知道真實成交結果**。正式報告同時提供兩個邊界：保守情境將鎖漲停視為 no-fill；樂觀情境將當日有成交量者視為可在漲停價成交。兩者差距即為撮合不確定性，不得只報較漂亮的一邊。

**必報指標：** 每日成交率、A 級候選之 no-fill 比例、`return_filled_only`、`return_opportunity`，以及「若全部可成交」與「實際可成交」兩種假設下的績效差距。

**此落差本身即為重要研究發現**——它量化了「紙上策略」與「可執行策略」的距離，且是多數坊間選股服務刻意不談的部分。

## 10.5 事件去重

事件邊界不得使用未來標籤決定。正式事件定義為：某股在至少 10 個交易日未通過 Gate 後，再次通過 Gate 的第一天；同一事件內後續入選日保留於每日表，但事件級主分析只使用首日。若連續未通過不足 10 日，仍視為同一事件。此規則只依 T 日以前資訊，可避免用「第一個正樣本日」造成標籤導向的選擇偏誤。

## 10.6 實作參考

DEF-CONTINUATION 本質為 triple barrier method。可參考 `mlfinpy` 的向量化路徑掃描實作，但 barrier 需改為相對市場的超額報酬序列。

文獻依據：Lopez de Prado, *Advances in Financial Machine Learning*, Ch.3。本案「Gate ＋ 排序」兩層架構對應 meta-labeling 概念。

# 11. 訊號與特徵

## 11.0 訊號設計原則

1. 每個訊號必須可獨立計算、可獨立開關
2. 所有門檻寫在 YAML，程式只讀不寫
3. 每個門檻須給參數掃描範圍，供 §13.7 高原檢查
4. 訊號之間不得互相依賴計算結果

## 11.1 P0 價量訊號

| 編號 | 名稱 | 條件 | 掃描範圍 |
|---|---|---|---|
| SIG-V01 | 爆量攻擊 | T 日量 ≥ 20 日均量 **2.5** 倍、收紅、成交金額 ≥ 5,000 萬 | 2.0–3.5 |
| SIG-P01 | 創波段新高 | 收盤 ≥ 過去 **60** 日最高收盤、收盤位置 ≥ 0.7 | 40–90 日 |
| SIG-P02 | 帶量長紅突破 | 漲幅 ≥ **5%**、站上 20 日均線、同時符合 SIG-V01 | 3%–7% |
| SIG-R01 | 雙週期相對強度 | 60 日報酬排名前 **15%** 且 20 日報酬排名前 **10%** | 10%–25% / 5%–20% |

**SIG-R01 的排名必須對照當日標的池計算，不可對照現存股票清單。**

## 11.2 P0 籌碼訊號

| 編號 | 名稱 | 條件 | 掃描範圍 |
|---|---|---|---|
| SIG-C01 | 法人連買 | 外資或投信連續買超 ≥ **3** 日 | 2–5 日 |
| SIG-C02 | 投信連續買超 | 投信連買 ≥ **2** 日 | 2–4 日 |

**累計買超需除以流通股數或近 20 日均量正規化。** 買超 5,000 張對台積電是雜訊，對小型股是重大事件。

## 11.3 波形特徵

- 收盤位置 `(C - L) / (H - L)`
- 盤整壓縮度：過去 N 日 `(最高 - 最低) / 均價`
- 上影線比例（連續長上影為負面訊號）
- 量價確認：上漲日均量 ÷ 下跌日均量
- 跳空缺口：開盤價 vs 前收

**明確不做：** 型態辨識（頭肩底、旗形等，無標準定義且無穩健證據）；將 K 線圖截圖交由多模態模型判讀（不可重現，且圖上座標軸與日期直接洩漏未來資訊）。

## 11.4 延伸度特徵

現行特徵（60 日 RS、20 日 RS、創新高）系統性偏袒已上漲多日之個股，而模型**沒有任何欄位可表達「這檔已飆幾天」**，因此無法自行修正。

| 欄位 | 說明 |
|---|---|
| `days_since_first_gate` | 本波啟動至今交易日數 |
| `run_up_since_gate` | 本波啟動以來累積漲幅 |
| `ext_from_ma20` | 收盤對 20 日均線乖離率 |
| `consecutive_days` | 連續入選天數 |

對應 H10（倒 U 假設）：剛啟動時訊號未確認，上漲過久後動能衰竭，中段為甜蜜區。

## 11.5 市場環境（regime）特徵

| 欄位 | 說明 |
|---|---|
| `mkt_regime` | 多頭／盤整／空頭（由指數位階與均線關係判定） |
| `mkt_breadth` | 全市場上漲家數佔比 |

寬表以 `mkt_regime_score ∈ {-1,0,1}` 與 `mkt_breadth` 兩個純數值欄位保存。產品固定權重不直接學習交互作用；市場狀態主要用於 H5 分組報告，完整寬表比較模型才可使用。

## 11.6 族群乘數（本版收斂）

### 11.6.1 為什麼族群不做成一組特徵

v2.2–v2.4 曾將族群拆為動能、籌碼、消息、個股相對位置四組共 19–22 欄。本版收斂為**單一乘數**，理由：

1. 族群消息特徵依賴新聞歷史（不可得）
2. 欄位過多使 §14.6 的 MDE 惡化
3. 族群的作用是「整體抬升或壓抑」，本質是一個純量，不需拆成多欄
4. 乘法對「無族群訊號乘 1.0」的處理比加權歸一化自然

### 11.6.2 公式

```python
theme_multiplier = 1.0 + (
    0.15 * theme_ignition_curve   # 啟動天數倒 U
  + 0.10 * theme_leader_strength  # 龍頭強度
  + 0.08 * theme_breadth_rising   # 上漲家數「在增加」（變化量，非水位）
  + 0.06 * theme_money_flow       # 族群法人淨買超佔均額
)
theme_multiplier = clip(theme_multiplier, 0.85, 1.35)
```

**四個輸入全部來自既有價量籌碼資料，零新資料源。**

**v2.6 措辭修正：** v2.5.2 稱「無門檻、無 if-else」並不正確——§11.6.3 之啟動判定使用 0.8／0.5 門檻，倒 U 曲線使用 5 天／12 天／20 天分段。正確表述為：**四個輸入本身為連續值，但啟動狀態之判定與倒 U 分段確實包含門檻，故該等門檻一律列入 M6 參數高原掃描**（§11.6.2.1、§11.6.3）。

係數與 clip 範圍進 M6 參數高原掃描，現階段為初值。

### 11.6.2.0 leave-one-out：不得用自己的漲幅替自己加分

外部審查指出一項自我參照缺陷：若某股本身即為族群龍頭，`theme_leader_strength` 會由該股自己的報酬決定，等同**用自己的漲幅推高自己的分數**；`theme_breadth_rising` 與 `theme_money_flow` 亦同。

**正式規則：三個可低成本排除自身的橫斷面輸入一律採 leave-one-out；路徑相依的 ignition 使用族群共同狀態，但必須另做敏感度檢查。**

| 輸入 | LOO 作法 |
|---|---|
| `theme_leader_strength` | 取「排除該股後」族群內最強成分股之報酬百分位 |
| `theme_breadth_rising` | 分子分母皆排除該股 |
| `theme_money_flow` | 排除該股之法人買超與成交金額 |
| `theme_ignition_curve` | 使用族群共同啟動序列；M6 抽樣比較完整 LOO 版本的啟動日差異 |

`leader_strength` 以族群第一、第二大值向量化；breadth 與 money-flow 以「族群總和 − 該股值」計算。三者成本低，不得因工程方便省略。

**成分股 < 6 檔時**（扣除自身後不足 5 檔），乘數設為 1.0 並標註，與 §11.6.4.1 一致。

輸出同時保存 `theme_multiplier_raw`、`theme_multiplier_loo` 與三項 LOO 差額。若 M6 顯示 ignition 的非 LOO 版本使啟動日差異超過 1 日的事件比例 > 5%，則正式版本須改為 ignition LOO；該選擇只能使用 train／validation，不得查看 holdout。

**此修正同時消除 §14.4「單純族群動能」基準的一個混淆來源**——LOO 之後，族群乘數確實只反映「同儕」資訊。

### 11.6.2.1 四個輸入的值域定義（v2.5.2 補齊，v2.6 補缺值規則）

**統一規範：四個輸入一律標準化至 `[-1, +1]`，其中 0 為中性。** 係數加總為 0.39，故乘數理論範圍為 `[0.61, 1.39]`，再 clip 至 `[0.85, 1.35]`。**下界 clip 為有效約束**，代表族群極弱時最多壓抑 15%，不會把個股分數壓垮。

| 輸入 | 計算方式 | 值域 |
|---|---|---|
| `theme_ignition_curve` | 依 §11.6.3 之啟動天數分段函數（見下表） | [-0.5, 1.0] |
| `theme_leader_strength` | 族群內最強成分股之 20 日報酬全市場百分位 `pct`，取 `2 × pct − 1` | [-1, 1] |
| `theme_breadth_rising` | 族群上漲家數佔比之 5 日變化量 `Δ`，取 `clip(Δ / 0.25, -1, 1)` | [-1, 1] |
| `theme_money_flow` | 族群法人淨買超佔成交金額比，取當日全體族群之百分位 `pct`，再取 `2 × pct − 1` | [-1, 1] |

**`theme_ignition_curve` 分段函數（初值，M6 掃描）：**

| 啟動天數 | 值 |
|---|---|
| 未啟動（未觸發 §11.6.3 條件） | **0**（中性，非負值） |
| 第 1–5 天 | 1.0 |
| 第 6–12 天 | 由 1.0 線性遞減至 0 |
| 第 13–20 天 | 由 0 線性遞減至 −0.5 |
| 第 21 天以後 | −0.5 |

**「未啟動 = 0」而非負值**：沒有族群訊號不等於族群不利，此與 §12.3.5「無消息不填中性負值」為同一原則。

**缺值規則（v2.6 補齊）：** 任一輸入無法計算時（資料缺漏、成分股不足、族群未建立），該輸入以 **0（中性）** 代入，而非跳過或以平均值填補；四項皆缺時乘數為 1.0。缺值情形須記錄於 `theme_breakdown`，使證據卡可顯示「本項無資料」。

**採用百分位（而非原始值）標準化的理由：** 三項輸入皆為橫斷面比較，百分位可自動適應不同市況與族群規模，且無須另訂絕對門檻，符合 §11.0 之設計原則。`theme_breadth_rising` 為唯一使用絕對尺度者（除以 0.25），因其本身已是有界的比例變化量；0.25 為初值，M6 掃描 0.15–0.40。

### 11.6.3 啟動日判定（必須寫死）

> 族群相對強度百分位**首次突破 0.8** 的當日為第 1 天；
> 之後只要未跌回 **0.5 以下**，持續計數；
> 跌破則重置。

倒 U 曲線初值：第 1–5 天為高原（值 1.0），第 6–12 天線性遞減，第 13 天以後為 0 或轉負。

### 11.6.4 為什麼用變化量而非水位

`theme_breadth_rising` 取**變化量**：「上漲家數從 20% 升到 45%」是擴散訊號；「已經 45% 且停在那」不是。

### 11.6.4.1 主題歸屬規則

**一檔股票可屬於多個主題**（例：光環同時屬 CPO 與矽光子），須明訂處理方式。

| 情境 | 規則 |
|---|---|
| 每股候選主題 | 最多保留 3 個，按 LLM ⓪ rubric score 排序；此 score 不是校準機率 |
| primary theme | 取 rubric score 最高者；並列時依人工可查的產品證據數，再以主題名稱排序確保可重現 |
| 合格主題 | 初始 rubric score ≥ 0.7 且成分股 ≥ 6；門檻只可用主題驗證集校準 |
| 正式族群乘數 | **只使用 primary theme**，不取多主題最大值 |
| 無合格主題 | 以官方產業別作為 sector fallback，`theme_source_is_sector = 1` |
| fallback 成分股 < 6 檔 | 乘數 = 1.0，輸出標註 |

取多主題最大值會讓主題較多的股票產生次序統計量優勢，因此不作正式規則。`max`／`mean` 只可列為 P1 敏感度分析，不得依 holdout 結果改回正式方案。

**以官方產業別作為 fallback 的理由：** 官方產業別資料既有且可重現，可讓非題材股仍有同儕比較。但報告必須分開呈現 `llm_theme_coverage`、`sector_fallback_rate` 與 `total_group_coverage`，不得用 fallback 後接近 100% 的總覆蓋率宣稱 LLM 主題分類成功。

**主題數量要求：** 目標建立 25–40 個主題；連同 sector fallback，每日有效族群數應 ≥ 30。若有效族群數 < 20，百分位啟動規則不穩定，B+ 版須降級為 sector-only，而不是臨時更換另一套未驗證門檻。

**覆蓋率驗收：** `llm_theme_coverage` 目標 ≥ 50%，`total_group_coverage` 目標 ≥ 95%；未達目標不代表系統失敗，但須分別揭露並解釋 B+ 實際主要來自主題或產業 fallback。

### 11.6.5 族群共同公式、個股 LOO 調整乘數

所有成分股使用相同係數與 ignition 曲線；但 leader、breadth、money-flow 會排除自身，因此最終乘數可因個股略有不同。不得再稱為「族群內完全統一乘數」。

**落後股不會因為落後而被推前。** 這避免「族群熱就買最弱的股票」的陷阱——族群內最落後者多半是有原因才落後（產品線未真正沾到題材、營收占比低、財務有問題）。動能文獻的一致結論是強勢族群中領先者傾向繼續領先。

系統要抓的是「龍頭已動、族群啟動初期、**個股自身已有確認訊號**」的擴散標的。個股自身確認由第一輪的 Gate 保證。

# 12. 消息面與 LLM 模組

## 12.1 三個 LLM 位置

見 §4.2 對照表。本章詳述 LLM ⓪ 與 LLM ①；LLM ② 見 §15.3。

## 12.2 LLM ⓪：主題成分表

### 12.2.1 為什麼需要

**官方產業別分不出台股的主題。** CPO、矽光子、重電、AI 伺服器、機器人等主題橫跨「電子零組件」「通信網路」「電腦週邊」「電機機械」多個官方分類。關鍵字比對也失效——多數公司的產品描述不會出現「CPO」三個字。

這是規則做不到、LLM 有明確優勢的任務，且**有標準答案可人工抽驗**。

### 12.2.2 輸入與輸出

**輸入**：公開資訊觀測站的營運概況、主要產品、營收比重。

**輸出**：

```json
{
  "stock_id": "3234",
  "theme": "CPO",
  "confidence": 0.9,
  "evidence": "主要產品為光收發模組，光通訊營收占比逾七成"
}
```

**`evidence` 必須是原文可查證的句子，不得為 LLM 推論。** 抽驗時翻開原始資料即可判定對錯。

### 12.2.3 版本管理

成分表加 `valid_from` / `valid_to`，重跑產生新版本而非覆蓋。

**適用範圍須區分（v2.5.1 修正）：**

| 期間 | 可用版本 | 說明 |
|---|---|---|
| 歷史回測期（2019–2026/7） | **僅有 2026 年建立之版本** | 成分表於 M4（10 月）才建立，歷史期不存在「當時那一版」。**此期間之族群結果一律標示為「回顧式分類（retrospective classification）」，不得稱為嚴格 PIT，亦不得稱為準 PIT** |
| 上線後（2026/11 起） | 當時有效版本 | 由 `valid_from`／`valid_to` 決定，回放模式須載入對應版本 |

v2.5 原文「回測使用當時那一版，不可用最新版跑舊資料」在歷史期無法執行，故修正為上述分期規則。**版本管理機制仍須於第一天建立**，否則上線後的回放（AC-17）與可重現性（AC-16）將失效。

### 12.2.4 必須寫入報告的限制

主題本身會演化——CPO 在 2022 年還不是市場主題。以今日主題清單回測 2022–2023，本質上假設當時已知這些主題存在，屬**輕微前瞻偏誤**。

緩解方式：以**產品組成**而非市場熱度定義主題。此偏誤無法完全消除，須於報告明列。

### 12.2.4.1 B+ 版歷史結果的正確表述（v2.6）

外部審查指出：以今日建立的成分表回測 2022，不能宣稱為 PIT。修正後之表述規則：

| 期間 | 標示 | 報告用語 |
|---|---|---|
| 2019–2026/7 之 B+ 版結果 | **回顧式分類** | 「族群歸屬採用 2026 年建立之成分表回溯套用，非當時可得資訊，屬回顧式分類，結果為上限估計」 |
| 2026/11 上線後 | 嚴格 PIT | 「族群歸屬使用當時有效版本」 |

**H3（族群增益）之結論須同時標註此限制。** 若前瞻期樣本足夠，應另行呈現「僅前瞻期」之 B+ vs B 對照，作為未受此偏誤影響的佐證。

### 12.2.5 股票與主題為多對多（v2.6 明確化）

資料模型須為獨立的關聯表，不得於股票表加單一 `theme` 欄位：

```
theme_membership(
  stock_id, theme_id, confidence, evidence,
  valid_from, valid_to, table_version
)
```

一檔股票可對應多個主題，正式乘數只使用 §11.6.4.1 的 primary theme；其他關係保留供 UI 與敏感度分析。**PK 為 (stock_id, theme_id, valid_from)。**

### 12.2.6 驗收

選 6 個主題：3 個高關注主題、2 個中等覆蓋主題、1 個負向對照主題。兩位組員各自依公司產品證據獨立核對成分股，再形成共識標準答案。正式報告同時呈現 precision、recall、F1 與每個主題的樣本數；目標 precision、recall 均 ≥ 85%。若只完成 3 個主題，H8 結論必須明確限於該 3 個主題。

## 12.3 LLM ①：消息抽取

### 12.3.1 消息面正式 Schema（全文唯一權威版本）

LLM ① 原始輸出：

```json
{
  "event_type": "order_contract",
  "evt_sentiment": 1,
  "has_amount": true,
  "amount_twd": 1200000000,
  "has_schedule": true,
  "has_named_customer": false,
  "specificity": 5,
  "materiality": 5,
  "evt_is_denial": false,
  "evt_is_cancellation": false,
  "evt_direction": 0,
  "quoted_span": "取得A客戶光通訊模組訂單，金額約新台幣12億元",
  "summary": "取得 12 億元訂單，Q4 起分批出貨"
}
```

`quoted_span` 必須在執行階段通過「為正規化原文之完全子字串」檢查；失敗即拒收並重試，不得只在 gold set 事後統計。`summary` 為 `display_only`，不進特徵表。

`event_type` 固定為 6 類加 `other`：

| 值 | 涵蓋 |
|---|---|
| `order_contract` | 訂單、重要契約、代工案 |
| `guidance` | 財務預測公布、上修、下修 |
| `capex_capacity` | 擴產、重大投資、新廠、產能調整 |
| `denial_clarification` | 公司對媒體報導之澄清 |
| `financing` | 增資、可轉債、私募 |
| `negative_ops` | 減產、停工、重大訴訟、調查、重大事故 |
| `other` | 其餘事件 |

公告進 L2-ann 的 20 欄如下；M0 後可能刪除兩個序數欄而降為 18 欄：

| # | 欄位 | 型別 | 來源 |
|---:|---|---|---|
| 1–7 | `ann_evt_type_*` | 7 個 0/1 | LLM |
| 8 | `ann_sentiment` | -1/0/1 | LLM |
| 9 | `ann_has_amount` | 0/1 | LLM |
| 10 | `ann_amount_to_mktcap` | float | 程式：`amount_twd` ÷ PIT 市值 |
| 11 | `ann_has_schedule` | 0/1 | LLM |
| 12 | `ann_has_named_customer` | 0/1 | LLM |
| 13 | `ann_specificity` | 0–5 | LLM；條件式保留 |
| 14 | `ann_materiality` | 0–5 | LLM；條件式保留 |
| 15 | `ann_is_denial` | 0/1 | LLM 定位，程式原文驗證 |
| 16 | `ann_is_cancellation` | 0/1 | LLM 定位，程式原文驗證 |
| 17 | `ann_direction` | -1/0/1 | LLM 定位，程式原文驗證 |
| 18 | `ann_novelty_90d` | 0/1 | 程式查資料庫 |
| 19 | `ann_days_since_last_evt` | int | 程式 |
| 20 | `has_announcement` | 0/1 | 程式 |

`amount_twd` 原始值保存在消息表，不直接進寬表。M0 對 `specificity` 與 `materiality` 使用 quadratic weighted κ 或 Krippendorff's alpha：兩欄皆 ≥ 0.6 才全留；0.4–0.6 只留較高者；皆 < 0.4 則刪除兩欄。

新聞若啟用，使用同名 `news_*` 欄位存於 L2-news；不得與 `ann_*` 放入同一模型。

### 12.3.2 已刪除與已移轉的維度

| 維度 | 處置 | 理由 |
|---|---|---|
| `potentially_unpriced_score`（尚未反映） | **刪除** | 等同要求 LLM 預測股價反應，違反 §4.3，且為最大污染入口 |
| 新穎度 | **改由程式計算** | 「同公司同事件類型 90 天內首次出現」是一句 SQL，比 LLM 準且免費 |
| 時效性 | 程式為主 | 消息日期 vs 事件時程 |

### 12.3.3 `event_type` 的編碼

**必須用 one-hot，不可用整數編碼。** 五十餘種類型若編成 1–50，樹模型會學到「類型 23 和 24 相鄰」這種不存在的關係。

固定使用 §12.3.1 的 7 個 one-hot 欄位，不再於實作期增減類別。

### 12.3.4 金額正規化

`amount_twd` 必須除以市值或近 20 日均額。12 億對台積電是雜訊，對 30 億市值公司是重大事件。

### 12.3.5 缺值處理

無公告時，`has_announcement = 0`，其他 `ann_*` 欄位維持 null。固定權重版只在公告存在時加入公告分數，否則技術／籌碼權重重新歸一化。條件式 LR 不接收含 null 的單一四面向矩陣：正式比較使用「無公告二面向 LR」與「有公告三面向 LR」兩個明確模型，或退回固定權重；不得臨時以 0 假裝中性。

### 12.3.6 gold set 人工標註（P0，不可砍）

- 抽取 **180 則**合法取得之 MOPS 公告或合法新聞（分層涵蓋各類型）
- 兩位組員**獨立**標註上述欄位
- 二元欄位：兩位人工標註者使用 Cohen's κ
- 名目 `event_type`：人工一致性使用未加權 Cohen's κ；LLM 對共識答案使用 accuracy、macro-F1、各類 precision／recall 與混淆矩陣
- 序數 0–5：quadratic weighted κ 或 Krippendorff's alpha
- `amount_twd`：解析成功率、±1% 正確率與中位絕對誤差
- `quoted_span`：原文子字串通過率必須為 100%
- 分析失敗模式：抽錯金額、幻覺數字、舊聞誤判為新聞
- **P1 延伸**：同一 gold set 上比較 1 個小型 API 模型 + 1 個地端模型；地端模型僅在部署用 Linux 主機通過 GPU 顯存、吞吐與驅動相容性驗證後採用 vLLM

類別樣本 < 20 則者只列混淆情形，不單獨宣稱該類性能。180 則為可行但仍有限的 gold set，預估 5–7 人天；不得稱為「不受樣本數限制」。

## 12.4 工程要求

- **快取**：key = `hash(prompt_version + model_id + text)`，value = 完整原始回應。重跑成本歸零。**第一天就要寫。**
- **儲存原始回應**：存入資料庫，不是只存解析後分數。外部模型可能下架或靜默更新。
- **`model_id` 釘死版本字串**，不使用 `latest` alias。每列記錄 `model_id`、`prompt_hash`、`temperature`、呼叫時間。
- **Batch API**：歷史回補無延遲需求，批次模式可省約一半成本。
- **Schema 驗證與重試**：使用 Pydantic 或 `instructor`。
- **引文驗證**：`quoted_span` 非原文子字串即拒收；原文與正規化版本皆保存雜湊。
- 溫度設為 0。

## 12.5 成本估算

- 先以 M0 的全年公告統計取得實際白名單通過率，再估算呼叫數
- 每則先做確定性過濾與快取，只有新 `content_hash` 才呼叫
- 成本表使用實際模型當日官方價格、輸入／輸出 token 分開計算，另加 30% 重試 buffer
- 成本超出團隊核定預算即縮小公告類型，不以未驗證的固定金額承諾

**月營收完全不需要 LLM**，為純數值表格，以規則計算年增率、月增率、加速度。

## 12.5.1 消息來源分離原則

公告與新聞的可用期間、揭露義務、授權條件與覆蓋率不同，混入同一模型會造成訓練／推論分布不一致，也無法解釋增益來自哪一來源。

### 規則：兩套來源，特徵前綴分離，不得混用

| 來源 | 特徵前綴 | 可用期間 | 用於 |
|---|---|---|---|
| 公司重大訊息（公告） | `ann_*` | 2022–（若 M0 採用） | C-ann／D-ann 回測與條件式產品模型 |
| 合法財經新聞 | `news_*` | 各來源實際啟用日– | D-news exploratory；不進正式模型 |

**硬性規則：同一個模型不得同時使用可用期間不同的兩組來源特徵。**

### 依 M0 結果分為兩種情境

**情境甲：公告通過資料品質與 MDE 門檻**

- 建立 C-ann／D-ann，僅使用 `ann_*`；H4 依預先註冊切分檢定。
- D-news 仍為獨立探索性表，不與公告融合。

**情境乙：公告未通過任一門檻**

- 正式研究只保留 A／B／B+，H4 標記「資料不足，未檢定」。
- 不得用短期新聞資料冒充 H4；D-news 只作功能展示與描述統計。

決策最晚 8/10 寫入紀錄，9/20 隨預先註冊一起凍結。`candidate_card` 分開保存 `announcement` 與 `news_exploratory` 物件；正式 `score_components` 只允許前者。

## 12.6 污染控制

| 措施 | 說明 |
|---|---|
| 只做抽取與分類 | 不詢問未來價格方向 |
| 已刪除「尚未反映」維度 | 最大污染入口 |
| 新聞只作 exploratory | 不以新聞結果支持正式假設 |
| gold set 為主要驗證 | 直接檢查給定原文下的抽取正確性 |
| 固定 prompt 與模型版本，溫度 0 | 可重跑檢查一致性 |
| P1：地端小模型比較 | 小模型對台股具體事件記憶較弱，可作為污染敏感度檢查 |

**污染影響範圍：** 價量、籌碼、族群數值與標籤為純計算；LLM 只影響主題歸屬與消息抽取。即使模型可能記得公開事件，只要 prompt 僅提供當時可得原文、禁止外部知識、保存引文並通過 gold set，抽取錯誤仍可量測；但此控制不能證明模型完全沒有記憶污染，限制須寫入報告。

# 13. 兩輪評分與候選判定

## 13.1 硬規則層（布林判斷，不打分數）

**必須與分數計算在程式碼上物理隔離。**

| 類別 | 內容 |
|---|---|
| 可交易性（**僅限 T 日已知者**） | 標的池資格、流動性門檻（20 日均額）、全額交割排除、當日是否處置或停牌 |
| Gate（至少滿足一項） | 爆量攻擊／創波段新高／帶量長紅／首根漲停；**所有正式版本使用相同 Gate** |
| 風險否決（**程式規則，非 LLM 評分**） | 見 §13.1.1 |

**風險否決不得寫成「扣 20 分」。** 讓分數權衡風險，遲早會出現「技術分高所以蓋過重大負面消息」的案例，那是產品責任問題。

**⚠️ v2.6 移除：T+1 可成交判定不得置於本層。** T 日 21:30 無法得知 T+1 之開盤價與最低價，將其寫入硬規則即為未來資料洩漏。可成交性一律移至 §10.4 之成交模擬層。**此為 AC-02 leakage 測試之必檢項目。**

### 13.1.1 風險否決規則表

硬否決只處理兩種語意非常明確的 MOPS 公司說明：**否認傳聞**與**取消／終止契約**。同時滿足下列條件才觸發：

1. `source_type = 'mops'`，且公告在 T 日 21:30 前可得。
2. 正規化後的**公告原文**命中版本化 YAML 詞組；不得只比對 LLM 產生文字。
3. 通過否定語境檢查，例如「並未取消」「未有下修」不得誤判。
4. 若 LLM 提供 `quoted_span`，它必須是原文子字串；LLM 欄位可協助定位，但不是觸發必要條件。

| 類型 | 初始明確詞組 | 行為 |
|---|---|---|
| 公司否認 | 與事實不符、並無此事、報導有誤、尚未簽訂 | 硬否決 |
| 契約取消 | 取消、終止、解除、撤銷、不予執行；且語境指向訂單／契約 | 硬否決 |
| 財測下修、減產、停工、訴訟、調查、事故 | — | 只加 `risk_flags`，不刪除 |

規則每次修改都須增加正例與反例單元測試、更新 `risk_rule_version`，並只能在 train／validation 定案。人工抽驗所有案例或最多 30 則；案例不足 30 則時如實報告，不湊數。

### 13.1.2 新聞與不確定負面訊息只作警示

新聞、非 MOPS 來源、LLM 負面判斷、原文未命中、或語境不確定者一律保留候選，只寫入 `risk_flags`。LLM confidence 完全移出 Gate、否決與分級路徑；不使用 0.5／0.8 等未校準門檻。

## 13.2 第一輪：個股分數

僅對通過硬規則層者計算。

### 13.2.1 百分位轉換

子分數的原始分佈不同，直接加權會使宣稱的權重與實際影響力不符。所有百分位都只在「當日通過共同 Gate 的集合」計算。

```
tech_pct = rank(technical_score, 當日通過 Gate 之集合) / N
chip_pct = rank(chip_score, 同上) / N
ann_pct  = rank(announcement_score, 當日有公告且通過 Gate 者) / N_ann
```

同時解決：尺度不一致、跨期不可比、市場整體漲跌造成的分數漂移。

### 13.2.2 加權

P0 固定權重：

```python
if has_announcement and announcement_module_enabled:
    round1_raw = 0.40 * tech_pct + 0.30 * chip_pct + 0.30 * ann_pct
else:
    round1_raw = (0.40 * tech_pct + 0.30 * chip_pct) / 0.70
```

技術、籌碼子分數由預先凍結的完整訊號清單取平均；不得只平均「有觸發的訊號」，否則觸發一個極端訊號的股票會取得不合理優勢。公告模組未通過 M0 時，所有正式版本都使用二面向公式。

### 13.2.3 候選池

```python
candidate_pool = top_30_by_round1_score
```

正式候選池固定最多 30 檔；公告與新聞都不另開聯集入口，使 A／B／B+／D-ann 的 Gate 與候選預算一致。

### 13.2.4 聯集路徑取消

v2.6 的消息聯集可能帶入排名 30 名以後的股票，卻又稱其「必定進入 B 級」，與 B 級定義 11–30 名矛盾；同時會改變 H4 的候選池，使排序增益無法公平比較。v2.6.2 取消正式聯集路徑。新聞或公告但價量未確認者可顯示在**獨立事件頁**，不列 A／B／C 級，也不進正式績效。

## 13.3 族群層：共同公式、個股 LOO 乘數

見 §11.6。公式與係數共同，但 leader、breadth、money-flow 排除個股自身。

**成分股不足 6 檔的族群**：乘數設為 1.0，並於輸出標註。

## 13.4 第二輪：重排

```python
final_score = round1_score * theme_multiplier_loo
```

### 13.4.1 為什麼用乘法

1. 無族群訊號時乘 1.0，第一輪排名原樣保留，比加權歸一化自然
2. 乘數有明確上下限，一個族群判斷無法推翻整個個股分析
3. 第一輪模型不讀族群乘數，避免族群效果在 LR 與第二輪重複計入

### 13.4.2 乘數範圍的理由

clip 至 `[0.85, 1.35]`，只限制單次放大／壓抑幅度。它能移動多少名取決於當日分數間距，不能保證「第 30 名不會升到第 1」；M6 須報告實際名次變動分布與最大變動。

## 13.5 消息與價量的一致性

| 組合 | 條件 | 系統行為 |
|---|---|---|
| 最強 | 正面重大消息＋價格突破＋量能確認＋法人買超 | 最高分 |
| 觀察 | 正面消息但價量未確認 | 獨立事件頁顯示，不列正式候選 |
| 風險 | 價量大漲但 MOPS 明確否認或取消 | 符合 §13.1.1 才硬否決；其餘警示 |

## 13.6 權重的三個來源

### 13.6.1 訓練資料從哪來

**訓練資料不需另外蒐集，是系統自己產生的。**

- **X_product** = 第一輪面向分數；不含族群乘數
- **y** = Labeler 輸出（DEF-RANK）
- 兩張表以 `(stock_id, date)` join

基礎版 train 使用 2019–2023；公告版最早只能使用實際成功回補的 2022–2023。樣本列數、Gate 集合正例率與正例數一律由資料管線產出，不以全池約 5% 推估 Gate 正例數。

**訓練群體 = 通過 Gate 之後的集合，不是全市場**（訓練分佈必須等於推論分佈）。

### 13.6.2 固定權重與條件式 Logistic Regression

**產品預設為 §13.2.2 固定權重。** LR 只有在 validation 同時改善 conditional PR-AUC 與 end-to-end Precision@10、且跨年度係數方向穩定時才可取代第一輪固定權重；否則保留為研究比較。

基礎 LR：`X = [tech_pct, chip_pct]`。公告 LR：`X = [tech_pct, chip_pct, ann_pct, has_announcement]`；`ann_pct` 缺值只以訓練期平均填補，並由 `has_announcement` 明確表示缺值。

```python
Pipeline([
    ('impute', SimpleImputer(strategy='mean')),
    ('scale', StandardScaler()),
    ('lr', LogisticRegression(
        penalty='l2',
        C=selected_c,
        solver='lbfgs',
        max_iter=1000,
        class_weight='balanced',
    )),
])
```

`selected_c` 只在 train 由 `[0.01, 0.046, 0.215, 1, 4.64, 21.5, 100]` 選擇。LR 有係數、截距與超參數，`lbfgs` 也可能未收斂。每次訓練保存 `C`、係數、截距、`n_iter_` 與警告；達 `max_iter` 視為未收斂。LR 機率因 class weight 可能未校準，只用於排序；輸出先轉為當日 Gate 集合百分位，再作 `round1_score`，以維持第二輪分數尺度。實作行為以 [scikit-learn LogisticRegression 官方文件](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html)為準。

完整 48–54 欄 LR 只作 P1 研究比較，不進設定檔；不得將完整特徵係數絕對值加總後冒充三面向產品權重。

### 13.6.3 必跑的零參數基準

```python
round1_rank = mean([rank_tech, rank_chip])
final_score = percentile_inverse(round1_rank) * theme_multiplier_loo
```

公告版另加 `rank_ann`，但只對 `has_announcement=1` 的股票使用；無公告者維持二面向等權。

無任何可調參數、對分佈不敏感、不可能過擬合。

**若學習權重打不贏等權排名平均，則採用等權，並在報告誠實記載「權重最佳化未帶來顯著增益」。** 此為方法論加分項，同時是時程失控時的保底引擎。

### 13.6.4 三層保險

| 保險 | 內容 |
|---|---|
| 固定權重 | 無公告時 0.57／0.43；有公告時 0.40／0.30／0.30 |
| 等權排名平均 | 零參數，不可能過擬合 |
| 參數高原檢查 | 若學出的權重為雜訊尖峰，直接退回等權 |

**「訓練失敗」在本設計中不是失敗模式，而是一個分支。三條路都能出貨。**

## 13.7 參數高原檢查

不找單點最佳值（多為雜訊）。作法：

- 基礎二面向權重掃描 0.30–0.70；公告版三面向權重總和為 1、每項 0.15–0.55、步長 0.05
- LR 的 `C` 依 §13.6.2 候選點另畫穩健性曲線
- 畫成 heatmap
- 鄰近組合表現相近 → 高原，取中心值
- 僅單一組合特別好、鄰近皆差 → 雜訊尖峰，**不採用**，退回等權或高原中心

**heatmap 直接放入簡報，用以回答「為什麼是這個權重」。**

## 13.8 梯度提升樹（P1，不當產品引擎）

以 LightGBM 或 XGBoost 跑一次作為**效果上限參考**。

不採用為產品引擎的理由：

1. **可解釋性**：產品核心是證據卡。線性模型可直接呈現各面向貢獻；樹模型只能給 SHAP 值，與產品定位衝突。
2. **過擬合風險**：完整特徵 48–54 欄，且 Gate 集合正例率須實測，本期無時間做完整巢狀驗證。
3. **時程**：調參為無底洞，預期增益有限。

只有實際完成時才寫入報告；未完成就列為未執行 P1，不得預先替結果下結論。

## 13.9 候選分級

| 等級 | 條件 | 系統行為 |
|---|---|---|
| A 級 | 通過 Gate、無風險否決，第二輪前 10 名，且 `final_score` ≥ 絕對下限（見下） | 正式候選 |
| B 級 | 第 11–30 名 | 觀察名單 |
| C 級 | 未達門檻但有單一強訊號 | 研究觀察 |
| 排除 | 風險否決或不可交易 | 不列入 |

### 13.9.1 絕對下限的定義（v2.5.1 補充）

僅有排名門檻時，即使當日全市場訊號極弱，系統仍會湊滿 10 檔。絕對下限的作用是讓「今日無符合條件之候選」成為可能。

> **絕對下限：`final_score` ≥ 0.60**（第一輪百分位加權後乘以族群乘數之值）。
> 掃描範圍 **0.50–0.75**，於 M6 與其他參數一併掃描。

**校準紀律：** 下限值須以訓練期回測校準至「空清單日佔比落在 5%–15%」。過高將使系統長期無輸出（產品失去意義），過低則等同無下限。此比例本身為 M6 的呈現項目之一。

**B 級亦適用較寬之下限**（預設 0.50），未達者不列入任何名單。

**系統必須能輸出空清單。** 「今日無符合條件之候選」是合法輸出，也是避免為了固定名額而降低標準的產品紀律。

## 13.10 同族群名額上限

A 級前 10 名，同一族群最多 **N** 檔，超出者擠到 B 級。

**分數層完全不動**，只在輸出層處理分散度。三方案於 M6 回測比較：不設限／上限 4 檔／強制不同族群。

**設計理由**：族群強勢時前 10 名可能集中單一族群；名額上限只處理輸出分散度，不預設 `theme_ignition` 的倒 U 一定成立。正式方案只能用 validation 選擇，holdout 不再修改。

# 14. 評估設計

## 14.1 第一層：分類能力

主要指標分成 Gate、條件式排序與端到端三層；所有點估計均附以週為時間區塊的 95% 信賴區間。

不使用 Accuracy 作為主要指標。

### 14.1.1 Lift 的基準必須是「實際被評分集合」的正例率（v2.6 修正）

**v2.5.2 的錯誤：** 假設 Precision@10 的隨機基準為 5%。但標籤定義於全標的池前約 5%，模型只對通過 Gate 的集合排名；Gate 集合正例率可能不同，必須實測。

若以 5% 作為基準計算 lift，將**系統性高估模型價值**——那部分增益來自 Gate（規則篩選），不是排序模型。

**修正後規則：**

| 基準 | 定義 | 用途 |
|---|---|---|
| `base_universe` | 當日全標的池之實際正例率 | 說明 Gate 前基準 |
| **`base_scored`** | **當日通過 Gate 且被評分之集合的實際正例率** | **計算排序模型 lift 的正式基準** |

四組正式指標：

| 層 | 指標 | 定義 |
|---|---|---|
| Gate | Gate Recall | Gate 內正例數 ÷ 全池正例數 |
| Gate | `base_scored`／`base_universe` | Gate 對正例率的改變 |
| 排序 | Conditional PR-AUC | 只在 Gate 集合內評估排序 |
| 端到端 | Precision@5／10、Recall@10 | 使用者實際看到的 top-K 表現，相對全池計算 recall |

```text
Lift_gate  = base_scored / base_universe
Lift_model = Precision@10 / base_scored
Lift_total = Precision@10 / base_universe
```

三個 lift 必須以**同一批聚合計數**計算；不得先逐日算比例再將不同平均數相乘。H2／H3／H4 因正式版本共用同一 Gate，主要比較 Conditional PR-AUC 與端到端 Precision@10，lift 分解作解釋。

同一交易日股票高度相關，相鄰交易日也可能屬同一行情。正式 CI 採「週」為時間區塊重抽 1,000 次；日內整批候選不可拆散。若有效週數不足，僅報點估計與限制，不以逐列 bootstrap 製造過窄 CI。

### 14.1.2 分類評估之樣本範圍

分類層評估**包含 no-fill 樣本**（§10.4）；成交率與交易績效於 §14.2 單獨呈現。兩層數字不得混用或互相取代。

**名單穩定性三指標**（進回測報告與每日品質報告）：

| 指標 | 說明 |
|---|---|
| 名單換手率 | 當日 A 級與前一日之重疊比例 |
| 平均連續入選天數 | 名單是否僵化 |
| 有效獨立事件數 / 名目樣本數 | 直接影響 MDE |

分位數單調性分析：候選分數分 5 組，檢視各組未來超額報酬與 IC。

## 14.2 第二層：交易可行性

模擬條件：T 日 21:30 完成判斷、T+1 開盤價買進、T+10 收盤價賣出、雙邊手續費、賣出證交稅、滑價、漲停成交邊界與流動性上限；no-fill 依 §10.4 分成 filled-only 與 opportunity 口徑。

```yaml
trading_costs:
  commission_rate_per_side: 0.001425   # 保守採標準費率，不假設券商折扣
  sell_transaction_tax: 0.003          # 非當沖股票賣出
  slippage_bps_per_side: [0, 5, 10]    # 5 bps 為主情境，其餘作敏感度
  max_order_to_avg_amount_20d: [0.001, 0.005]
  fill_models: [conservative_locked_limit, optimistic_volume_traded]
```

費率在凍結設定前再次核對法規並寫入 `effective_date`；基準採證交所[交易制度頁面](https://www.twse.com.tw/en/products/system/trading.html)所示股票標準手續費率 0.1425% 與財政部[證券交易稅條例第 2 條](https://law-out.mof.gov.tw/LawContent.aspx?id=FL006079)之股票賣出 3‰。流動性上限只用來估計容量與成交模擬，不得回頭改變分類標籤。

評估：累積報酬、平均每筆報酬、勝率、最大回撤、與市場基準比較。

**本期不做** Sharpe／Sortino 等組合層級指標與部位配置最佳化。

## 14.4 基準模型

## 14.5 資料切分與鎖定機制（v2.6 重排）

### 14.5.1 v2.5.2 的順序錯誤

驗證集鎖到 11/20、設定亦於 11/20 凍結——**等於沒有任何時間根據驗證結果做選擇**。驗證期若在凍結後才開啟，它就不是驗證集，而是第二個保留集。

### 14.5.2 修正後的時序

| 日期 | 動作 | 說明 |
|---|---|---|
| 9/20 | **預先註冊 Git tag 凍結** | 假設、指標、決策規則、特徵清單、切分定義 |
| 9/20 – 11/5 | 僅使用 **train** 期 | 訊號開發、權重學習、參數掃描皆在此期完成 |
| **11/5** | **開啟 validation（僅此一次）** | `--unlock-validation`，寫入日誌 |
| 11/5 – 11/20 | 依驗證結果**做最終選擇** | 權重方案、參數高原中心、集中度方案、ignition LOO 去留 |
| **11/20** | **凍結設定，記錄 `config_hash`** | 此後不得再調整任何參數 |
| 11/20 之後 | **開啟 2026 holdout（僅此一次）** | 凍結後才開，作為真正的 out-of-sample |
| 12/1 | 前瞻期資料截止 | 各資料來源依實際啟用日統計 |

**驗證期只開一次、且必須在凍結之前**；holdout 只開一次、且必須在凍結之後。兩者順序不可顛倒，日誌為證。

### 14.5.3 切分邊界須留 gap（v2.6 新增）

主標籤向前看 10 個交易日。若 train 結束於 2023-12-31、validate 起於 2024-01-01，則 train 最後 10 天的樣本，其標籤來自 validate 期間——**標籤洩漏**。

**規則：每個切分邊界之後留 `gap = 10 個交易日`（等於標籤視窗長度），該區間樣本不納入任何切分。** 副標籤 DEF-SURGE 視窗為 20 日，若納入分析，該部分之 gap 為 20 日。

```yaml
data_split:
  base:
    train_calendar:    [2019-01-01, 2023-12-31]
    validation_calendar: [2024-01-01, 2025-12-31]
    holdout_calendar:  [2026-01-01, 2026-11-19]
  announcement_if_enabled:
    train_calendar:    [2022-01-01, 2023-12-31]
    validation_calendar: [2024-01-01, 2025-12-31]
    holdout_calendar:  [2026-01-01, 2026-11-19]
  purge_last_feature_days_before_boundary: 10
  event_embargo_days: 10
  label_horizon_days: 10
```

每一前段切分最後 10 個可作為 T 的交易日予以 purge，使其 T+10 標籤不跨入下一切分；下一切分從其日曆期間第一個交易日開始。事件若跨越邊界，依 `event_embargo_days` 只保留在較早切分，避免同一波段同時出現在兩側。D-news 不切 train／validation／holdout，因其定位原本就是 exploratory。

**實作提示：** `sklearn.model_selection.TimeSeriesSplit` 提供 `gap` 參數，可直接用於交叉驗證；本案之固定切分亦以同一常數處理，避免兩處不一致。

**驗收：** 自動化測試須斷言「任一切分中的樣本，其標籤計算所用之最後日期，不落入下一個切分區間」。此併入 AC-02。

## 14.6 檢定力分析與預先註冊

### 14.6.1 為什麼要做

以絕對門檻標籤（正樣本率 1–2%）估算，消息增益的最小可偵測效果約 6–8 個百分點，遠大於任何合理預期。**不論真相為何都會得到「不顯著」，且無法區分「效果不存在」與「樣本不足」。**

改用 DEF-RANK 可提高事件數，但有效樣本仍受 Gate、事件去重、週期相關與公告覆蓋率影響，不能只用交易日數推估。

### 14.6.2 執行方式

**時機：9 月中，取得 Labeler 與基準數字之後，投入 LLM 開發之前。**

1. 計算實際事件數（含事件去重、扣除名單重疊後的有效獨立事件數）
2. 估計候選在時間上的相關性
3. 分別計算 B+ vs B、D-ann vs 同期間 B+ 在 α=0.05、power=0.8 下的 MDE
4. 將 MDE 寫入報告與簡報

### 14.6.3 預先註冊

撰寫預先註冊文件：H1–H10、條件式 H4 啟動門檻、主要指標、決策規則、資料切分、特徵清單、H9／H10 分組與趨勢檢定。**Git tag 凍結，日期為證。** 之後才碰 validation。

最終報告附上該 commit hash 與日期。

成本合計約 2 人天。

## 14.7 訊號與參數有效性門檻

訊號進入凍結設定檔前必須通過：

| 檢定 | 門檻 |
|---|---|
| 單獨使用時的 Lift | > 1.2 |
| 觸發頻率 | 每日平均 3–50 檔（過少無用，過多無區別力） |
| 參數穩健性 | 掃描範圍內至少 60% 的參數值 Lift > 1.1 |
| 與既有訊號的相關性 | 相關係數 < 0.8（避免重複） |
| 共線性 | VIF < 5（供迴歸係數解讀） |

未通過者不得進入產品引擎，但可保留於報告作為負面結果。

## 14.8 H9／H10：避免循環論證

H9 的 ignition 倒 U 已出現在乘數公式，H10 的延伸度也進特徵；若用加權後候選驗證，結果只能證明規則造成了形狀。因此正式假設檢定採以下流程：

1. 樣本單位使用 §10.5 的 Gate 事件首日，不使用連續每日列。
2. H9 使用未套用族群乘數的原始事件；H10 使用未套用延伸度權重的原始事件。
3. train 期只用來探索合理分組與曲線；9/20 前預先註冊固定分組與趨勢檢定。
4. validation 只決定採倒 U、線性或不採該項；11/20 後在 holdout 一次檢驗。
5. holdout 不呈倒 U 時，結論為「不支持 H9／H10」；不得重新掃描後再用同一 holdout 宣稱成立。
6. 產品加權後表現另列為產品效果，不可用來支持市場現象假設。

# 15. 產品與使用者介面（P0）

## 15.1 產品定位

> 把散戶每天盤後要花兩小時做的功課，壓縮到五分鐘，而且每個結論都能點開看到來源。

系統做的是**縮減、佐證、追蹤**，不是預測，也不是建議。

**UI 中不得出現：** 買進、賣出、目標價、建議部位、勝率預測。
**UI 中必須出現：** 入選原因、原始資料連結、風險標記、後續表現追蹤。

## 15.2 三個畫面（範圍卡死）

### 畫面一：今日候選清單
A 級與 B 級名單，含最終分數、第一輪排名、族群乘數、觸發訊號摘要、風險標記。允許顯示「今日無符合條件之候選」。

### 畫面二：證據卡

- 兩輪分數拆解（第一輪各面向百分位 → 族群乘數 → 最終）
- 族群乘數的四項貢獻拆解
- 觸發的訊號與具體數值
- 當日 MOPS／合法新聞原始連結與允許顯示的抽取欄位；不得轉載未獲授權全文
- 風險標記
- **迷你 K 線 ＋ 法人買賣超柱狀 ＋ 消息事件標記疊在同一條時間軸**
- LLM ② 生成的白話說明（或模板 fallback）

### 畫面三：回放模式 ＋ 成績單

**回放：** 輸入任一歷史日期，重建當日可得的價量、籌碼與族群計算，再按一鍵揭曉後續 10 日結果。2019–2026/7 主題歸屬標示「2026 成分表回顧式分類」；各新聞來源啟用日前不顯示新聞面，不能宣稱完整 PIT 重建。

此功能**只有在 point-in-time 做對的情況下才做得出來**，把最痛苦、最看不見的工程直接變成可視化賣點。後端即為回測引擎，邊際成本主要在前端。

**成績單：** 過去 N 天所有候選的 5／10／20 日表現，自動更新，**包含失敗案例**。

### 畫面四（P1，可砍）：族群概覽
當日各族群的乘數、啟動天數、成分股分布。回應「是否漏看其他族群」。

### 15.3.3 數字一致性自動檢查

```python
def verify(text: str, record: dict) -> bool:
    nums_out = extract_numbers(text)
    nums_in  = flatten_numbers(record)
    return all(n in nums_in for n in nums_out)
```

| 編號 | 風險 | 對策 |

## 22.2 必答題與標準答案

**Q：能賺錢嗎？報酬率多少？**
不閃躲，直接給數字，連壞的一起給。定位是把盤後功課從兩小時壓到五分鐘，不是保證獲利。

**Q：跟現有看盤軟體有什麼不一樣？**
三點：讀消息原文而非只看技術指標；每檔可點開看到理由與原始連結；**自動公布過去每一次的成績，包括失敗的**。第三點要講得用力。

**Q：為什麼要用 AI，寫規則不行嗎？**
價量籌碼確實用規則。AI 的兩個核心任務是把合法取得的消息文字轉為欄位、以及依公司產品證據建立主題關聯；兩者都有人工驗證。把結果講成人話只是 P1，沒有完成也會由模板輸出。

**Q：準不準？**
十檔平均對 X 檔，隨機選是 Y 檔。價值在把 1,800 檔縮到 10 檔。

**Q：照名單買賠錢怎麼辦？**
這是候選清單不是投資建議，系統不給買賣訊號也不給目標價。（背到反射）

**Q：AI 會不會亂編？**
會，所以我們有自動檢查：生成的文字裡每個數字都必須出現在輸入資料中，不通過就退回模板。通過率 X%。

**Q：誰會用？會有人付錢？**
每天自己做盤後功課的散戶。給成本數字而非願景。

**Q：這樣算不算投顧？會不會違法？**
證券投資信託及顧問法第 4 條的要件是「取得報酬」加上「對特定證券提供分析意見或推介建議」。我們的系統確實會對個股產生結論，所以關鍵在第一項——本專題不收費、不接受任何對價，屬校內研究與展示。我們也明確規定，未來若要收費，必須先取得正式法律意見。**（重點：不要回答「我們沒寫建議兩個字」，那不是法律要件。）**

**Q：資料合法嗎？**
價量、籌碼與公告列明官方或授權來源；新聞逐站記錄條款、允許欄位與檢查日期，只有通過授權閘門者才啟用，不因頁面公開就主張可任意使用。UDN 未取得書面許可不納入。

# 25. 最終專案定位

> 一套每日盤後自動執行的台股異常訊號偵測與佐證系統。第一輪以價量、籌碼與條件式 MOPS 公告分數辨認個股異常，第二輪以個股 LOO 族群乘數重新排序；新聞只作合法來源的探索性展示。回測與前瞻追蹤驗證各層是否真的具有增益。

# 26. 設計決策紀錄

記錄開發過程中評估後未採用的方案，避免重複討論。

| 提案 | 決定 | 理由 |
|---|---|---|
| 拿掉融合引擎，由 LLM 直接給分 | **否決** | 引擎本身僅 3–4 人天；貴的是資料層與回測，那兩項誰算分數都要做。拿掉則回放、可重現、消融、參數掃描全失效 |
| LLM 直接給族群或消息乘數 | **否決** | 評分無標準答案，無法驗證；回放模式失效（重跑答案不同）；污染從局部變全域；「事後寫理由」是合理化不是計算過程 |
| 族群飆股占比壓抑（占比 > 30–40% 則壓抑） | **否決** | ①用未來報酬判定會洩漏；②用「已入選名單」判定會循環震盪；③用漲幅門檻判定則只是 `theme_breadth` 的粗糙二值化。且占比高在啟動初期與末期意義相反 |
| 冷卻期（強制壓低連續入選者） | **否決** | 事件去重已處理重複樣本；是否衰竭由 H9／H10 驗證，不再疊硬規則 |
| 只用上線後資料、不做歷史回測 | **否決** | 特徵與標籤需多年資料；短期樣本不足以比較 A／B／B+，且無法提供可信回放與 MDE |
| 讓 LLM 知道未來以提升訓練資料品質 | **否決** | 標籤由版本化行情與固定函式計算，不需 LLM；讓特徵讀到未來會污染回測 |
| 補漲效應進 Gate（族群強則買落後股） | **否決** | 族群內落後股可能有基本差異；個股必須先通過共同 Gate，族群只在第二輪調整 |
| 財經新聞歷史回補至 2019 | **否決** | 無可信 `first_seen_at` 與覆蓋率；新聞只自合法來源實際啟用日起作 exploratory |
| 族群消息特徵（同業公告溢出） | **否決** | 依賴新聞歷史，不可回測 |
| 法說會簡報 PDF 內容抽取 | **否決** | 覆蓋率偏向大型股、頻率為季度以上、PDF 解析成本高。只取召開公告 |
| K 線圖截圖交多模態模型判讀 | **否決** | 不可重現；圖上座標軸與日期直接洩漏未來資訊；可用數字精確表達者不應轉為圖片 |
| 型態辨識（頭肩底、旗形） | **否決** | 無標準定義，學術上無穩健證據 |
| GBDT 作為產品引擎 | **否決** | 完整寬表過擬合與解釋成本較高；本期只列 P1 上限參考 |
| 拆成「潛力股／飆股」兩套標籤兩個產品 | **否決** | 樣本數再切半，兩邊都失去統計效力 |
| 換題為 agent 交易模擬器 | **保留為後手** | 9/15 前決定，見第 21 章 |
| 以 T+1 可成交作為 Gate 條件 | **否決（v2.6）** | T 日 21:30 無從得知 T+1 開盤與最低價，屬未來資料洩漏 |
| 將 T+1 鎖死者自樣本中刪除 | **否決（v2.6）** | 系統當時確實選中，刪除即選擇偏誤；改記 `no-fill` 並分層報告 |
| 以全池約 5% 作為 Precision@10 之 lift 基準 | **否決（v2.6）** | 排序集合是 Gate，須用實測 `base_scored`，不假設一定高於 5% |
| 以 LLM `materiality` 或 confidence 驅動風險否決 | **否決** | 不可逆決策須比對 MOPS 原文、明確詞組與否定語境 |

# 附錄 B：異常情境與降級行為

**核心原則：寧可降級輸出並明確標註，不可延後決策時間，也不可靜默失敗。**

| 情境 | 系統行為 |
|---|---|
| 官方價量資料源全面故障 | 當日流程中止，推播 ERROR，隔日回補；**不輸出候選清單** |
| 部分股票資料缺漏 | 該股當日不參與評分，記入品質報告，清單頁標註涵蓋率 |
| 三大法人或融資券延遲公布 | 21:25 前持續重試；仍缺則籌碼欄位標記缺值，權重重新歸一化，標註「本日未含籌碼面」 |
| **合法新聞來源故障** | 正式 A／B／B+ 不受影響；D-news 標記缺口，該區間不作探索統計 |
| LLM ① 故障或超出預算 | 若 D-ann 已啟用則當日降級為 B+，標註「本日未含公告抽取」並發 ERROR；快取可用 |
| LLM ① 輸出連續驗證失敗 | 該則消息標記抽取失敗、不進入特徵寬表；當日失敗率 > 20% 發 ERROR |
| LLM ② 未實作或數字檢查未通過 | 直接使用 P0 模板；若已呼叫則最多重試一次 |
| 主題成分表載入失敗 | 所有族群乘數設為 1.0，等同 B 版，標註「本日未含族群面」 |
| 族群成分股不足 6 檔 | 該族群乘數設為 1.0，輸出標註 |
| 單一量化訊號模組錯誤 | 該訊號回傳缺值、記 ERROR，其餘照常，百分位轉換於有效面向間重新歸一化 |
| 當日無任何股票通過 Gate | 輸出「今日無符合條件之候選」，此為合法輸出 |
| A 級名單換手率連續 5 日 < 20% | 品質報告發 WARN 並標註；不自動變更輸出 |
| 同日重複執行 | 冪等覆蓋，不重複推播 |
| 排程未觸發 | 隔日偵測缺漏並補跑，標註 `late_run=true`，**不計入嚴格 PIT 樣本** |

# 附錄 D：名詞對照表

| 術語 | 白話說明 |
|---|---|
| DEF-RANK | 未來 10 日超額報酬排進當日池約前 5% 就算成功；`ceil`、並列與缺值會使實際比例略有變動 |
| 兩輪評分 | 第一輪看個股本身，第二輪乘上族群強度重新排 |
| 族群乘數 | 用共同公式計算族群狀態，並以 LOO 排除個股自己的高影響輸入，範圍 0.85–1.35 |
| 族群啟動天數 | 這個族群連續維持強勢幾天；是否中段最好要由 H9 驗證 |
| 倒 U 形 | 研究假設：中段可能優於過早或過晚；不是預先當成市場事實 |
| 事件去重 | 同一波行情只算一次，避免同一檔灌水成十筆 |
| Point-in-time / PIT | 每筆資料記「何時才可被使用」，回測只准用當時已公開的 |
| 準 PIT vs 嚴格 PIT | 第三方資料無法還原當時原始版本 vs 自建擷取，時間戳為實際取得時間 |
| `first_seen_at` | 系統實際取得公告或合法新聞的時間，是自建資料的 PIT 依據 |
| Leakage | 偷用未來資料，讓成績虛高 |
| 存活偏誤 | 只看現在還在的股票、漏掉已下市的，成績虛高 |
| Precision@10 | 每天前 10 檔裡有幾檔成功；排序隨機基準是 Gate 集合實測的 `base_scored` |
| Lift | 比隨機選股好幾倍 |
| MDE | 以現有樣本數，效果要多大才驗得出來；用來區分「沒效果」與「驗不出來」 |
| 消融比較 | 逐一拔掉某面向，看它到底有沒有貢獻 |
| gold set | 人工標註的正確答案集，用來檢驗 LLM 抽得對不對 |
| Cohen's κ | 兩個標註者一致程度的統計量，扣除碰巧一致的部分 |
| 抽取 vs 評分 | 抽取有標準答案（原文寫 12 億就是 12 億），評分沒有 |
| Gate | 必要條件：不通過就不論分數多高都不入選 |
| 風險否決 | 只有 MOPS 原文明確否認或取消且規則通過時排除；其餘負面訊息只警示 |
| 百分位轉換 | 把分數換成「當日池內排第幾趴」，解決尺度不一與跨期不可比 |
| 參數高原 | 好參數的鄰居也應該好；只有單點好就是雜訊 |
| no-fill | 隔天開盤鎖漲停買不到；系統當時確實選中了，所以樣本要留著，只是記成沒買到 |
| `base_scored` | 算 lift 要用「有被評分的那群股票」的實際成功率當基準，不是全市場的 5% |
| leave-one-out | 算族群分數時把自己排除，避免用自己的漲幅替自己加分 |
| purge／embargo | 刪除邊界前會跨期的 T 日樣本，並避免同一事件同時落在兩個切分 |
| 回顧式分類 | 用今天才有的主題名單去套過去，不能宣稱是當時可得的資訊 |
| fallback 族群 | 沒有合格主題時改用官方產業別；成分股不足仍降級為中性乘數 |
| 來源分離 | 公告和新聞的可用年份不同，不能混在同一個模型裡訓練 |
| 主題成分表 | 哪些股票屬於 CPO、重電這類題材；官方產業別分不出來 |
| 延伸度 | 這檔已經漲幾天、離均線多遠，判斷是剛啟動還是已追高 |
| 名單換手率 | 今天前十名跟昨天差多少，太低代表名單僵化 |
| 有效樣本數 | 名目 50 筆但都是同幾檔的連續日，實際獨立事件遠少於 50 |
| 記憶污染 | LLM 記得歷史上發生過什麼，會讓回測成績虛高 |
| `config_hash` | 設定檔指紋，證明「凍結後沒再偷改參數」 |
