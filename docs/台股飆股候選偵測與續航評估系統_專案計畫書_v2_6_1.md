# 1. 執行摘要

本專案建置一套每日收盤後自動執行的台股候選標的偵測與佐證系統。

系統採**兩輪評分**：

**第一輪**以規則式價量與籌碼訊號，加上 LLM 從消息文字抽取的結構化特徵，計算個股分數並取前 30 名（聯集當日有消息者）。

**第二輪**以族群層統一乘數重新排序，取前 10 名為正式候選。族群乘數由該族群的啟動天數、龍頭強度、廣度變化與法人流向計算，族群內不分個股。

**產品主張不是預測，而是縮減、佐證與追蹤：**

> 把全市場 1,800 檔壓縮成當日值得關注的候選，說明每一檔的入選依據，並自動追蹤與公開後續表現。任一歷史日期皆可完整重播，且保證不使用該時點之後的資訊。

最終成果包含：可運作的每日系統、可回溯的重播介面、歷史回測與消融比較報告、LLM 抽取品質的人工標註驗證，以及誠實揭露的限制清單。

# 2. 專案背景與問題定義

台股中部分個股會在短期內出現顯著高於市場的漲幅。這類走勢通常涉及價格突破、成交量放大、法人資金流入，以及訂單或營收等公開催化劑的組合。且台股飆股極少單獨發動，多為整個族群同步啟動、由龍頭向外擴散。

單純使用技術分析會忽略催化劑；單純閱讀消息又可能在資訊已反映後才追價；只看個股會錯過族群擴散的時間差。本專案將三者整合，建立可系統化驗證的候選偵測機制。

本專案不試圖證明任何方法必然獲利，而是要可信地回答：

> 公開的價量、籌碼、族群動能與消息資訊，經規則式計算與 LLM 事件抽取後，能否使候選股票未來成為高品質超額動能事件的比例，顯著高於隨機選股或簡單動能規則？

**本專案事前承認：** 消息面之驗證期間僅約 85 個交易日（見 §8.5），**H4**（消息增益）之檢定力不足，將僅報告效果量與信賴區間，不作顯著性判定。此限制於 §14.6 詳述。

# 3. 專案目標

## 3.1 核心目標

1. 建立具明確數學定義、且統計上可評估的候選標籤。
2. 建立每日收盤後可自動執行的兩輪候選偵測流程。
3. 將價量、籌碼、族群與消息整合為可解釋的排序分數。
4. 使用現成 LLM 將消息文字轉為結構化欄位，並以人工標註驗證其可靠度。
5. 以歷史回放、時間切分及前瞻追蹤驗證系統。
6. 產生可追溯的候選清單，清楚呈現入選原因與原始證據連結。
7. 提供可操作的使用者介面，包含歷史任一日期的完整重播。
8. 建立完整報告，無論結果正面或負面皆形成可信結論。

## 3.2 次要目標

1. 比較五種版本：純價量／＋籌碼／＋族群／只有消息／完整融合。
2. 分析系統在多頭、空頭與盤整市場的差異。
3. 建立候選股後續 5、10、20 日表現成績單並自動公開。
4. 比較固定權重、學習權重與等權排名三種融合方式。
5. 在 gold set 上比較不同規模模型的抽取一致性。

## 3.3 非目標

本期不追求：保證找到所有飆股、保證獲利、預測未公開資訊、盤中即時交易、自動下單、智慧停利停損、投資組合最佳化、自行訓練或微調大型模型、多代理人自主交易、社群輿情分析、提供投資建議。

# 4. 專案關鍵決策

## 4.1 不自行訓練大型模型

年底前資源投入於資料正確性、時點控制、標籤定義、訊號計算、回測可信度、每日自動化與使用者介面。LLM 採現成服務或現成可部署模型。

**本項排除的是大型語言模型的訓練與微調，不包含統計模型。** 本案使用邏輯迴歸學習融合權重（§13.6），並以梯度提升樹作為效果上限參考。

## 4.2 LLM 不是決策者，出現在三個位置

| | LLM ⓪ 主題成分表 | LLM ① 消息抽取 | LLM ② 敘述生成 |
|---|---|---|---|
| 位置 | 系統建置期 | 第一輪之前 | 第二輪之後 |
| 輸入 | 公司產品資料 | 單則消息文字 | `candidate_card` |
| 輸出 | `{theme, members[], evidence}` | 11 欄 JSON | 2–4 句中文 |
| 進入分數 | 間接（決定族群歸屬） | **是** | **絕對不進入** |
| 驗證 | 人工抽驗 | gold set（Cohen's κ） | 數字一致性自動檢查 |
| 頻率 | 一次性 ＋ 季度更新 | 每日 | 每日 |
| 溫度 | 0 | 0 | 0 |

**核心原則：LLM 讀文字填表格，程式算分數，LLM 再把算好的結果講成人話。**

程式碼層面必須物理隔離：`narrative` 欄位存放於獨立資料表並標記 `display_only`，不得被融合引擎讀取。

## 4.3 抽取可驗證，評分不可驗證

這是本案所有 LLM 設計的判準：

| | 抽取任務 | 評分任務 |
|---|---|---|
| 例 | 「原文有沒有寫金額？寫多少？」 | 「這則消息值 1.8 倍乘數」 |
| 有標準答案 | **有**，翻開原文即知 | **沒有**，除非知道未來 |
| 記憶污染會否改變答案 | 不會（原文寫 12 億就是 12 億） | 會，且無法察覺 |
| 可否用 gold set 驗證 | 可 | 不可 |

因此：**LLM 只做抽取與分類，不做影響力評分，且不得驅動任何硬性決策。**

### 4.3.1 主觀評分欄位的定位（v2.6 釐清）

v2.5.2 一方面宣稱「LLM 不做影響力評分」，另一方面保留 `materiality`（重大性 0–5）並讓 LLM 判斷結果影響風險否決，**此為內部矛盾**。修正如下：

| 欄位 | 是否保留 | 用途 | 禁止用途 |
|---|---|---|---|
| `specificity`（具體性） | 保留 | 作為**軟性特徵**進入分數 | 不得驅動硬規則 |
| `materiality`（重大性） | 保留 | 同上 | **不得作為風險否決依據** |

**風險否決一律由程式規則決定**（見 §13.1.1），其輸入為 LLM 抽取的**客觀欄位**（事件類型、是否為否認、是否為財測下修、金額、時程），不使用主觀評分。

**理由：** 硬否決會直接移除一檔候選，屬不可逆決策，必須可稽核、可重跑、可解釋。以無標準答案的主觀評分驅動不可逆決策，違反本節「抽取可驗證、評分不可驗證」的判準。

`materiality` 與 `specificity` 仍為 gold set 的主要檢驗對象（H7）。

## 4.4 聚焦「續航」與「擴散」

系統偵測兩種情境：

1. **個股續航**：已出現價量、籌碼或消息異常後，未來 10 個交易日是否維持超額強勢。
2. **族群擴散**：龍頭已發動、族群啟動初期，同族群中已有自身確認訊號但尚未充分反映的個股。

系統不主張能預知尚未公開消息造成的突然起漲。

## 4.5 結論可信優先於結論漂亮

即使結果顯示消息模組無顯著增益、系統只在多頭有效、或扣除成本後無法勝過基準，只要資料、回測與比較方法可信，仍為有效成果。

**但「不顯著」必須能被解釋。** 因此本案於 §14.6 事前計算最小可偵測效果，使報告能區分「效果不存在」與「樣本不足以判定」。

## 4.6 法律定位（v2.6 修正）

### 4.6.1 用詞迴避不等於免責

v2.5.2 稱「不使用建議二字」為法規考量，此理解不正確。

**證券投資信託及顧問法第 4 條第 1 項**之定義為：<cite index="17-1">直接或間接自委任人或第三人取得報酬，對有價證券、證券相關商品或其他經主管機關核准項目之投資或交易有關事項，提供分析意見或推介建議</cite>。

構成要件有二，**與頁面上出現什麼字眼無關**：

1. **取得報酬**（直接或間接）
2. **對特定證券提供分析意見或推介建議**

法院見解亦指出，<cite index="22-1">取得報酬不以實際收取者為限，若已約定報酬而尚未收取，仍與無償委任有別而應包括在內</cite>。實務上亦有見解認為，<cite index="22-1">於網路上營利刊載投資資訊時應盡量提供一般性資訊，避免提供具體個股分析意見或推介建議；不論形式為講習、提供投資資訊或程式操作，只要投資人吸收後可直接或間接得出個別有價證券之結論，即可能落入第 4 條範疇</cite>。

**本系統輸出的正是「個別有價證券之結論」**，因此第 2 項要件實質上已成立。**真正的保護因素是第 1 項不成立——本期無任何報酬。**

### 4.6.2 本期定位與紅線

| 情境 | 風險評估 |
|---|---|
| 校內專題、口試展示、非營利、封閉使用 | **本期定位**，因無報酬，不構成第 4 條之證券投資顧問 |
| 對外公開但完全免費、無任何直接或間接收益 | 風險較低，但仍應審慎 |
| **收費、訂閱、廣告分潤、以此招攬客戶、換取任何形式對價** | **已可能構成第 4 條，須先取得正式法律意見與主管機關許可** |

**紅線（寫入專案守則）：** 本系統於取得正式法律意見前，**不得以任何形式收費或換取對價**，包括訂閱、贊助、廣告、導流分潤、或以系統作為招攬其他服務之工具。

### 4.6.3 用詞規範仍然保留

UI、推播與報告中不得出現買進、賣出、目標價、建議部位、勝率預測等字眼。

**但須理解其定位已改變：這是降低誤解與管理使用者期待的產品規範，不是法律豁免。** 兩者不可混為一談，此區分亦為 §22 口試之必答內容。

# 6. 核心研究問題與假設

## 6.1 主要研究問題

在每日固定決策時間，僅使用當時已公開的價量、法人籌碼、融資融券、族群動能與消息資訊，透過規則式量化訊號及現成 LLM 之事件抽取，能否提高未來 10 個交易日高品質超額動能事件的偵測精確率？

## 6.2 次要研究問題

1. 籌碼資訊加入價量訊號後，是否提高 Precision 與 PR-AUC？
2. 族群乘數是否在個股訊號之外提供額外增益？
3. LLM 抽取的消息特徵，是否在價量、籌碼、族群之外提供額外增益？
4. 系統是否只在多頭市場有效？
5. 候選分數是否與未來超額報酬呈現單調關係？
6. 學習權重是否優於先驗權重與等權排名？
7. 現成 LLM 對台股消息的結構化抽取，與人工標註的一致程度為何？
8. LLM 建立的主題成分表，與人工分類的一致程度為何？

## 6.3 研究假設

| 編號 | 假設 | 可判定性 |
|---|---|---|
| H1 | 價量規則可使正樣本率高於隨機基準 | ✅ |
| H2 | 加入籌碼後優於只有價量 | ✅ |
| H3 | 加入族群乘數後優於個股訊號 | ✅ |
| H4 | 加入消息特徵後優於前三者 | ⚠️ **檢定力不足** |
| H5 | 系統在多頭市場表現優於空頭市場 | ✅ |
| H6 | 重大負面消息可有效降低假正例 | ✅ |
| H7 | LLM 消息抽取與人工標註 κ > 0.6 | ✅ **不受樣本數限制** |
| H8 | LLM 主題分類與人工分類一致率 > 85% | ✅ **不受樣本數限制** |
| H9 | 族群啟動天數與續航機率呈倒 U 形 | ✅ |
| H10 | 個股延伸度與續航機率呈倒 U 形 | ✅ |

## 8.2 Point-in-time 原則

每筆資料保存：`event_date`、`published_at`、`first_seen_at`、`retrieved_at`、`updated_at`、`available_from`、`source`、`revision_number`。

每日決策時間：**台北時間 21:30**。只有 `available_from <= decision_timestamp` 的資料可進入當日判斷。

**擷取截止時間為 21:25。** 21:25 之後到達的資料一律計入隔日。資料未到時標記缺值，**不得沿用前一日數值**，也**不得延後決策時間**。

## 8.3 PIT 分級（誠實揭露）

| 期間與來源 | PIT 等級 | 說明 |
|---|---|---|
| 2019–2026/7 價量籌碼（第三方彙整） | **準 PIT** | 已控制未來資料洩漏，但無法還原「當時公布的原始版本」 |
| **2026-08-01 起自爬新聞** | **嚴格 PIT** | `first_seen_at` 即實際取得時間 |

- 三大法人：部分成交（盤後定價、鉅額配對）可能於初次公布後才被補計進當日統計

此揭露為 AC-23（誠實揭露）的必要內容。

## 8.4 原始價與還原價分離

- **原始價**：成交判斷、漲跌停、10 元門檻、成交金額、交易成本
- **還原價**：報酬率、均線、相對強度、標籤計算

欄位命名強制區分：`close_adj` / `close_raw`，不得使用 `close`。

**還原價必須驗證：** 抽 20 檔（含 5 檔已下市、3 檔有減資或面額變更），與證交所除權除息計算結果表自行推算的結果對照，誤差需可解釋。此為 8/31 關卡項目。

## 8.5 消息面資料策略（本版核心改動）

### 8.5.1 為什麼不回補歷史新聞

2019–2025 的財經新聞無可信 `published_at`：網站分頁只回溯數月至一兩年、舊 URL 大量失效、時間戳多為「最後更新時間」而非首次發布時間、覆蓋率不明。**覆蓋率不明的語料無法支撐任何覆蓋率相關的研究結論。**

### 8.5.2 改為今日起自爬

新聞不必等系統完成才開始擷取。起爬日直接決定樣本量：

| 起爬日 | 到 12/1 可用交易日 | 獨立事件（估） |
|---|---|---|
| 11/20（隨系統上線） | 9 | 約 30 |
| **8/1（本版決定）** | **約 85** | **約 250–350** |

差距約十倍。且自爬資料的 `first_seen_at` 為實際取得時間，**嚴格 PIT，無存檔品質問題**。

**此項具時效性：每晚一天即永久少一天樣本，無法補回。**

### 8.5.3 這對研究結論的影響

## 8.6 公司重大訊息：待八月統計後定案

### 8.6.1 v2.0–v2.4 的認知錯誤（本版修正）

前版 §12.4 稱「取得或處分資產（重大訂單常走此類）」，**此為錯誤**。該準則規範的是公司取得或處分**資產**（不動產、設備、有價證券、無形資產），有明確的公告格式與金額標準。**客戶下訂單屬營業收入合約，不在該條射程內。**

### 8.6.2 實際規定

證交所重訊處理程序第 4 條第 1 項共 51 個款次，分三類：發生即須發布、達金額或比例標準才須發布、概括條款。

**⚠️ 上市與上櫃的款次編號不同（v2.5.1 補充，影響實作）：** 上櫃適用櫃買中心之對應處理程序，第 4 條第 1 項為 **53 個款次**（52 款明確內容 ＋ 1 款概括條款）。**兩市場的款次編號無法直接對應**，故 §8.6.3 之「強制類別白名單」必須維護 TWSE 與 TPEx 兩套對照表，不可共用一組編號。此為 M0 統計實驗須一併確認的項目。

**申報時限（影響 PIT，v2.5.1 補充）：**

| 情境 | 時限 |
|---|---|
| 一般各款情事 | 事實發生日起**次一營業日交易時間開始二小時前**（約次日 07:00 前） |
| 暫停或恢復交易（第 40 款） | 公告後 1 小時內 |
| 媒體報導澄清 | **立即輸入，至遲不得逾發現後 2 小時** |

**對本系統的實際影響：** 多數重訊之法定時限為「次一營業日開盤前」，代表 T 日發生的事件，其公告可能要到 **T+1 日清晨**才出現在公開資訊觀測站——**晚於 T 日 21:30 的決策時間**。因此該則公告會自然落在 T+1 日的判斷中，而非 T 日。

此行為由 §8.2 的 `available_from` 機制自動處理，無須額外邏輯，但有兩個必須知道的後果：

1. **回測與實盤一致**，不會產生洩漏；
2. **重訊在時效上系統性落後媒體報導**。這反向支持了 §8.5 自爬新聞的決定——新聞先到，重訊隨後（且媒體報導澄清類公告的 2 小時時限，正是這個時間差的制度化證據）。

**M0 須驗證：** 抽樣 30 則 2025 年重訊，比對 `事實發生日` 與 `公告時間`，量化實際落後幅度並寫入報告。

| 事項 | 是否強制公告 |
|---|---|
| 一般客戶訂單 | **不用** |
| 達重大標準之重要契約 | 要，有金額門檻 |
| **澄清媒體報導** | 要，且須於發現後 2 小時內 |
| 減產、停工 | 要（達影響比例標準） |
| 財務預測公布或更新 | 要 |
| 增資、可轉債、董事會重大決議 | 要 |

大量「取得 X 億訂單」公告屬**自願性揭露**，覆蓋率不均且偏向中小型股（有拉抬能見度動機）。

### 8.6.3 若採用，白名單須改為雙軌

1. **強制類別**：澄清媒體報導、財測更新、減產停工、董事會重大決議、重大訴訟、主管機關調查
2. **主旨關鍵字**：訂單、合約、擴產、認證、量產、客戶

單靠類別編號無法涵蓋訂單類（散在概括條款）。

### 8.6.4 為什麼這是關鍵決策點

**若八月統計顯示公告可用，則可回補至 2022，H4 的驗證期間從 85 個交易日回到約 4 年——這是本專案唯一能讓 H4 變成可判定的路徑。**

因此 §18 M0 的公告統計實驗必須在八月完成。

### 8.6.5 澄清媒體報導的特殊價值

該類別時效最嚴（2 小時內），代表：**媒體先報導 → 公司必須在 2 小時內承認或否認。**

系統因此免費取得一個經官方查證的媒體訊號，結構化、時間戳精確、可回測。被否認者正是 §13.5 的風險否決來源。

## 8.7 歷史標的池

**實作要點：資料一律以「日期」為單位擷取全市場檔案，不以「股票代號」為單位擷取歷史。** 逐日期擷取會自然包含當日交易但日後下市的股票，存活偏誤自動解決。

**已知限制：** 警示、處置與全額交割股的歷史狀態序列無乾淨公開時序資料，本期不回補。歷史期不套用此過濾並列為限制；前瞻期套用當期資料。

# 10. 標籤定義

## 10.0 三層分離原則（v2.6 新增，最重要的結構修正）

外部審查指出 v2.5.2 將「可成交性」寫入標籤與硬規則層，造成兩個問題：T 日 21:30 無法得知 T+1 之開盤與最低價（**未來資料洩漏**）；且將 T+1 鎖死者事後剔除，會使評估樣本排除掉最強的一批結果（**選擇偏誤**）。

本版明確分為三層，各層時點規則不同，**不得互相混用**：

| 層 | 內容 | 可用資訊 | 位置 |
|---|---|---|---|
| **L-A 決策層** | Gate、風險否決、評分排序 | 僅 T 日 21:30 前已公開者 | §13 |
| **L-B 標籤層** | DEF-RANK 等標籤計算 | 允許使用未來資料（標籤的定義即如此） | §10.1 |
| **L-C 成交模擬層** | T+1 進場、no-fill、成本、滑價 | 允許使用未來資料 | §10.4、§14.2 |

**關鍵規則：可成交性判定只存在於 L-C，不得出現在 L-A，也不作為 L-B 的樣本篩選條件。**

## 10.1 主標籤：DEF-RANK（v2.6 修正）

> T 日收盤後出現訊號，該股 **T 日收盤至 T+10 收盤**之相對市場超額報酬，是否落在當日標的池的**前 5%**。

**正樣本 Label = 1**，同時符合：

1. 自 **T 日收盤**至 **T+10 收盤**之報酬，減去同期對應市場報酬指數之報酬（**同為收盤對收盤**），其排名落在當日標的池前 5%
2. 資料完整（見 10.1.2）
3. 符合 T 日標的池資格

**v2.6 移除的條件：** 原第 1 項「T+1 存在合理成交可能」已刪除。理由見 §10.0 與 §10.4。

### 10.1.1 為什麼改為收盤對收盤

v2.5.2 以「T+1 開盤價進場」計算個股報酬，卻以收盤值計算市場指數報酬，**兩者時間口徑不一致**，超額報酬因此混入一段無法對應的隔夜跳空。

改為收盤對收盤後：

- 個股與指數口徑一致，超額報酬定義乾淨
- 標籤與「能不能買到」完全脫鉤，L-B 與 L-C 責任分明
- T+1 開盤進場之實務落差，全部由 §14.2 交易模擬層呈現，且該落差本身即為研究發現

### 10.1.2 前 5% 的精確定義（v2.6 補齊）

v2.5.2 稱「正樣本率精確等於 5%」為過度簡化。實際規則：

| 項目 | 規則 |
|---|---|
| 取樣數 | 當日有效樣本數 N，正樣本數 = `ceil(0.05 × N)` |
| 有效樣本 | 須符合 T 日標的池資格，**且 T→T+10 之報酬序列完整可計算** |
| 並列處理 | 以超額報酬降冪排序；並列時取 `method='min'` 之排名，若因並列導致超出 `ceil(0.05×N)`，**並列者全數列為正樣本**（寧可略高於 5%，不以任意規則切斷相同報酬者） |
| 停牌 | T→T+10 期間停牌但最終有收盤價者，以實際可得之收盤價計算，標記 `has_halt=1` |
| 期間下市或長期停牌 | 無法計算 T+10 報酬者，標籤為 **NaN**，排除於分類評估之外，並統計其比例寫入報告 |
| 缺值 | 任一價格缺失導致報酬不可計算者，同上標記 NaN |

**因此實際正樣本率為約 5%（通常 5.0%–5.3%），非精確 5%。** 每年實際值須列於報告。

**採用理由（修正後表述）：** 正樣本率穩定在約 5%，跨期可比；事件數為絕對門檻標籤的 3–5 倍；不受市場整體漲跌影響。**注意：此 5% 為「全標的池」之基準，不等於模型評估集合之基準，見 §14.1.1。**

## 10.2 副標籤（v2.6.1 對齊口徑）

**全部副標籤與主標籤採同一起算點：T 日收盤，還原價，相對對應市場報酬指數，收盤對收盤。**

**DEF-CONTINUATION**：T 收盤起算未來 10 個交易日之超額報酬 ≥ 20%，期間相對最大回撤 ≤ 15%；超額報酬落於 8%–20% 者為緩衝帶，標記 NaN。

**報告中須同時呈現「緩衝帶視為負樣本」的版本**，因為排除緩衝帶會虛增 precision，此為必問項。

**DEF-SURGE**：T 收盤起算未來 20 個交易日內之**最高收盤漲幅** ≥ 30%，同期超額報酬 ≥ 20%，期間最大回撤 ≤ 15%。

> **v2.6.1 修正：** 原文為「最高**可實現**漲幅」，「可實現」隱含可成交性判定，違反 §10.0 之三層分離。標籤層不得涉及成交可行性，故改為「最高收盤漲幅」。實際能否吃到，一律由 §10.4 與 §14.2 之成交模擬層回答。

**DEF-SURGE 的溝通用途（v2.6.1 新增）：** 一般所稱之「飆股」接近 DEF-SURGE，而 DEF-SURGE 樣本幾乎必然是 DEF-RANK 之子集。因此報告與口試應同時呈現兩個數字：

- **統計結論用 DEF-RANK**：Precision@10 與其對 `base_scored` 之 lift
- **產品溝通用 DEF-SURGE**：「A 級候選中，有 X% 於 20 個交易日內漲幅超過 30%」

第二個數字由既有回測資料直接計算，零額外成本，但它才是評審與使用者聽得懂的語言。**兩者不得混用**：DEF-SURGE 之樣本數過少，不作為顯著性判定依據。

## 10.3 標籤的正當性

標籤 y 使用未來資料計算，**這不是洩漏，這是標籤的定義**。且 y 由真實成交價算出，準確度為 100%，不涉及任何模型判斷。

洩漏的定義是特徵 X 使用了決策時點之後的資訊。X 與 y 的時點規則不同，不可混淆。

## 10.4 成交模擬與 no-fill 處理（v2.6 修正）

**v2.5.2 的錯誤：** 將 T+1 鎖死者「樣本剔除」。系統在 T 日確實選中了該股，事後刪除等同假裝當時沒選到，會使評估樣本系統性排除最強的一批結果，**precision 與報酬同時失真**。

**修正後規則：**

| 判定 | 定義 | 處理 |
|---|---|---|
| **no-fill** | T+1 開盤價 = 漲停價 **且** T+1 最低價 = 漲停價 | 標記 `filled = false`；**樣本保留** |
| filled | 其餘情形 | 以 T+1 開盤價進場 |

**兩層分別報告，不得合併：**

1. **訊號品質（分類層）**：所有被選中的候選皆納入，含 no-fill 者。此層回答「系統選得準不準」。
2. **實際成交率與交易績效（模擬層）**：no-fill 者記為未成交、報酬不計入，但**必須列入分母**並單獨報告成交率。此層回答「選得準能不能吃得到」。

**必報指標：** 每日成交率、A 級候選之 no-fill 比例、以及「若全部可成交」與「實際可成交」兩種假設下的績效差距。

**此落差本身即為重要研究發現**——它量化了「紙上策略」與「可執行策略」的距離，且是多數坊間選股服務刻意不談的部分。

## 10.5 事件去重

同一股票連續多日符合正樣本時，主分析僅保留該波段第一個正樣本日。日期級資料仍保存供每日追蹤使用。統計顯著性以事件級樣本為主。

## 10.6 實作參考

DEF-CONTINUATION 本質為 triple barrier method。可參考 `mlfinpy` 的向量化路徑掃描實作，但 barrier 需改為相對市場的超額報酬序列。

文獻依據：Lopez de Prado, *Advances in Financial Machine Learning*, Ch.3。本案「Gate ＋ 排序」兩層架構對應 meta-labeling 概念。

# 11. 訊號與特徵

## 11.0 訊號設計原則

1. 每個訊號必須可獨立計算、可獨立開關
2. 所有門檻寫在 YAML，程式只讀不寫
3. 每個門檻須給參數掃描範圍，供 §13.7 高原檢查
4. 訊號之間不得互相依賴計算結果

## 11.1 P0 價量訊號

| 編號 | 名稱 | 條件 | 掃描範圍 |
|---|---|---|---|
| SIG-V01 | 爆量攻擊 | T 日量 ≥ 20 日均量 **2.5** 倍、收紅、成交金額 ≥ 5,000 萬 | 2.0–3.5 |
| SIG-P01 | 創波段新高 | 收盤 ≥ 過去 **60** 日最高收盤、收盤位置 ≥ 0.7 | 40–90 日 |
| SIG-P02 | 帶量長紅突破 | 漲幅 ≥ **5%**、站上 20 日均線、同時符合 SIG-V01 | 3%–7% |
| SIG-R01 | 雙週期相對強度 | 60 日報酬排名前 **15%** 且 20 日報酬排名前 **10%** | 10%–25% / 5%–20% |

**SIG-R01 的排名必須對照當日標的池計算，不可對照現存股票清單。**

## 11.2 P0 籌碼訊號

| 編號 | 名稱 | 條件 | 掃描範圍 |
|---|---|---|---|
| SIG-C01 | 法人連買 | 外資或投信連續買超 ≥ **3** 日 | 2–5 日 |
| SIG-C02 | 投信連續買超 | 投信連買 ≥ **2** 日 | 2–4 日 |

**累計買超需除以流通股數或近 20 日均量正規化。** 買超 5,000 張對台積電是雜訊，對小型股是重大事件。

## 11.3 波形特徵

- 收盤位置 `(C - L) / (H - L)`
- 盤整壓縮度：過去 N 日 `(最高 - 最低) / 均價`
- 上影線比例（連續長上影為負面訊號）
- 量價確認：上漲日均量 ÷ 下跌日均量
- 跳空缺口：開盤價 vs 前收

**明確不做：** 型態辨識（頭肩底、旗形等，無標準定義且無穩健證據）；將 K 線圖截圖交由多模態模型判讀（不可重現，且圖上座標軸與日期直接洩漏未來資訊）。

## 11.4 延伸度特徵

現行特徵（60 日 RS、20 日 RS、創新高）系統性偏袒已上漲多日之個股，而模型**沒有任何欄位可表達「這檔已飆幾天」**，因此無法自行修正。

| 欄位 | 說明 |
|---|---|
| `days_since_first_gate` | 本波啟動至今交易日數 |
| `run_up_since_gate` | 本波啟動以來累積漲幅 |
| `ext_from_ma20` | 收盤對 20 日均線乖離率 |
| `consecutive_days` | 連續入選天數 |

對應 H10（倒 U 假設）：剛啟動時訊號未確認，上漲過久後動能衰竭，中段為甜蜜區。

## 11.5 市場環境（regime）特徵

| 欄位 | 說明 |
|---|---|
| `mkt_regime` | 多頭／盤整／空頭（由指數位階與均線關係判定） |
| `mkt_breadth` | 全市場上漲家數佔比 |

提升為特徵寬表欄位（非僅事後分組），使模型可學習「同一訊號在不同市況下成功率不同」，直接支援 H5。

## 11.6 族群乘數（本版收斂）

### 11.6.1 為什麼族群不做成一組特徵

v2.2–v2.4 曾將族群拆為動能、籌碼、消息、個股相對位置四組共 19–22 欄。本版收斂為**單一乘數**，理由：

1. 族群消息特徵依賴新聞歷史（不可得）
2. 欄位過多使 §14.6 的 MDE 惡化
3. 族群的作用是「整體抬升或壓抑」，本質是一個純量，不需拆成多欄
4. 乘法對「無族群訊號乘 1.0」的處理比加權歸一化自然

### 11.6.2 公式

```python
theme_multiplier = 1.0 + (
    0.15 * theme_ignition_curve   # 啟動天數倒 U
  + 0.10 * theme_leader_strength  # 龍頭強度
  + 0.08 * theme_breadth_rising   # 上漲家數「在增加」（變化量，非水位）
  + 0.06 * theme_money_flow       # 族群法人淨買超佔均額
)
theme_multiplier = clip(theme_multiplier, 0.85, 1.35)
```

**四個輸入全部來自既有價量籌碼資料，零新資料源。**

**v2.6 措辭修正：** v2.5.2 稱「無門檻、無 if-else」並不正確——§11.6.3 之啟動判定使用 0.8／0.5 門檻，倒 U 曲線使用 5 天／12 天／20 天分段。正確表述為：**四個輸入本身為連續值，但啟動狀態之判定與倒 U 分段確實包含門檻，故該等門檻一律列入 M6 參數高原掃描**（§11.6.2.1、§11.6.3）。

係數與 clip 範圍進 M6 參數高原掃描，現階段為初值。

### 11.6.2.0 leave-one-out：不得用自己的漲幅替自己加分（v2.6 新增）

外部審查指出一項自我參照缺陷：若某股本身即為族群龍頭，`theme_leader_strength` 會由該股自己的報酬決定，等同**用自己的漲幅推高自己的分數**；`theme_breadth_rising` 與 `theme_money_flow` 亦同。

**修正規則：族群層四項輸入，於計算某檔個股之乘數時，一律排除該股自身（leave-one-out, LOO）。**

| 輸入 | LOO 作法 |
|---|---|
| `theme_leader_strength` | 取「排除該股後」族群內最強成分股之報酬百分位 |
| `theme_breadth_rising` | 分子分母皆排除該股 |
| `theme_money_flow` | 排除該股之法人買超與成交金額 |
| `theme_ignition_curve` | 啟動天數依族群整體強度序列判定；**族群相對強度序列亦採 LOO 版本重算** |

**實作提示：** LOO 可以「族群總和 − 該股值」向量化計算，成本近乎為零，不需逐股重算。

**成分股 < 6 檔時**（扣除自身後不足 5 檔），乘數設為 1.0 並標註，與 §11.6.4.1 一致。

**此修正同時消除 §14.4「單純族群動能」基準的一個混淆來源**——LOO 之後，族群乘數確實只反映「同儕」資訊。

### 11.6.2.1 四個輸入的值域定義（v2.5.2 補齊，v2.6 補缺值規則）

**統一規範：四個輸入一律標準化至 `[-1, +1]`，其中 0 為中性。** 係數加總為 0.39，故乘數理論範圍為 `[0.61, 1.39]`，再 clip 至 `[0.85, 1.35]`。**下界 clip 為有效約束**，代表族群極弱時最多壓抑 15%，不會把個股分數壓垮。

| 輸入 | 計算方式 | 值域 |
|---|---|---|
| `theme_ignition_curve` | 依 §11.6.3 之啟動天數分段函數（見下表） | [-0.5, 1.0] |
| `theme_leader_strength` | 族群內最強成分股之 20 日報酬全市場百分位 `pct`，取 `2 × pct − 1` | [-1, 1] |
| `theme_breadth_rising` | 族群上漲家數佔比之 5 日變化量 `Δ`，取 `clip(Δ / 0.25, -1, 1)` | [-1, 1] |
| `theme_money_flow` | 族群法人淨買超佔成交金額比，取當日全體族群之百分位 `pct`，再取 `2 × pct − 1` | [-1, 1] |

**`theme_ignition_curve` 分段函數（初值，M6 掃描）：**

| 啟動天數 | 值 |
|---|---|
| 未啟動（未觸發 §11.6.3 條件） | **0**（中性，非負值） |
| 第 1–5 天 | 1.0 |
| 第 6–12 天 | 由 1.0 線性遞減至 0 |
| 第 13–20 天 | 由 0 線性遞減至 −0.5 |
| 第 21 天以後 | −0.5 |

**「未啟動 = 0」而非負值**：沒有族群訊號不等於族群不利，此與 §12.3.5「無消息不填中性負值」為同一原則。

**缺值規則（v2.6 補齊）：** 任一輸入無法計算時（資料缺漏、成分股不足、族群未建立），該輸入以 **0（中性）** 代入，而非跳過或以平均值填補；四項皆缺時乘數為 1.0。缺值情形須記錄於 `theme_breakdown`，使證據卡可顯示「本項無資料」。

**採用百分位（而非原始值）標準化的理由：** 三項輸入皆為橫斷面比較，百分位可自動適應不同市況與族群規模，且無須另訂絕對門檻，符合 §11.0 之設計原則。`theme_breadth_rising` 為唯一使用絕對尺度者（除以 0.25），因其本身已是有界的比例變化量；0.25 為初值，M6 掃描 0.15–0.40。

### 11.6.3 啟動日判定（必須寫死）

> 族群相對強度百分位**首次突破 0.8** 的當日為第 1 天；
> 之後只要未跌回 **0.5 以下**，持續計數；
> 跌破則重置。

倒 U 曲線初值：第 1–5 天為高原（值 1.0），第 6–12 天線性遞減，第 13 天以後為 0 或轉負。

### 11.6.4 為什麼用變化量而非水位

`theme_breadth_rising` 取**變化量**：「上漲家數從 20% 升到 45%」是擴散訊號；「已經 45% 且停在那」不是。

### 11.6.4.1 主題歸屬規則（v2.5.2 補齊）

**一檔股票可屬於多個主題**（例：光環同時屬 CPO 與矽光子），須明訂處理方式。

| 情境 | 規則 |
|---|---|
| 屬於多個合格主題 | **取乘數最大者**；產生該乘數之主題記為 `theme_name`（主主題），其餘記於 `theme_all[]` |
| 合格主題之定義 | LLM ⓪ 之 `confidence` ≥ 0.7 **且** 該主題成分股 ≥ 5 檔 |
| 無合格主題 | **以官方產業別作為 fallback 族群**，同樣計算乘數 |
| fallback 族群成分股 < 5 檔 | 乘數 = 1.0，輸出標註 |

**取最大值而非平均的理由：** 一檔同時屬於 CPO 與矽光子的公司，在 CPO 啟動期確實受惠於 CPO；取平均會被尚未發動的另一主題稀釋，低估實際情況。**惟此為設計選擇，M6 須同時掃描 `max` 與 `mean` 兩種聚合方式並於報告呈現對照。**

**以官方產業別作為 fallback 的理由：** 若無 fallback，大量非題材股（金融、傳產、公用事業）之乘數將一律為 1.0，形成一個無差異的大群體，使族群面向僅對少數題材股生效，B+ vs B 的消融比較會被稀釋。官方產業別資料既有、零成本，可使乘數覆蓋全標的池。

**主題數量要求：** §11.6.3 之啟動判定使用族群百分位（> 0.8），須有足夠主題數才有意義。**LLM ⓪ 應建立 25–40 個主題**；連同官方產業別 fallback，每日參與百分位計算之族群數應 ≥ 30。**若實際主題數 < 20，§11.6.3 之百分位門檻須改以絕對門檻（族群 20 日報酬 > 全市場中位數）替代**，並於報告說明。此為 AC-07 之附加驗收項。

### 11.6.5 族群內不做個股差異

族群層乘數對族群內所有股票統一套用。

**落後股不會因為落後而被推前。** 這避免「族群熱就買最弱的股票」的陷阱——族群內最落後者多半是有原因才落後（產品線未真正沾到題材、營收占比低、財務有問題）。動能文獻的一致結論是強勢族群中領先者傾向繼續領先。

系統要抓的是「龍頭已動、族群啟動初期、**個股自身已有確認訊號**」的擴散標的。個股自身確認由第一輪的 Gate 保證。

# 12. 消息面與 LLM 模組

## 12.1 三個 LLM 位置

見 §4.2 對照表。本章詳述 LLM ⓪ 與 LLM ①；LLM ② 見 §15.3。

## 12.2 LLM ⓪：主題成分表

### 12.2.1 為什麼需要

**官方產業別分不出台股的主題。** CPO、矽光子、重電、AI 伺服器、機器人等主題橫跨「電子零組件」「通信網路」「電腦週邊」「電機機械」多個官方分類。關鍵字比對也失效——多數公司的產品描述不會出現「CPO」三個字。

這是規則做不到、LLM 有明確優勢的任務，且**有標準答案可人工抽驗**。

### 12.2.2 輸入與輸出

**輸入**：公開資訊觀測站的營運概況、主要產品、營收比重。

**輸出**：

```json
{
  "stock_id": "3234",
  "theme": "CPO",
  "confidence": 0.9,
  "evidence": "主要產品為光收發模組，光通訊營收占比逾七成"
}
```

**`evidence` 必須是原文可查證的句子，不得為 LLM 推論。** 抽驗時翻開原始資料即可判定對錯。

### 12.2.3 版本管理

成分表加 `valid_from` / `valid_to`，重跑產生新版本而非覆蓋。

**適用範圍須區分（v2.5.1 修正）：**

| 期間 | 可用版本 | 說明 |
|---|---|---|
| 歷史回測期（2019–2026/7） | **僅有 2026 年建立之版本** | 成分表於 M4（10 月）才建立，歷史期不存在「當時那一版」。**此期間之族群結果一律標示為「回顧式分類（retrospective classification）」，不得稱為嚴格 PIT，亦不得稱為準 PIT** |
| 上線後（2026/11 起） | 當時有效版本 | 由 `valid_from`／`valid_to` 決定，回放模式須載入對應版本 |

v2.5 原文「回測使用當時那一版，不可用最新版跑舊資料」在歷史期無法執行，故修正為上述分期規則。**版本管理機制仍須於第一天建立**，否則上線後的回放（AC-17）與可重現性（AC-16）將失效。

### 12.2.4 必須寫入報告的限制

主題本身會演化——CPO 在 2022 年還不是市場主題。以今日主題清單回測 2022–2023，本質上假設當時已知這些主題存在，屬**輕微前瞻偏誤**。

緩解方式：以**產品組成**而非市場熱度定義主題。此偏誤無法完全消除，須於報告明列。

### 12.2.4.1 B+ 版歷史結果的正確表述（v2.6）

外部審查指出：以今日建立的成分表回測 2022，不能宣稱為 PIT。修正後之表述規則：

| 期間 | 標示 | 報告用語 |
|---|---|---|
| 2019–2026/7 之 B+ 版結果 | **回顧式分類** | 「族群歸屬採用 2026 年建立之成分表回溯套用，非當時可得資訊，屬回顧式分類，結果為上限估計」 |
| 2026/11 上線後 | 嚴格 PIT | 「族群歸屬使用當時有效版本」 |

**H3（族群增益）之結論須同時標註此限制。** 若前瞻期樣本足夠，應另行呈現「僅前瞻期」之 B+ vs B 對照，作為未受此偏誤影響的佐證。

### 12.2.5 股票與主題為多對多（v2.6 明確化）

資料模型須為獨立的關聯表，不得於股票表加單一 `theme` 欄位：

```
theme_membership(
  stock_id, theme_id, confidence, evidence,
  valid_from, valid_to, table_version
)
```

一檔股票可對應多個主題（§11.6.4.1 之取最大值規則據此運作），一個主題含多檔成分股。**PK 為 (stock_id, theme_id, valid_from)。**

### 12.2.5 驗收

挑 3 個主題（CPO、重電、機器人），兩位組員獨立核對 LLM 產出的成分股名單，計算準確率與召回率。目標 > 85%（H8）。

## 12.3 LLM ①：消息抽取

### 12.3.1 輸出特徵欄（10 個邏輯欄位，實際佔 18–22 個寬表欄）

| 欄位 | 型別 | 產生方式 | 驗證方式 |
|---|---|---|---|
| `evt_type_*`（one-hot 8–12 類） | 0/1 | LLM 分類 | gold set |
| `evt_sentiment` | -1/0/1 | LLM 分類 | gold set |
| `has_amount` | 0/1 | LLM 抽取 | **對原文比對** |
| `amount_twd` | float | LLM 抽取 | **對原文比對** |
| `amount_to_mktcap` | float | **程式**（÷ 市值） | 純計算 |
| `has_schedule` | 0/1 | LLM 抽取 | 對原文比對 |
| `has_named_customer` | 0/1 | LLM 抽取 | 對原文比對 |
| `specificity` | 0–5 | LLM 評分 | gold set（κ） |
| `materiality` | 0–5 | LLM 評分 | gold set（κ） |
| `evt_is_denial` | 0/1 | LLM 抽取 | **對原文比對** |
| `evt_direction` | up/down/na | LLM 抽取 | **對原文比對** |
| `evt_is_cancellation` | 0/1 | LLM 抽取 | **對原文比對** |
| `novelty_90d` | 0/1 | **程式**查資料庫 | 純計算 |
| `has_news` | 0/1 | 程式 | — |

**只有 2 欄是主觀評分**（`specificity`、`materiality`），其餘為可對原文比對的抽取或程式計算。

**欄位數計算（v2.6.1 更新）：** 上表為 14 列（v2.6 新增三個風險否決用之客觀欄位），其中 `evt_type_*` 本身即為 8–12 個 one-hot 欄位，故實際佔用寬表 **21–25 欄**。§11.7 之欄數已同步更正。

**三個新增欄位皆為客觀抽取項**（可對原文比對），非主觀評分，符合 §4.3.1 之判準，且為 §13.1.1 風險否決規則之唯一輸入來源。

**若 §14.6 檢定力分析顯示欄位過多，優先縮減 `evt_type_*` 至 6 類**（其餘併入 `evt_other`），可省下 2–6 欄且不影響其他面向。

### 12.3.2 已刪除與已移轉的維度

| 維度 | 處置 | 理由 |
|---|---|---|
| `potentially_unpriced_score`（尚未反映） | **刪除** | 等同要求 LLM 預測股價反應，違反 §4.3，且為最大污染入口 |
| 新穎度 | **改由程式計算** | 「同公司同事件類型 90 天內首次出現」是一句 SQL，比 LLM 準且免費 |
| 時效性 | 程式為主 | 消息日期 vs 事件時程 |

### 12.3.3 `event_type` 的編碼

**必須用 one-hot，不可用整數編碼。** 五十餘種類型若編成 1–50，樹模型會學到「類型 23 和 24 相鄰」這種不存在的關係。

只保留 8–12 個高價值類型各一個布林欄位，其餘歸入 `evt_other`。

### 12.3.4 金額正規化

`amount_twd` 必須除以市值或近 20 日均額。12 億對台積電是雜訊，對 30 億市值公司是重大事件。

### 12.3.5 缺值處理

無消息時：

- **固定權重版**：權重重新歸一化
- **迴歸版**：`has_news = 0`，由模型學習其影響
- **樹模型**：直接填 `NaN`

**不得填入「中性值」**——填中性等於白送分給八成股票。無消息不代表負面，個股仍可依價量籌碼入選。

### 12.3.6 gold set 人工標註（P0，不可砍）

- 抽取 **180 則**消息（涵蓋各類型）
- 兩位組員**獨立**標註上述欄位
- 計算人與人一致性（Cohen's κ）
- 計算 LLM 與人的一致性
- 分析失敗模式：抽錯金額、幻覺數字、舊聞誤判為新聞
- **P1 延伸**：同一 gold set 上比較 1 個小型 API 模型 + 1 個地端模型（vLLM，現有 GPU）

**此為本案不受樣本數限制的驗證途徑，是保底成果。成本約 5 人天。**

## 12.4 工程要求

- **快取**：key = `hash(prompt_version + model_id + text)`，value = 完整原始回應。重跑成本歸零。**第一天就要寫。**
- **儲存原始回應**：存入資料庫，不是只存解析後分數。外部模型可能下架或靜默更新。
- **`model_id` 釘死版本字串**，不使用 `latest` alias。每列記錄 `model_id`、`prompt_hash`、`temperature`、呼叫時間。
- **Batch API**：歷史回補無延遲需求，批次模式可省約一半成本。
- **Schema 驗證與重試**：使用 Pydantic 或 `instructor`。
- 溫度設為 0。

## 12.5 成本估算

- 預篩池每日約 100 檔，其中當日有相關消息者約 10–20%
- 每日 10–20 次呼叫；若公告採用並回補至 2022，約 1,000 個交易日 ≈ **15,000–30,000 次**
- 每次約 2,000 input + 300 output token
- 小模型等級：約 **NT$3,000–5,000**；中型：約 **NT$10,000**
- 含重跑，預算抓 2–3 倍

**月營收完全不需要 LLM**，為純數值表格，以規則計算年增率、月增率、加速度。

## 12.5.1 消息來源分離原則（v2.5.2 補齊）

**問題：** 若 M0 決定採用公告並回補至 2022，將出現兩種消息來源、且可用期間不同——公告自 2022 起、自爬新聞自 2026-08 起。若將兩者混為單一「消息面」特徵，則 2022–2026/7 期間 `has_news` 恆為 0（無新聞）、僅有公告，而 2026/8 之後兩者皆有。**訓練分布與推論分布不一致，違反 §13.6.1 之明確要求。**

### 規則：兩套來源，特徵前綴分離，不得混用

| 來源 | 特徵前綴 | 可用期間 | 用於 |
|---|---|---|---|
| 公司重大訊息（公告） | `ann_*` | 2022– （若 M0 採用） | C／D 版之回測與訓練 |
| 自爬財經新聞 | `news_*` | 2026-08– | 前瞻期分析；不進入歷史回測訓練 |

**硬性規則：同一個模型不得同時使用可用期間不同的兩組來源特徵。**

### 依 M0 結果分為兩種情境

**情境甲：M0 判定公告可用（則數 > 2,000／年且分布 > 300 家）**

- C／D 版**僅使用 `ann_*` 特徵**，訓練與驗證期間一致（2022 起），H4 轉為可判定
- `news_*` 僅用於前瞻期，另立一組**探索性分析**（非預先註冊之主要假設），報告中明確標示為 exploratory
- 兩者不合併為單一 `news_score`

**情境乙：M0 判定公告不可用**

- C／D 版**僅使用 `news_*` 特徵**，期間為自爬視窗約 85 個交易日
- H4 維持檢定力不足，僅報告效果量與 CI（現行 §14.6 之寫法）
- `ann_*` 不實作，M3 直接跳過

**兩種情境皆不產生分布不一致。** 決策於 8/7 M0 完成時作出，並寫入 9/20 預先註冊文件。

**輸出欄位：** `candidate_card` 之 `news` 物件須帶 `source` ∈ `{announcement, news, both}`，使任一日期之重播可還原當時使用的來源組合。

## 12.6 污染控制

| 措施 | 說明 |
|---|---|
| 只做抽取與分類 | 不詢問未來價格方向 |
| 已刪除「尚未反映」維度 | 最大污染入口 |
| 消息面驗證限縮於自爬視窗 | 8/1 起的新聞在模型訓練截止之後，無記憶優勢 |
| gold set 為主要驗證 | 不受記憶污染影響 |
| 固定 prompt 與模型版本，溫度 0 | 可重跑檢查一致性 |
| P1：地端小模型比較 | 小模型對台股具體事件記憶較弱，可作為污染敏感度檢查 |

**污染影響範圍的誠實評估：** 系統五個部分中，價量訊號、籌碼訊號、族群乘數、標籤 y 四者為純計算，LLM 未參與，**不受污染**。僅消息面 11 欄中的 2 欄主觀評分有污染疑慮，且已透過自爬視窗隔離。

# 13. 兩輪評分與候選判定

## 13.1 硬規則層（布林判斷，不打分數）

**必須與分數計算在程式碼上物理隔離。**

| 類別 | 內容 |
|---|---|
| 可交易性（**僅限 T 日已知者**） | 標的池資格、流動性門檻（20 日均額）、全額交割排除、當日是否處置或停牌 |
| Gate（至少滿足一項） | 爆量攻擊／創波段新高／帶量長紅／首根漲停／高可信度新消息 |
| 風險否決（**程式規則，非 LLM 評分**） | 見 §13.1.1 |

**風險否決不得寫成「扣 20 分」。** 讓分數權衡風險，遲早會出現「技術分高所以蓋過重大負面消息」的案例，那是產品責任問題。

**⚠️ v2.6 移除：T+1 可成交判定不得置於本層。** T 日 21:30 無法得知 T+1 之開盤價與最低價，將其寫入硬規則即為未來資料洩漏。可成交性一律移至 §10.4 之成交模擬層。**此為 AC-02 leakage 測試之必檢項目。**

### 13.1.1 風險否決規則表（v2.6 新增）

**否決條件一律為程式可稽核之布林運算，輸入僅限 LLM ① 抽取之客觀欄位。**

| 否決條件 | 判定依據（皆為客觀抽取欄位） |
|---|---|
| 公司否認傳聞 | `evt_type = 澄清媒體報導` **且** `evt_is_denial = true` |
| 財測下修 | `evt_type = 財務預測更新` **且** `evt_direction = down` |
| 訂單或合約取消 | `evt_type = 重要契約` **且** `evt_is_cancellation = true` |
| 重大訴訟、主管機關調查 | `evt_type ∈ {重大訴訟, 主管機關調查}` |
| 停工、減產、重大事故 | `evt_type ∈ {停工減產, 重大災害}` |

**新增抽取欄位（客觀、可對原文比對）：** `evt_is_denial`、`evt_direction`、`evt_is_cancellation`。三者皆為 gold set 檢驗項目。

### 13.1.2 低信心負面消息不否決，改為警示（v2.6 新增）

外部審查指出：以低信心的負面判斷直接刪除候選，過於武斷且不可稽核。

| LLM 抽取信心 | 系統行為 |
|---|---|
| `confidence ≥ 0.8` 且符合 §13.1.1 條件 | **硬否決**，排除於所有名單 |
| `0.5 ≤ confidence < 0.8` | **不否決**，但於清單與證據卡標記 `risk_flags` 醒目警示，且該股不得列入 A 級（降為 B 級） |
| `confidence < 0.5` | 僅記錄於 `risk_flags`，不影響分級 |

**設計理由：** 硬否決是不可逆的；警示則把判斷權交還使用者，同時保留系統的可稽核性。此規則之門檻進 M6 掃描。

## 13.2 第一輪：個股分數

僅對通過硬規則層者計算。

### 13.2.1 百分位轉換

三個子分數的原始分佈完全不同（`news_score` 有八成以上為缺值），直接加權會使宣稱的權重與實際影響力不符，且跨期不可比。

```
tech_pct = rank(technical_score, 當日通過 Gate 之集合) / N
chip_pct = rank(chip_score, 同上) / N
news_pct = rank(news_score, 同上) / N
```

同時解決：尺度不一致、跨期不可比、市場整體漲跌造成的分數漂移。

### 13.2.2 加權

初值 `0.40 * tech_pct + 0.30 * chip_pct + 0.30 * news_pct`，權重來源見 §13.6。

無消息時歸一化為 `0.57 / 0.43 / 0`。

### 13.2.3 候選池

```
候選池 = (第一輪分數前 30 名) ∪ (當日有有效消息者)
```

**實際規模約 35–45 檔。**

### 13.2.4 聯集路徑的實際作用（v2.5.2 釐清）

v2.5 原文稱「第一輪第 40 名的消息股必須靠這條路徑進入」，此敘述須修正——**該股進入候選池後仍到不了 A 級**，因為 §13.4.2 已明訂乘數上限 1.35「推不動第 30 名到第 1」。釐清如下：

**聯集路徑的真實定位：確保有催化劑者必定進入 B 級觀察名單，而非讓其進入 A 級。**

三點理由：

1. **消息已佔第一輪 30% 權重**（§13.2.2）。真正的重大催化劑通常已使該股排進前 30，聯集是**安全網而非主要路徑**。
2. **不為消息股開 A 級特別名額。** 那等同以規則覆蓋排序，與 §13.1「硬規則不打分數、分數不做硬規則」的分層原則衝突，也與 §13.4.2「重新排序而非重新決定」的克制一致。
3. **B 級即為此類標的的正確位置**：有催化劑、價量未確認，正是 §13.5 表中「觀察」那一列。

**實作要求：**

- 每檔候選記錄 `entry_path` ∈ `{score, news_union}`，寫入 `candidate_card` 與輸出欄位。
- 聯集帶入數量上限 **15 檔**（避免重大事件日候選池膨脹），超出者依 `news_pct` 排序取前 15。
- **M6 須量化此路徑的價值**：統計 `news_union` 帶入者的比例、其後續 5／10／20 日表現，以及其是否曾在後續交易日循 `score` 路徑升入 A 級（即「先觀察、後確認」的完整案例）。

**若 M6 顯示該路徑帶入者表現不優於池內平均，且從未於後續升入 A 級，則於凍結時移除聯集路徑。** 此為可量測的設計，而非永久假設。

## 13.3 族群層：統一乘數

見 §11.6。族群內所有股票套用同一乘數。

**成分股不足 5 檔的族群**：乘數設為 1.0，並於輸出標註。

## 13.4 第二輪：重排

```python
final_score = round1_score * theme_multiplier
```

### 13.4.1 為什麼用乘法

1. 無族群訊號時乘 1.0，第一輪排名原樣保留，比加權歸一化自然
2. 乘數有明確上下限，一個族群判斷無法推翻整個個股分析
3. 取對數後即為線性，`log(final) = log(round1) + log(multiplier)`，§13.6 的邏輯迴歸照樣可學係數

### 13.4.2 乘數範圍的理由

clip 至 `[0.85, 1.35]`。上限 1.35 約可讓第 15 名升至前 5，但推不動第 30 名到第 1——這是合理的「重新排序」，不是「重新決定」。

## 13.5 消息與價量的一致性

| 組合 | 條件 | 系統行為 |
|---|---|---|
| 最強 | 正面重大消息＋價格突破＋量能確認＋法人買超 | 最高分 |
| 觀察 | 正面消息但價量未確認 | 進入觀察名單 |
| 風險 | 價量大漲但公司否認傳聞或有重大負面消息 | **風險否決，直接排除** |

## 13.6 權重的三個來源

### 13.6.1 訓練資料從哪來

**訓練資料不需另外蒐集，是系統自己產生的。**

- **X** = 特徵寬表（L2）
- **y** = Labeler 輸出（DEF-RANK）
- 兩張表以 `(stock_id, date)` join

預估規模（訓練期 2022-01 至 2023-12）：

```
約 490 個交易日 × 每日 80–150 檔
= 40,000 – 70,000 列
正樣本（5% 基準）≈ 2,000 – 3,500 個
```

**訓練群體 = 通過 Gate 之後的集合，不是全市場**（訓練分佈必須等於推論分佈）。

### 13.6.2 三個階段

**階段一（8–9 月）：先驗值 40/30/30**
目的是把管線跑通，不是求準。

**階段二（10 月）：邏輯迴歸**

```python
from sklearn.linear_model import LogisticRegression
model = LogisticRegression(class_weight='balanced')
model.fit(X, y)
```

特徵標準化後，將各組特徵的係數絕對值分別加總並歸一化，得到資料建議的權重。

經驗法則為每個特徵至少 10–20 個正樣本。本案約 7 個面向係數、2,000+ 正樣本，**超額約三十倍**。邏輯迴歸為凸最佳化，有唯一解，無隨機初始化、無超參數、無收斂問題。

**與先驗值的比較本身即為報告的一節。**

**階段三（11 月）：參數高原檢查，然後凍結**

### 13.6.3 必跑的零參數基準

```python
final_rank = (rank_tech + rank_chip + rank_theme) / 3
```

無任何可調參數、對分佈不敏感、不可能過擬合。

**若學習權重打不贏等權排名平均，則採用等權，並在報告誠實記載「權重最佳化未帶來顯著增益」。** 此為方法論加分項，同時是時程失控時的保底引擎。

### 13.6.4 三層保險

| 保險 | 內容 |
|---|---|
| 先驗權重 40/30/30 | 不用訓練，直接能跑 |
| 等權排名平均 | 零參數，不可能過擬合 |
| 參數高原檢查 | 若學出的權重為雜訊尖峰，直接退回等權 |

**「訓練失敗」在本設計中不是失敗模式，而是一個分支。三條路都能出貨。**

## 13.7 參數高原檢查

不找單點最佳值（多為雜訊）。作法：

- 權重加總 = 1，每個限制在 0.15–0.55，步長 0.05 → 約 40–50 種組合，全部跑完
- 畫成 heatmap
- 鄰近組合表現相近 → 高原，取中心值
- 僅單一組合特別好、鄰近皆差 → 雜訊尖峰，**不採用**，退回等權或高原中心

**heatmap 直接放入簡報，用以回答「為什麼是這個權重」。**

## 13.8 梯度提升樹：跑一次，不當產品引擎

以 LightGBM 或 XGBoost 跑一次作為**效果上限參考**。

不採用為產品引擎的理由：

1. **可解釋性**：產品核心是證據卡。線性模型可直接呈現各面向貢獻；樹模型只能給 SHAP 值，與產品定位衝突。
2. **過擬合風險**：正樣本率 5%、特徵 35–40 個，本期無時間做巢狀驗證。
3. **時程**：調參為無底洞，預期增益有限。

報告寫法：「非線性模型的 PR-AUC 為 X，線性版本為 Y，顯示特徵交互作用帶來的增益有限，故選擇可解釋的線性版本作為產品引擎。」

**此為口試強答：不是不會用，是試過之後有理由地不用。**

## 13.9 候選分級

| 等級 | 條件 | 系統行為 |
|---|---|---|
| A 級 | 通過 Gate、無風險否決，第二輪前 10 名，且 `final_score` ≥ 絕對下限（見下） | 正式候選 |
| B 級 | 第 11–30 名 | 觀察名單 |
| C 級 | 未達門檻但有單一強訊號 | 研究觀察 |
| 排除 | 風險否決或不可交易 | 不列入 |

### 13.9.1 絕對下限的定義（v2.6.1 重寫）

**v2.5.1 的錯誤：** 原定義為 `final_score ≥ 0.60`。但 §13.2.1 之 `tech_pct = rank(...) / N` 為**當日集合內百分位**，故當日排名第一者之 `round1_score` 恆 ≈ 1.0，**與當日訊號強弱無關**。任何建立在百分位分數上的門檻，實質上只是排名門檻的另一種寫法，**無法表達「今天大家都很弱」**，原訂之「空清單日佔比 5%–15%」在數學上不可能達成。

**空清單的真正來源是 Gate。** Gate 條件（爆量 ≥ 20 日均量 2.5 倍、創 60 日新高、漲幅 ≥ 5%）皆為**絕對條件**，弱勢日自然少有股票通過。此機制已存在且正確，無須另加分數門檻。

**修正後之 A 級絕對條件（三項並行，皆不使用百分位）：**

| 條件 | 定義 | 預設 | 掃描範圍 |
|---|---|---|---|
| AL-1 訊號數 | 須至少觸發 **2 個** P0 訊號（§11.1、§11.2 合計） | 2 | 1–3 |
| AL-2 原始強度 | `technical_score_raw`（**未經百分位轉換**之原始加權值）≥ 絕對門檻 | 依 M2 分布校準 | 訓練期 60–80 分位對應值 |
| AL-3 無降級 | 當日非 `degraded_mode = no_chip`（籌碼缺失日不出 A 級，僅出 B 級） | — | — |

**AL-2 的校準方式：** 於訓練期計算 `technical_score_raw` 之分布，取某分位對應之絕對數值寫入設定檔並**凍結為固定數值**（非分位數），使其在推論期具備「絕對」意義。

**空清單佔比為觀察指標而非校準目標：** M6 須報告訓練期與驗證期之空清單日佔比，但**不得為了達成某個佔比而回頭調整 Gate 參數**——那會使 Gate 淪為湊數工具。合理區間為 5%–20%，超出範圍時於報告說明原因即可。

**B 級不設絕對下限**，僅取第二輪第 11–30 名且通過 Gate 與風險否決者。

> **實作備註：** `technical_score_raw` 須與 `tech_pct` 並存於特徵寬表與 `candidate_card`，前者供絕對判定、後者供排序。此為 v2.6.1 新增之欄位需求。

**系統必須能輸出空清單。** 「今日無符合條件之候選」是合法輸出，且是產品的信任來源——市面上沒有選股服務敢這樣做。

## 13.10 同族群名額上限

A 級前 10 名，同一族群最多 **N** 檔，超出者擠到 B 級。

**分數層完全不動**，只在輸出層處理分散度。三方案於 M6 回測比較：不設限／上限 4 檔／強制不同族群。

**設計理由**：族群強勢時前 10 名同族群佔多數，真正的風險不是「這族群走完了」（那由 `theme_ignition` 倒 U 處理），而是**分散度**——名單全押單一族群，判斷錯了就全錯，且使用者難以使用。

- 所有權重與門檻寫在 YAML，程式只讀不寫
- 分數計算為純函式：

```python
score(features_row, config) -> {
    round1_score, round1_rank,
    tech_pct, chip_pct, news_pct,
    theme_multiplier, theme_breakdown,

    gate_passed, veto_reason
}
```

- 回測與每日排程呼叫**同一個函式**
- 每列輸出帶 `config_hash`，凍結時記錄並寫入最終報告（AC-16 可重現）

# 14. 評估設計

## 14.1 第一層：分類能力

主要指標：Precision、Recall、PR-AUC、Precision@5、Precision@10、Lift over Baseline、每日平均候選數、**事件級 95% 信賴區間**。

不使用 Accuracy 作為主要指標。

### 14.1.1 Lift 的基準必須是「實際被評分集合」的正例率（v2.6 修正）

**v2.5.2 的錯誤：** 假設 Precision@10 的隨機基準為 5%。但標籤定義於**全標的池**前 5%，而模型只對**通過 Gate 的集合**排名。通過 Gate 者本身即為爆量、突破、法人買超之強勢股，其正例率**必然高於 5%**，可能達 8%–15%。

若以 5% 作為基準計算 lift，將**系統性高估模型價值**——那部分增益來自 Gate（規則篩選），不是排序模型。

**修正後規則：**

| 基準 | 定義 | 用途 |
|---|---|---|
| `base_universe` | 當日全標的池之正例率（依定義約 5%） | 說明 Gate 本身的篩選價值 |
| **`base_scored`** | **當日通過 Gate 且被評分之集合的實際正例率** | **計算排序模型 lift 的正式基準** |

**Lift_model = Precision@K ÷ `base_scored`**，而非 ÷ 5%。

**報告須同時呈現三個數字，並拆解貢獻來源：**

1. 全池正例率（約 5%）
2. Gate 集合正例率 `base_scored` → 差額即 **Gate 的貢獻**
3. Precision@10 → 對 `base_scored` 之差額即 **排序模型的貢獻**

**此拆解是本案最誠實也最有說服力的呈現方式**——它明確區分了「規則篩選有用」與「排序模型有用」兩件事，而後者才是 H2、H3、H4 真正要檢定的對象。

### 14.1.3 三項待 M2 實測後定案之評估規則（v2.6.1）

以下三項無法在無真實數字時決定。**M2（9/20 前）跑出 Labeler 與基準數字後，須於預先註冊文件中一併定案並凍結。** 現階段記錄選項與建議，不預先選擇。

| # | 待決問題 | 選項 | 現階段建議 |
|---|---|---|---|
| 1 | Gate 通過數 < 10 檔之日，Precision@10 如何計算 | (a) 該日排除；(b) 以實際檔數計 Precision@k；(c) 分母固定 10、不足者計為未命中 | 傾向 **(b)**，另單獨報告「Gate 通過數 < 10 之日數佔比」；(a) 會排除弱勢日、系統性美化結果 |
| 2 | `base_scored` 逐日計算後平均，或全期間合併計算 | (a) 逐日平均；(b) 全期間 pooled | 傾向 **(b) pooled 為主要數字**，(a) 併列供參；集合大小逐日變動時，逐日平均會給小樣本日過高權重 |
| 3 | 事件去重與 Precision@10 之樣本基礎不一致 | Precision@10 本質為逐日指標，同一檔連續入選會重複計入；而顯著性檢定以事件級為主 | 明訂為**兩套並列指標**：`Precision@10_daily`（產品指標，含重複）與 `Precision@10_event`（研究指標，去重後）。報告中兩者皆列並標明各自基礎，**不得以其一取代另一** |

### 14.1.4 Gate 與排序模型不得同時最佳化（v2.6.1 新增）

`base_scored` 為 Gate 之函數：**Gate 越嚴，`base_scored` 越高，排序模型之 lift 越低——即使模型完全未變。**

此性質造成一個陷阱：若將 Gate 參數與排序權重放入同一組最佳化，系統會傾向「放寬 Gate」以美化 lift，而實際上是把更多雜訊放進來。

**規則：**

1. **Gate 參數於 §13.7 參數高原掃描中固定**，不與排序權重同組掃描。
2. Gate 之調整僅依 §14.7 之訊號有效性門檻進行，並以「Gate 集合正例率」與「每日通過檔數」兩項指標評估，**不看 lift**。
3. 報告須分開呈現 Gate 貢獻（5% → `base_scored`）與排序貢獻（`base_scored` → Precision@10），且註明兩者為不同層次之效果，不可相加宣稱。

### 14.5.1 v2.5.2 的順序錯誤

### 14.5.2 修正後的時序

| 日期 | 動作 | 說明 |
|---|---|---|
| 9/20 | **預先註冊 Git tag 凍結** | 假設、指標、決策規則、特徵清單、切分定義 |
| 9/20 – 11/5 | 僅使用 **train** 期 | 訊號開發、權重學習、參數掃描皆在此期完成 |
| **11/5** | **開啟 validation（僅此一次）** | `--unlock-validation`，寫入日誌 |

| **11/20** | **凍結設定，記錄 `config_hash`** | 此後不得再調整任何參數 |
| 11/20 之後 | **開啟 2026 holdout（僅此一次）** | 凍結後才開，作為真正的 out-of-sample |
| 12/1 | 前瞻期資料截止 | 自 8/1 起累積之嚴格 PIT 樣本 |

**驗證期只開一次、且必須在凍結之前**；holdout 只開一次、且必須在凍結之後。兩者順序不可顛倒，日誌為證。

### 14.5.3 切分邊界須留 gap（v2.6 新增）

主標籤向前看 10 個交易日。若 train 結束於 2023-12-31、validate 起於 2024-01-01，則 train 最後 10 天的樣本，其標籤來自 validate 期間——**標籤洩漏**。

**規則：每個切分邊界之後留 `gap = 10 個交易日`（等於標籤視窗長度），該區間樣本不納入任何切分。** 副標籤 DEF-SURGE 視窗為 20 日，若納入分析，該部分之 gap 為 20 日。

```yaml
data_split:
  # A / B / B+ 版（純量化）
  train:       [2019-01-01, 2023-12-31]
  gap_1:       10 個交易日           # 不納入任何切分
  validate:    [2024-01-16, 2025-12-31]   # 實際起點順延 gap
  gap_2:       10 個交易日
  holdout:     [2026-01-16, 2026-11-19]

  # C / D 版（依賴消息，來源見 §12.5.1）
  news_window: [2026-08-01, 2026-12-01]
  # announce_train: [2022-01-01, 2023-12-31]   # 若 M0 採用公告

  label_horizon_days: 10
  gap_days: 10
```

**實作提示：** `sklearn.model_selection.TimeSeriesSplit` 提供 `gap` 參數，可直接用於交叉驗證；本案之固定切分亦以同一常數處理，避免兩處不一致。

**驗收：** 自動化測試須斷言「任一切分中的樣本，其標籤計算所用之最後日期，不落入下一個切分區間」。此併入 AC-02。

## 14.6 檢定力分析與預先註冊

### 14.6.1 為什麼要做

以絕對門檻標籤（正樣本率 1–2%）估算，消息增益的最小可偵測效果約 6–8 個百分點，遠大於任何合理預期。**不論真相為何都會得到「不顯著」，且無法區分「效果不存在」與「樣本不足」。**

改用 DEF-RANK 後事件數提升 3–5 倍。但 C／D 版僅有約 85 個交易日，MDE 仍偏大。

### 14.6.2 執行方式

**時機：9 月中，取得 Labeler 與基準數字之後，投入 LLM 開發之前。**

1. 計算實際事件數（含事件去重、扣除名單重疊後的有效獨立事件數）
2. 估計候選在時間上的相關性
3. 分別計算 B+ vs B、D vs B+ 在 α=0.05、power=0.8 下的 MDE
4. 將 MDE 寫入報告與簡報

### 14.6.3 預先註冊

撰寫預先註冊文件：H1–H10、主要指標、決策規則、資料切分、特徵清單。**Git tag 凍結，日期為證。** 之後才碰驗證期資料。

最終報告附上該 commit hash 與日期。

成本合計約 2 人天。

| 檢定 | 門檻 |

# 15. 產品與使用者介面（P0）

## 15.1 產品定位

> 把散戶每天盤後要花兩小時做的功課，壓縮到五分鐘，而且每個結論都能點開看到來源。

系統做的是**縮減、佐證、追蹤**，不是預測，也不是建議。

**UI 中不得出現：** 買進、賣出、目標價、建議部位、勝率預測。
**UI 中必須出現：** 入選原因、原始資料連結、風險標記、後續表現追蹤。

## 15.2 三個畫面（範圍卡死）

### 畫面一：今日候選清單
A 級與 B 級名單，含最終分數、第一輪排名、族群乘數、觸發訊號摘要、風險標記。允許顯示「今日無符合條件之候選」。

### 畫面二：證據卡

- 兩輪分數拆解（第一輪各面向百分位 → 族群乘數 → 最終）
- 族群乘數的四項貢獻拆解
- 觸發的訊號與具體數值
- 當日消息原文連結與 LLM ① 抽取欄位
- 風險標記
- **迷你 K 線 ＋ 法人買賣超柱狀 ＋ 消息事件標記疊在同一條時間軸**
- LLM ② 生成的白話說明（或模板 fallback）

### 畫面三：回放模式 ＋ 成績單

**回放（本系統最強的展示功能）：** 輸入任一歷史日期，系統重建當晚 21:30 的完整畫面。再按一鍵揭曉後續 10 日結果。

此功能**只有在 point-in-time 做對的情況下才做得出來**，把最痛苦、最看不見的工程直接變成可視化賣點。後端即為回測引擎，邊際成本主要在前端。

**成績單：** 過去 N 天所有候選的 5／10／20 日表現，自動更新，**包含失敗案例**。

### 畫面四（P1，可砍）：族群概覽
當日各族群的乘數、啟動天數、成分股分布。回應「是否漏看其他族群」。

### 15.3.2 輸出約束（寫入 prompt）

- 只能使用輸入中出現的數字
- 不得補充輸入中沒有的資訊
- 不得使用買進、賣出、目標價、建議等字眼
- 不得推測未來走勢
- 2–4 句繁體中文
- 溫度 0

### 15.3.3 數字一致性自動檢查

```python
def verify(text: str, record: dict) -> bool:
    nums_out = extract_numbers(text)
    nums_in  = flatten_numbers(record)
    return all(n in nums_in for n in nums_out)
```

流程：生成 → 檢查 → 未過重試一次 → 再未過退回模板。**使用者永遠看不到未通過檢查的文字。** 通過率須記錄並寫入報告（AC-18 敘述品質）。

### 15.3.4 模板 fallback 必須先寫

> 光環（3234）今日入選：成交量為 20 日均量 3.2 倍、收盤創 60 日新高、投信連續買超 4 日。所屬 CPO 族群啟動第 4 日，族群乘數 1.24。當日消息：取得 12 億元訂單。

**先有模板，LLM ② 是加分項而非必需品。** 如此 API 中斷、預算用盡或十二月出狀況時，系統仍可輸出。

## 22.2 必答題與標準答案

**Q：能賺錢嗎？報酬率多少？**
不閃躲，直接給數字，連壞的一起給。定位是把盤後功課從兩小時壓到五分鐘，不是保證獲利。

**Q：跟現有看盤軟體有什麼不一樣？**
三點：讀消息原文而非只看技術指標；每檔可點開看到理由與原始連結；**自動公布過去每一次的成績，包括失敗的**。第三點要講得用力。

**Q：為什麼要用 AI，寫規則不行嗎？**
價量籌碼確實用規則。AI 只做規則做不到的三件事：把消息文字轉為可計算欄位、判斷公司屬於哪個題材（官方產業別分不出 CPO 這種主題）、把結果講成人話。前兩項都有人工標註驗證正確率。

**Q：準不準？**
分三個數字講，順序不能亂（對應 §14.1.1）：

1. 全市場隨機挑，成功率是 5%（這是我們標籤的定義）
2. 先用規則篩掉不合格的，剩下這批的成功率是 **Z%**（`base_scored`）——這是**規則篩選**的貢獻
3. 我們的模型從這批裡挑十檔，成功率是 **X%**——超出 Z% 的部分才是**排序模型**的貢獻

**不要只講「X% vs 5%」**，那會把規則篩選的功勞算到模型頭上，被追問時會站不住。願意主動拆解這三層，反而是最能展現方法論嚴謹度的回答。

另外附上白話版：「A 級候選裡有 W% 在 20 個交易日內漲超過 30%」（DEF-SURGE，§10.2）。價值在把 1,800 檔縮到 10 檔。

**Q：照名單買賠錢怎麼辦？**
這是候選清單不是投資建議，系統不給買賣訊號也不給目標價。（背到反射）

**Q：AI 會不會亂編？**
會，所以我們有自動檢查：生成的文字裡每個數字都必須出現在輸入資料中，不通過就退回模板。通過率 X%。

**Q：誰會用？會有人付錢？**
每天自己做盤後功課的散戶。給成本數字而非願景。

**Q：這樣算不算投顧？會不會違法？**
證券投資信託及顧問法第 4 條的要件是「取得報酬」加上「對特定證券提供分析意見或推介建議」。我們的系統確實會對個股產生結論，所以關鍵在第一項——本專題不收費、不接受任何對價，屬校內研究與展示。我們也明確規定，未來若要收費，必須先取得正式法律意見。**（重點：不要回答「我們沒寫建議兩個字」，那不是法律要件。）**

**Q：資料合法嗎？**
證交所、櫃買中心、公開資訊觀測站的公開資料，加上自行擷取的公開新聞，無付費授權或會員限定來源。

# 25. 最終專案定位

> 一套每日盤後自動執行的台股異常訊號偵測與佐證系統。第一輪以量化訊號與 LLM 消息抽取辨認個股異常，第二輪以族群動能重新排序，捕捉台股飆股「龍頭先動、族群擴散」的典型型態。回測與前瞻追蹤驗證其是否真的具有增益。

核心成果不是「保證找出飆股」，而是一套**可執行、可解釋、可回測、可重現、可比較、可誠實驗證**，且**任一歷史日期皆可完整重播**的台股多訊號候選偵測平台。

# 26. 設計決策紀錄

記錄開發過程中評估後未採用的方案，避免重複討論。

| 提案 | 決定 | 理由 |
|---|---|---|
| 拿掉融合引擎，由 LLM 直接給分 | **否決** | 引擎本身僅 3–4 人天；貴的是資料層與回測，那兩項誰算分數都要做。拿掉則回放、可重現、消融、參數掃描全失效 |
| LLM 直接給族群或消息乘數 | **否決** | 評分無標準答案，無法驗證；回放模式失效（重跑答案不同）；污染從局部變全域；「事後寫理由」是合理化不是計算過程 |
| 族群飆股占比壓抑（占比 > 30–40% 則壓抑） | **否決** | ①用未來報酬判定會洩漏；②用「已入選名單」判定會循環震盪；③用漲幅門檻判定則只是 `theme_breadth` 的粗糙二值化。且占比高在啟動初期與末期意義相反 |
| 冷卻期（強制壓低連續入選者） | **否決** | `theme_ignition` 倒 U 已處理衰竭，不需疊第二層硬規則 |
| 只用上線後資料、不做歷史回測 | **否決** | ①上線即需 120 個交易日歷史才算得出特徵；②抓半年與抓四年程式碼相同；③11/20 起算僅約 30 個獨立事件、期望正樣本 1–2 個；④十個猜的參數永遠無法驗證；⑤回放 demo 不存在 |
| 讓 LLM 知道未來以提升訓練資料品質 | **否決** | 標籤 y 本來就來自未來且已 100% 準確，不需 LLM；污染只會影響特徵 X。模型會學成「讀 LLM 的記憶」而非「讀消息」，上線即歸零 |
| 補漲效應進 Gate（族群強則買落後股） | **否決** | 族群內落後股多半有原因；改列研究問題。族群乘數改為族群內統一，落後股自然留在後面 |
| 財經新聞歷史回補至 2019 | **否決** | 無可信 `published_at`，覆蓋率不明；改為 2026-08-01 起自爬 |
| 族群消息特徵（同業公告溢出） | **否決** | 依賴新聞歷史，不可回測 |
| 法說會簡報 PDF 內容抽取 | **否決** | 覆蓋率偏向大型股、頻率為季度以上、PDF 解析成本高。只取召開公告 |
| K 線圖截圖交多模態模型判讀 | **否決** | 不可重現；圖上座標軸與日期直接洩漏未來資訊；可用數字精確表達者不應轉為圖片 |
| 型態辨識（頭肩底、旗形） | **否決** | 無標準定義，學術上無穩健證據 |
| GBDT 作為產品引擎 | **否決** | 可解釋性與產品定位衝突；正樣本率 5% 下過擬合風險高；無時間做巢狀驗證。改為跑一次當上限參考 |
| 拆成「潛力股／飆股」兩套標籤兩個產品 | **否決** | 樣本數再切半，兩邊都失去統計效力 |
| 換題為 agent 交易模擬器 | **保留為後手** | 9/15 前決定，見第 21 章 |
| 以 T+1 可成交作為 Gate 條件 | **否決（v2.6）** | T 日 21:30 無從得知 T+1 開盤與最低價，屬未來資料洩漏 |
| 將 T+1 鎖死者自樣本中刪除 | **否決（v2.6）** | 系統當時確實選中，刪除即選擇偏誤；改記 `no-fill` 並分層報告 |
| 以全池 5% 作為 Precision@10 之 lift 基準 | **否決（v2.6）** | 評分集合為 Gate 通過者，其正例率高於 5%，將高估排序模型價值 |
| 以 LLM `materiality` 驅動風險否決 | **否決（v2.6）** | 不可逆決策須可稽核；改由客觀抽取欄位之程式規則判定 |
| 以「不使用建議二字」作為法律防線 | **否決（v2.6）** | 投顧法第 4 條之要件為取得報酬＋對特定證券提供分析意見，與用詞無關 |

# 附錄 B：異常情境與降級行為

**核心原則：寧可降級輸出並明確標註，不可延後決策時間，也不可靜默失敗。**

| 情境 | 系統行為 |
|---|---|
| 官方價量資料源全面故障 | 當日流程中止，推播 ERROR，隔日回補；**不輸出候選清單** |
| 部分股票資料缺漏 | 該股當日不參與評分，記入品質報告，清單頁標註涵蓋率 |
| 三大法人或融資券延遲公布 | 21:25 前持續重試；仍缺則籌碼欄位標記缺值，權重重新歸一化，標註「本日未含籌碼面」 |
| **新聞爬蟲故障** | 消息欄位標記缺值（`has_news=0`），量化流程照常；記錄斷線區間，該區間不計入 C／D 版有效樣本 |
| LLM ① 故障或超出預算 | 當日降級為 B+ 版輸出，標註「本日未含消息面分析」，發 ERROR；已快取結果仍可使用 |
| LLM ① 輸出連續驗證失敗 | 該則消息標記抽取失敗、不進入特徵寬表；當日失敗率 > 20% 發 ERROR |
| LLM ② 數字檢查未通過 | 重試一次；再未過退回模板。通過率記入報告 |
| 主題成分表載入失敗 | 所有族群乘數設為 1.0，等同 B 版，標註「本日未含族群面」 |
| 族群成分股不足 5 檔 | 該族群乘數設為 1.0，輸出標註 |
| 單一量化訊號模組錯誤 | 該訊號回傳缺值、記 ERROR，其餘照常，百分位轉換於有效面向間重新歸一化 |
| 當日無任何股票通過 Gate | 輸出「今日無符合條件之候選」，此為合法輸出 |
| A 級名單換手率連續 5 日 < 20% | 品質報告發 WARN 並標註；不自動變更輸出 |
| 同日重複執行 | 冪等覆蓋，不重複推播 |
| 排程未觸發 | 隔日偵測缺漏並補跑，標註 `late_run=true`，**不計入嚴格 PIT 樣本** |

# 附錄 D：名詞對照表

| 術語 | 白話說明 |
|---|---|
| DEF-RANK | 未來 10 日超額報酬排進當日池前 5% 就算成功，成功率固定 5%、跨期可比 |
| 兩輪評分 | 第一輪看個股本身，第二輪乘上族群強度重新排 |
| 族群乘數 | 整個族群是不是在動，用一個 0.85–1.35 的倍數統一套用 |
| 族群啟動天數 | 這個族群開始強勢幾天了，剛啟動最好、太久就衰竭 |
| 倒 U 形 | 太早不確定、太晚沒動能，中間才是甜蜜區 |
| 事件去重 | 同一波行情只算一次，避免同一檔灌水成十筆 |
| Point-in-time / PIT | 每筆資料記「何時才可被使用」，回測只准用當時已公開的 |
| 準 PIT vs 嚴格 PIT | 第三方資料無法還原當時原始版本 vs 自建擷取，時間戳為實際取得時間 |
| `first_seen_at` | 我們自己抓到這則新聞的時間，唯一可信的 PIT 依據 |
| Leakage | 偷用未來資料，讓成績虛高 |
| 存活偏誤 | 只看現在還在的股票、漏掉已下市的，成績虛高 |
| Precision@10 | 每天前 10 檔裡有幾檔真的成功（隨機基準 5%） |
| Lift | 比隨機選股好幾倍 |
| MDE | 以現有樣本數，效果要多大才驗得出來；用來區分「沒效果」與「驗不出來」 |
| 消融比較 | 逐一拔掉某面向，看它到底有沒有貢獻 |
| gold set | 人工標註的正確答案集，用來檢驗 LLM 抽得對不對 |
| Cohen's κ | 兩個標註者一致程度的統計量，扣除碰巧一致的部分 |
| 抽取 vs 評分 | 抽取有標準答案（原文寫 12 億就是 12 億），評分沒有 |
| Gate | 必要條件：不通過就不論分數多高都不入選 |
| 風險否決 | 出現重大負面消息時直接排除，不用扣分處理 |
| 百分位轉換 | 把分數換成「當日池內排第幾趴」，解決尺度不一與跨期不可比 |
| 參數高原 | 好參數的鄰居也應該好；只有單點好就是雜訊 |
| `technical_score_raw` | 沒轉成百分位的原始分數，用來判斷「今天到底夠不夠強」，百分位只能比高下不能比強弱 |
| Gate 貢獻 vs 排序貢獻 | 篩掉不合格的算一份功勞，從合格者中挑十檔算另一份，兩份要分開講 |
| no-fill | 隔天開盤鎖漲停買不到；系統當時確實選中了，所以樣本要留著，只是記成沒買到 |
| `base_scored` | 算 lift 要用「有被評分的那群股票」的實際成功率當基準，不是全市場的 5% |
| leave-one-out | 算族群分數時把自己排除，避免用自己的漲幅替自己加分 |
| gap（切分間隔） | 兩個切分之間空 10 個交易日，避免前一段的標籤偷看到後一段 |
| 回顧式分類 | 用今天才有的主題名單去套過去，不能宣稱是當時可得的資訊 |
| fallback 族群 | 沒被 LLM 歸到任何題材的股票，改用官方產業別當族群，確保每檔都有族群分數 |
| `entry_path` | 這檔是靠分數進來的，還是靠「當天有消息」被撿進來的 |
| 來源分離 | 公告和新聞的可用年份不同，不能混在同一個模型裡訓練 |
| 主題成分表 | 哪些股票屬於 CPO、重電這類題材；官方產業別分不出來 |
| 延伸度 | 這檔已經漲幾天、離均線多遠，判斷是剛啟動還是已追高 |
| 名單換手率 | 今天前十名跟昨天差多少，太低代表名單僵化 |
| 有效樣本數 | 名目 50 筆但都是同幾檔的連續日，實際獨立事件遠少於 50 |
| 記憶污染 | LLM 記得歷史上發生過什麼，會讓回測成績虛高 |
