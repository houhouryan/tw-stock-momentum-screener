## 1. 關鍵結構性發現

> 本節為 A0-01 最重要的產出，直接影響架構決策。

### 1.1 官方價量資料無法有效自建歷史

| 端點類型 | 涵蓋範圍 | 歷史查詢 |
|---|---|---|
| `openapi.twse.com.tw/v1/...` | 全市場 | **無**，僅最新一日 |
| `www.twse.com.tw/exchangeReport/STOCK_DAY` | **單檔單月** | 有 |

自建 2019–2026 全市場歷史價量約需 **1,800 檔 × 84 月 ≈ 151,200 次請求**，
以 5 秒間隔計約 **8.7 天**連續執行，中斷需重跑。

**決策：** 歷史價量以第三方回補並標記為**準 PIT**；自專案啟動日起每日擷取官方全市場快照，該部分為**嚴格 PIT**。此分級沿用 SDD 既有的 PIT 分級設計，不需修改架構。

### 1.2 籌碼資料則可以自建歷史

`www.twse.com.tw/fund/T86` 為**一次一天、全市場**，
1,700 個交易日約 **1,700 次請求**，5 秒間隔約 **2.4 小時**完成。

**決策：** 三大法人歷史**自建**，不依賴第三方。這讓 C01／C02 兩個 P0 訊號建立在官方資料上，是與價量的重大差異。

### 1.3 每日快照具時效性

官方快照僅提供最新一日，**未擷取的日期無法回溯取得嚴格 PIT 版本**。每日快照排程應盡早上線，延後一天即永久少一天資料。

### 1.4 普通股僅佔全部有價證券的 4.6%

行情端點回傳的是**所有有價證券**，其中九成五以上為權證、ETF 等非普通股。
若不先過濾，Universe 會嚴重錯誤。

| 市場 | 全部證券 | 普通股（CFICode `ES` 開頭） | 佔比 |
|---|---|---|---|
| 上市 | 32,053 | **1,083** | 3.4% |
| 上櫃 | 10,530 | **890** | 8.5% |
| 合計 | 42,583 | **1,973** | 4.6% |

**決策：Universe 第一道過濾規則為「CFICode 以 `ES` 開頭」**，來源為 ISIN 證券屬性表（見 2.3）。
1,973 檔與 SDD 所述「約 1,800 檔」相符，互為印證。

### 1.5 所有官方端點都混入非普通股

今日探測的每一個端點都是「全部有價證券」，無一例外：

| 端點 | 當日筆數 | 其中普通股 |
|---|---|---|
| 上市行情 | 1,373 | 約 1,083 |
| 上櫃行情 | 10,218 | 約 890 |
| ISIN 上市 | 32,053 | 1,083 |
| ISIN 上櫃 | 10,530 | 890 |
| T86 三大法人 | 14,659 | 約 1,973 |

**通則：任何官方資料進入計算前，一律先以 CFICode 過濾。**
此規則須寫入 B0-04 之 SourceAdapter `normalize()` 或後續清洗層，
不得依賴各訊號模組各自處理。

#### ⚠️ 上櫃行情端點的欄位明顯優於上市

| 欄位 | 上櫃（TPEx） | 上市（TWSE） |
|---|---|---|
| 開高低收量 | ✓ | ✓ |
| **`NextLimitUp` 明日漲停價** | ✓ | **✗** |
| **`NextLimitDown` 明日跌停價** | ✓ | **✗** |
| **`Capitals` 股本** | ✓ | **✗** |
| `Average` 均價 | ✓ | ✗ |
| `LatestBidPrice` / `LatesAskPrice` | ✓ | ✗ |

**`NextLimitUp` 的價值：** 它是 T 日收盤後公布的**明日**漲停價，
故 T 日 21:30 決策時即可合法取得，**無須自行以 ×1.1 推算**
（自行推算在減資、面額變更、初上市首五日無漲跌幅等情境會算錯）。

**這使 A0-05 在上櫃已解決，上市尚無著落**，須另尋端點，
否則 SIG-P05 將面臨「兩市場規則不一致」的設計問題。

| 項目 | 內容 |
|---|---|

| **單位** | **股**（`hints` 欄位明載「單位：股」） |

**19 個欄位的關鍵結構——外資與自營商各分兩種：**

| 類別 | 子欄位 |
|---|---|
| 外資 | 外陸資（**不含**外資自營商）／外資自營商 |
| 投信 | 單一欄位 |
| 自營商 | 自行買賣／**避險** |

**決策：SIG-C01／C02 採用「外陸資（不含外資自營商）」與「投信」兩欄。**

理由：
1. **外資自營商**多為造市與避險部位，不代表方向性看多。
2. **自營商避險**部位是權證發行商的對沖交易，與看法無關——
   前述每日 14,659 筆中大量權證正是這些避險部位的來源。
3. 使用「三大法人合計」會讓上述雜訊混入，且外資賣、投信買時互相抵銷，
   反而遮蔽投信認養這個對中小型股最有意義的訊號。

此決策須寫入 signals README，並為口試必答題。

## 2.7 通用解析注意事項（跨來源共通，B0-04 必讀）

今日探測中發現的資料格式陷阱，**每一項都會造成靜默錯誤**（程式不報錯但結果錯）。

| # | 陷阱 | 實例 | 處理方式 |
|---|---|---|---|
| 1 | **日期為民國年** | `"Date": "1150731"` = 2026-07-31 | 前 3 碼民國年 +1911；不可直接當西元解析 |
| 2 | **數字含千分位逗號** | `"162,286,825"` | 轉數值前須移除逗號，否則 `int()` 會拋錯或誤判 |
| 3 | **缺值為空字串** | BWIBBU 台泥 `"PEratio": ""` | 不是 `null` 也不是 `0`；轉型前須判空 |
| 4 | **Big5 編碼** | ISIN 頁面 | 需 `encoding='big5'`，否則中文全亂碼 |
| 5 | **HTML 混入標題列** | ISIN 表分類標題 | 以 `<td>` 數量過濾（標題 1 個、資料 7 個） |
| 6 | **回應結構不一致** | OpenAPI 回 list；官網回 dict 含 `data` | Adapter 須各自處理，不可共用解析邏輯 |
| 7 | **HTTP 200 不代表成功** | `openapi/v1/fund/T86` 回 200 但內容為 HTML | 須驗證 Content-Type 與可解析性 |
| 8 | **全端點混入非普通股** | 見 1.5 | 一律先以 CFICode 過濾 |

**這八項須納入 A1-07 資料字典與 B0-04 Adapter 的驗收條件。**
