## 3. R04 缺陷修正鏈與最終裁定

### 3.1 原始 R04 → FIX1

原始版本雖能透過 property 讀取公開名稱，真正的 Pydantic field 卻是 `request_json_snapshot`、`evidence_snapshot`、`rows_snapshot` 等 private storage 名稱，造成：

- `model_fields`、JSON schema 與 constructor signature 暴露錯誤名稱；
- 標準 `model_dump()`／`model_dump_json()` 無法形成可靠的公開 round-trip；
- 使用者可繞過預期公開契約直接送入 snapshot 欄位；
- insertion order 會影響 equality 或 dump；
- 部分 scalar 會被 Pydantic 靜默 coercion。

FIX1 已把 JSON 資料放回真正的公開 field，並以建構時 canonical copy、讀取時 deep copy、標準 serializer 讀取內部已驗證值的方式處理。審查者確認五個 model 的 `model_fields`、schema、signature、Python round-trip 與 JSON round-trip 全部一致，舊 snapshot 名稱全部被 `extra="forbid"` 拒絕。

### 3.2 FIX1 → FIX2

FIX1 的 `_canonical_rows()` 使用 `collections.abc.Sequence` 判斷最外層 rows。這比已裁定契約「只接受 built-in list／tuple」寬，會讓自訂 Sequence、list subclass 與 tuple subclass 通過。

FIX2 現在使用精確 identity boundary：

```python
if type(value) is list:
    ...
elif type(value) is tuple:
    ...
else:
    raise ValueError(...)
```

production module 已移除 `Mapping`／`Sequence` import 與無效 dummy assignment；測試以完全合法的 dict rows 證明拒絕原因確實是 outer container 型別，而不是 row 內容。

### 3.3 最終 findings

本次沒有新的 blocking finding，也沒有要求工程師回頭修改 frozen 報告。

需持續遵守的報告品質規則只有：

### 8.1 共通規則

五個 model 全部必須：

- `frozen=True`、`extra="forbid"`。
- 真正的 Pydantic public fields 必須與下列欄位表逐字一致；不得重犯 private snapshot＋property 問題。
- import 無副作用，不讀檔、不連網、不開 DB、不取目前時間。

- tuple 型 collection 建構時可接受 built-in list／tuple，以支援正常 Python 與 JSON round-trip；不得接受 generator、自訂 Sequence、list subclass 或 tuple subclass。

- JSON object key 做 canonical 排序；讀取公開 evidence 每次回傳 fresh deep copy；Python／JSON round-trip 都要保持 equality。
- 不使用 `Any` 穿越 production contract，不接受 silent scalar coercion。

| `results` | tuple of `SignalResult` | 每個 active signal 的結果 |

Invariant：

- `active_signal_ids` 不得重複。
- `results[*].signal_id` 不得重複。
- `results` 的 signal ID 順序與 `active_signal_ids` 必須完全相同；缺少、多出或錯序都拒絕。
- unavailable 的 active signal 仍要有 `SignalResult`，不得因不可用而從 results 消失。

### 8.6 `LabelFrame`

R05 只提供最小跨組列契約，不放未來路徑摘要或 label 計算細節：

| 欄位 | 型別 | 規則 |
|---|---|---|
| `label_version` | strict non-empty `str` | Label 契約版本 |
| `as_of_date` | `date` | 候選／特徵日期 T，不得 default today |
| `security_id` | strict non-empty `str` | 永久 security ID |
| `label_rank` | strict `int` 0／1或 null | DEF-RANK-v1 |
| `label_continuation` | strict `int` 0／1或 null | DEF-CONTINUATION-v1 |
| `label_surge` | strict `int` 0／1或 null | DEF-SURGE-v1 |
| `label_status` | `LabelStatus` | pending／matured／unavailable |
| `nan_reason` | strict non-empty `str | None` | 缺值理由；預設 null |
| `matured_at` | `AwareDatetime | None` | 成熟時間；aware 時轉 Asia/Taipei，預設 null，不取現在時間 |

Invariant：

- 三個 label 只接受真正的 integer `0`／`1` 或 null；拒絕 bool、float、str 與其他整數。
- `label_status=pending` 時三個 label 必須全部為 null，`matured_at` 必須為 null；不得用 0 代表尚未成熟。
- `label_status=unavailable` 時三個 label 必須全部為 null；不得用 0 代表不可用。
- `label_status=matured` 不強迫三個 label 全部非 null：SDD 允許資料缺漏與 continuation buffer 形成 NaN；缺值時以 `nan_reason` 說明。
- `matured_at` 若提供必須 aware；naive 一律拒絕並測試時區正規化。
