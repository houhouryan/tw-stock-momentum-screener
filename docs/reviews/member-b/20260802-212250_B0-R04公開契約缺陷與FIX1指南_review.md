## 4. Findings

### R04-F01｜Blocker｜Pydantic 公開欄位不是核准欄位

核准的精確 field sets 是：

| Model | 核准欄位 |
|---|---|
| FetchRequest | `source_id`、`dataset_id`、`request_json` |
| RawArtifact | `artifact_id`、`request`、`http_status`、`retrieved_at`、`content_hash`、`mime_type`、`raw_uri`、`license_snapshot_id`、`source_run_id`、`retry_count` |
| NormalizationIssue | `code`、`message`、`row_index`、`evidence` |
| NormalizedBatch | `artifact_id`、`dataset_id`、`rows`、`row_count`、`normalization_errors` |
| SourceHealth | `source_id`、`dataset_id`、`checked_at`、`healthy`、`message`、`evidence` |

實測卻是：

```text
FetchRequest:
  ('source_id', 'dataset_id', 'request_json_snapshot')
NormalizationIssue:
  ('code', 'message', 'row_index', 'evidence_snapshot')
NormalizedBatch:
  ('artifact_id', 'dataset_id', 'rows_snapshot', 'row_count', 'normalization_errors')
SourceHealth:
  ('source_id', 'dataset_id', 'checked_at', 'healthy', 'message', 'evidence_snapshot')
```

`model_json_schema()` 的 properties 與 `inspect.signature()` 也暴露相同的 snapshot 名稱。例如：

```text
FetchRequest(
  *,
  source_id: str,
  dataset_id: str,
  request_json_snapshot: str = '{}'
)
```

**影響：**

- Adapter、IDE、型別工具、JSON schema consumer 看到錯誤 API。
- `request_json` 等 property 不等於 Pydantic field；「欄位數剛好相同」不能滿足「欄位名稱與型別精確」。
- `exclude=True` 只控制 dump，不會把欄位變成 private，也不會阻止 constructor 接受它。

**裁定：Blocker。**

### R04-F02｜Blocker｜snapshot 是 secret／JSON 驗證繞過入口，標準 serializer 丟資料

直接傳內部欄位可成功：

```python
FetchRequest(
    source_id="s",
    dataset_id="d",
    request_json_snapshot='{"api_token":"SHOULD_REJECT"}',
)
```

審查者實測：

```text
snapshot_secret_bypass={'api_token': 'SHOULD_REJECT'}
issue_snapshot_secret_bypass={'password': 'SHOULD_REJECT'}
health_snapshot_secret_bypass={'private_key': 'SHOULD_REJECT'}
rows_snapshot_secret_bypass=[{'api_token': 'SHOULD_REJECT'}]
```

這四條都應在建構時拒絕，卻完全繞過 `_reject_secret_keys`。同一路徑也能傳入 malformed JSON 字串；實測 model 可成功建構，直到讀取 property 才拋 `JSONDecodeError`。

另外，工程師只覆寫 `model_dump()`；Pydantic 標準 `model_dump_json()` 直接使用 serializer，因此：

```text
request.model_dump(mode="json")
  -> {"source_id":"s","dataset_id":"d","request_json":{...}}

request.model_dump_json()
  -> {"source_id":"s","dataset_id":"d"}
```

NormalizationIssue／NormalizedBatch／SourceHealth 也會分別遺失 evidence／rows／evidence。

**影響：**

- 既定 secret boundary 可由公開 constructor 繞過。
- API、檔案或 queue 若使用 Pydantic 標準 JSON serializer，必要資料會靜默消失。
- `model_dump_json() -> model_validate_json()` 無法保留原物件語意。

**裁定：Blocker。**

### R04-F03｜Major｜canonical JSON 與 tuple 契約未成立

#### 4.3.1 Key order 影響 equality

```python
left = FetchRequest(request_json={"b": 2, "a": 1}, ...)
right = FetchRequest(request_json={"a": 1, "b": 2}, ...)
```

審查者實測 `left == right` 為 **False**。原因是 model equality 比較私有 snapshot 字串，而 `json.dumps()` 沒有 canonical sort。

這直接違反 §9.2「key order 不得影響 model equality 或 canonical dump 語意」。

#### 4.3.2 巢狀 tuple 被接受

審查者輸入：

```python
{"items": (1, 2)}
```

實際得到：

```text
{'items': [1, 2]}
```

現有 `UNSAFE_JSON_VALUES` 列了 bytes、set、object、非字串 key 與非有限數，卻漏掉檢查報告明列的 tuple。`json.dumps()` 會把 tuple 靜默當 array，所以現有 helper 沒有阻擋。

#### 4.3.3 rows runtime type 錯誤

`NormalizedBatch.rows` 的 annotation 與 runtime 都是 `list[dict[...]]`；實測：

```text
rows_runtime_type=list
```

核准契約明寫 outer container 為 tuple。深層防污染可以用 fresh copy 達成，但不能因此把公開型別改成 list。

**裁定：Major，與 F01／F02 一起阻塞 R04。**

### 6.2 移除錯誤的 snapshot 公開面

從 Pydantic fields 完整移除：

```text
request_json_snapshot
evidence_snapshot
rows_snapshot
```

同時移除為它們存在的四個 custom `__init__(**data)` 與四個 custom `model_dump(**kwargs)`。不得改用別名、computed field、serializer alias 或另一個可由 constructor 傳入的 hidden Pydantic field 重新包裝同一問題。

真實 fields 必須直接命名：

```python
request_json: dict[str, JsonValue]
evidence: dict[str, JsonValue]
rows: tuple[dict[str, JsonValue], ...]
```

空 object 使用 `default_factory=dict`；空 rows 使用 tuple default。這些名稱必須同時出現在 model fields、signature、schema、dump 與 JSON dump。

### 6.3 建構時精確 JSON 驗證與 canonical copy

以 `mode="before"` field validator 或等價方式，遞迴建立新的 canonical JSON 結構。輸入規則必須精確：

- 允許：null、str、bool、int、finite float、list、dict。
- bool 必須在 int 前判斷，避免 Python subclass 關係混淆。
- object 只接受真正的 dict；key 只接受 str。
- JSON array 只接受 list；巢狀 tuple 一律拒絕，不得交給 `json.dumps()` 靜默轉換。
- 拒絕 bytes、set、tuple、任意 object、custom mapping、非字串 key、NaN、Infinity、-Infinity。
- request／evidence 繼續使用既有 secret fragments 與 key normalization。
- 每層 object 依 key 排序後建立新 dict；array 保留元素順序。
- 不保留呼叫端原始 dict／list reference。

可使用 `object`、`cast`、遞迴 union 與既有 Pydantic `JsonValue`；production `acquisition.py` 不得再 import 或使用 `Any`。

### 6.4 讀取時 fresh copy，但保留真實 field

推薦且已由審查者驗證可行的策略：

1. model 內保存經 validator 建立的 canonical dict／tuple。
2. 共用 base 以 `ClassVar[frozenset[str]]` 列出需防污染的欄位。
3. 在公開 attribute 讀取時，以 `copy.deepcopy` 回傳 fresh copy。
4. Pydantic serializer 仍直接看到真正 fields，所以不需覆寫 `model_dump`。

必須達成的結果比實作技巧重要；若採其他方式，也必須同時滿足：

- `model_fields`／schema／signature 只有核准名稱。
- `model_dump()`、`model_dump(mode="json")`、`model_dump_json()` 全部保留資料。
- public root／nested mutation 不污染。
- 沒有可注入的 storage field。
- 無 dependency、無 custom object 穿越 public contract。

若工程師認為只能用 private/computed/snapshot field 才能完成，停止，不得再自行改契約；審查者原型已證明正常 public field 方案可行。

### 6.5 rows 的精確語意

- Public annotation 與 runtime value 都是 `tuple[dict[str, JsonValue], ...]`。
- JSON round-trip 會把 outer JSON array 解成 list；validator 必須接受 outer list 並正規化為 tuple。
- **只有 outer rows container** 可做這個 list→tuple 正規化。
- 每一個 row 必須是 dict。
- row 內的 JSON arrays 是 list；row 內 tuple 必須拒絕。
- public `batch.rows` 每次取得 fresh tuple／nested copy；修改巢狀 dict 或 list 不得污染下次讀取。
- `row_count` 必須依 canonical stored rows 驗證。

### 6.6 Equality、schema 與標準 round-trip

對所有帶 JSON 的 models 必須成立：

```text
相同語意、不同 object key insertion order
→ model equality 相同
→ model_dump(mode="json") 相同
→ model_dump_json() serialized text 相同
```

並且：

```python
type(model).model_validate(model.model_dump(mode="json")) == model
type(model).model_validate_json(model.model_dump_json()) == model
```

Schema properties 必須精確等於 §4 F01 的 field sets，不能有 snapshot 名稱。

### 6.7 Scalar strictness 裁定

工程師在工作報告 010 V-1 請審查者裁示是否一致化。此處作技術裁定，不需產品決策：

- `http_status` 保留 strict。
- `retry_count`、`row_index`、`row_count` 也必須拒絕 str、float 與 bool 的靜默轉換。
- `healthy` 必須只接受 bool，拒絕 `"true"`、`"false"`、0、1。
- UUID 與 aware datetime 必須保留標準 JSON round-trip 能力，不要求 strict Python-instance-only。
- non-empty string 必須拒絕非 str 的 coercion、空字串與純空白。

理由是本模組是跨 Adapter 的資料契約；若 boundary 靜默轉型，呼叫端無法區分來源實際送入的型別。這不新增欄位或產品語意，只讓已宣告的 integer／bool／str 型別可被測試守住。

### 6.8 保持不變

- 時區、license、retry、normalize 解耦。

### 7.1 真實公開欄位

- 每個舊 snapshot 名稱作 constructor input 都因 extra forbid 被拒絕。
- snapshot 內含 secret 或 malformed JSON 也不得成為繞過。

### 7.2 標準 serialization

對 FetchRequest、RawArtifact、NormalizationIssue、NormalizedBatch、SourceHealth：

- `model_dump()` 有正確 public JSON key。
- `model_dump(mode="json")` 可 `json.dumps(allow_nan=False)`。
