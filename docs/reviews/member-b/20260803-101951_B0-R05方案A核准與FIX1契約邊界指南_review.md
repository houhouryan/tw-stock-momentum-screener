## 5. Findings 與裁定

### B0-R05-F01｜Blocking／已核准方案 A｜R04 export 測試把快照當永久全集

**證據：**`tests/unit/domain/test_acquisition.py::test_domain_all_preserves_existing_and_adds_exactly_five` 目前包含：

```python
assert existing <= actual
assert actual - existing == added
assert len(domain.__all__) == len(existing) + len(added) == 21
```

R05 合法新增五個 export 後，後兩行必然失敗。審查者獨立重跑單一測試與完整 gate，結果分別為 1 failed，以及 504 passed／1 failed。

**根因：**R04 測試應保護「R04 以前的名稱不能消失、acquisition 五個名稱必須存在」，不應聲稱未來永遠不能新增其他 domain export。

**專案經理裁定：**方案 A 已核准；BLOCKED 解除。

**修改方向：**依 §6.1 同時修正 R04 與 R05 export tests，改成明確集合的子集斷言＋`__all__` 無重複，不再斷言固定總數或 `actual - baseline` 恰等於當輪 additions。

### B0-R05-F02｜Major｜collection 內的純空白 security ID 被接受

**證據：**審查者在未修改程式的獨立探針執行：

```python
UniverseResult(
    included_security_ids=["   "],
    exclusions=[],
    universe_version="u",
    eligibility_filter_version="e",
)
```

目前成功建立，runtime 值為 `('   ',)`。

**根因：**`StrictStr = Annotated[str, Field(min_length=1, strict=True)]` 只拒絕長度 0，不拒絕純空白。單值 fields 另有 `_reject_blank` validator，但 `included_security_ids` 元素沒有；`active_signal_ids` 也沒有直接的元素級空白檢查。

**影響：**Universe 可包含沒有可用識別語意的 security；後續 audit、join 與 A-facing 契約會收到表面合法的空白 ID。

**修改方向：**依 §6.2 對所有 collection identification elements 明確拒絕 `not value.strip()`，保留原字串，不做 silent strip。

### B0-R05-F03｜Major｜Python constructor 靜默 coercion 日期與成熟時間

**證據：**目前以下三種 Python input 都會成功：

```text
SignalFrame.as_of_date = "2026-08-03"              -> date(2026, 8, 3)
SignalFrame.as_of_date = datetime(2026, 8, 3, 0, 0) -> date(2026, 8, 3)
LabelFrame.matured_at  = "2026-08-17T10:30:00Z"    -> aware datetime
```

**根因：**`date` 與 `AwareDatetime` fields 未設定 strict；Pydantic 在 Python mode 自動解析／轉型。

**影響：**違反 §8.1「不接受 silent scalar coercion」，呼叫端無法由 Python type boundary 及早發現傳錯型別。

**可行性證據：**審查者另以 Pydantic 探針確認 `Field(strict=True)` 會拒絕上述 Python inputs，但 `model_validate_json()` 仍可接受標準 ISO JSON 字串，因此不會破壞 JSON round-trip。

**修改方向：**依 §6.3 只在兩個 `as_of_date` 與 `matured_at` fields 加 strict，不啟用整個 model 的 global strict，也不改 `LabelStatus` 等既有語意。

### B0-R05-F04｜Major／測試完整性｜明訂驗收項目沒有直接測到

現有 171 tests 很完整，但下列核准項目缺少直接 regression：

1. 沒有 `inspect.signature(model_cls)` 與 field names 的精確比對。
2. `test_python_round_trip` 實際呼叫 `model_dump(mode="json")`，不是 Python-mode `model_dump()`。
3. outer container 邊界只直接測 `included_security_ids`；沒有逐一保護 `exclusions`、`active_signal_ids`、`results`。
4. 沒有 collection 元素純空白負向測試。
5. 沒有 Python date／datetime string coercion 的負向測試。

**影響：**R04 已經證明「schema／signature／標準 serializer 看起來相近但不是同一契約」會造成真實缺陷；這些要求不能只靠目前實作碰巧正確。

**修改方向：**依 §7 補精確 parameterized tests。不得只修 production 讓當前探針通過，卻不留下 regression。

### 6.2 純空白 collection element

在 `research.py` 為以下 tuple elements 增加 after-validation：

```text
UniverseResult.included_security_ids
SignalFrame.active_signal_ids
```

每一個元素都必須：

- 已是 strict `str`；
- `value != ""`；
- `value.strip()` 不得為空；
- 不自動 strip、不改寫呼叫端原值。

可以建立 private helper 供兩個 validators 重用，也可以各自迭代；不得增加 public export、dependency 或修改 acquisition private helper。

至少加入：

```text
included_security_ids=[""]      -> reject
included_security_ids=["   "]   -> reject
included_security_ids=[1]        -> reject
active_signal_ids=[""]          -> reject
active_signal_ids=["   "]       -> reject
active_signal_ids=[1]            -> reject
```

active signal 的負向案例若會先撞 results mismatch，測試必須確認真正的 validation error 是空白／型別邊界，而不是用另一個 invariant 偶然拒絕。可以分離測 validator，或提供能明確定位的 error message。

### 6.3 Strict date／datetime

只修改下列 declarations：

```python
class SignalFrame(...):
    as_of_date: date = Field(strict=True)

class LabelFrame(...):
    as_of_date: date = Field(strict=True)
    matured_at: AwareDatetime | None = Field(default=None, strict=True)
```

必須成立：

- Python `date` input 通過。
- Python ISO date `str` 拒絕。
- Python midnight／non-midnight `datetime` 作 `as_of_date` 都拒絕。
- Python aware／naive ISO `str` 作 `matured_at` 都拒絕。
- Python aware `datetime` 通過並轉 Asia/Taipei。
- Python naive `datetime` 拒絕。
- `model_dump_json()` → `model_validate_json()` 仍完整 round-trip。

不要把 `model_config` 改成 global strict；那會擴張到 enum 與其他未裁定輸入。
