## 6. Finding R03-F02｜Major｜error context 可在建構後繞過 secret gate

### 6.1 問題

目前 `HotstockError.__init__()` 在建構時確實會驗證並深拷貝原始 context，但之後：

- `error.context` 是公開可變 dict。
- `to_dict()` 直接回傳同一個內部 dict。

審查者執行：

```python
error = HotstockError(
    ErrorCode.DATA_QUALITY,
    "safe",
    {"rows": [1]},
)
error.context["api_token"] = "SECRET"
payload = error.to_dict()
payload["context"]["rows"].append(2)
print(error.to_dict())
```

實際輸出：

```text
{
  'error_code': 'DATA_QUALITY',
  'message': 'safe',
  'context': {'rows': [1, 2], 'api_token': 'SECRET'}
}
```

也就是建構時的 secret 檢查可被建構後 mutation 完全繞過，且對 `to_dict()` 回傳值的巢狀修改會反向污染 exception。這違反「context 不得放 secret」與安全結構化日誌的核心目的。

### 6.2 精確修法

修改 `src/hotstock/domain/errors.py`：

1. 不再把內部 dict 指派給公開 `self.context`。
2. 驗證後把 context 保存為私有、不可由公開介面取得的序列化 snapshot；建議保存為私有 JSON 字串，例如 `_context_json`。
3. 建立唯讀 `context` property；每次存取都從私有 snapshot 產生一份新的深層 dict。
4. `to_dict()` 每次都建立新的 top-level dict，且其中 context 也是新的深層 copy。
5. 呼叫端修改：
   - 原始輸入 dict；
   - `error.context` 的回傳值；
   - 任一次 `to_dict()` 的回傳值；
   
   都不得影響後續的 `error.context` 或 `to_dict()`。
6. `str(error)`、`repr(error)`、`args` 仍不得包含 context。
7. 既有 JSON-safe、NaN／Infinity、secret key、非字串 key 行為不得放寬。

不得用淺拷貝；巢狀 list／dict 也必須隔離。

### 6.3 必加測試

修改 `tests/unit/domain/test_errors.py`，至少新增：

- [ ] 修改 `error.context` 回傳 dict 的根層，不影響下次讀取。
- [ ] 修改 `error.context` 回傳 dict 的巢狀 list／dict，不影響下次讀取。
- [ ] 對 `error.context` 回傳值加入 `api_token`，後續 `to_dict()` 不得出現。
- [ ] 修改 `to_dict()` 回傳 payload 的根層及巢狀內容，不影響下一次 `to_dict()`。
- [ ] 兩次 `to_dict()` 的 context 不是同一個 object。
- [ ] 既有 44 tests 全部保持通過。

這些測試必須先對舊實作失敗，再由修正後實作通過；工作報告 008 說明失敗理由，不需要修改 frozen 報告 007。
