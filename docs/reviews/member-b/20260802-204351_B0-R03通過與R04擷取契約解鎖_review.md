## 9. R04 精確資料契約

所有 model 放在 `src/hotstock/domain/acquisition.py`，以 Pydantic v2 實作，並由 `hotstock.domain` 重新 export。公開名稱恰為：

```text
FetchRequest
RawArtifact
NormalizationIssue
NormalizedBatch
SourceHealth
```

`JsonValue` 可使用目前已鎖定 Pydantic 提供的正式型別；本輪不自行加入 JSON 第三方套件。

### 9.1 共通規則

五個 model 全部必須：

- `frozen=True`、`extra="forbid"`。
- import 無副作用；不開 DB、不讀檔、不連網、不取現在時間。
- 所有識別字串拒絕空字串與純空白。
- datetime 使用 `AwareDatetime`；naive 一律拒絕，aware 一律正規化到 `PROJECT_TIMEZONE`。
- 所有 JSON 欄位只允許 string／integer／finite float／boolean／null／array／string-key object。
- JSON 欄位拒絕 bytes、set、tuple 當 array 的靜默轉換、任意 object、非字串 key、NaN、Infinity、-Infinity。
- request／evidence JSON 遞迴拒絕疑似 secret key；大小寫與 `-`／`_` 正規化行為須與 `HotstockError` 一致。
- 建構後修改原始 input 或 `model_dump()` 回傳值，不得污染模型內資料。
- 直接嘗試修改公開 JSON mapping／sequence 的根層或巢狀值，也必須被拒絕，或只作用於不會回寫模型的 fresh copy；不得在建構後注入 secret。
- `model_dump(mode="json")` 必須可由 `json.dumps(..., allow_nan=False)` 序列化。
- 不得用 `Any`、模糊自由 dict 或自訂 class instance 穿越契約。

本輪不為共用化而修改 `errors.py`。JSON／secret 驗證可在 `acquisition.py` 使用 private helper；巢狀資料可採遞迴 immutable container 或私有 JSON snapshot＋fresh-copy property／serializer，但不得新增 dependency、不得改變 §9.2～§9.6 的外部欄位語意。若工程師認為必須改既有 error 實作或公開欄位才能完成，依 §12 停止，不得自行擴張範圍。

### 9.2 `FetchRequest`

| 欄位 | 型別 | 規則 |
|---|---|---|
| `source_id` | non-empty `str` | 來源登錄 ID；不得含來源實作物件 |
| `dataset_id` | non-empty `str` | 資料集 ID |
| `request_json` | JSON object | 已移除 credentials 的正規化請求參數；預設空 object |

`request_json` 的 key order 不得影響 model equality 或 canonical dump 的語意；但 R04 不實作 config hash 或 artifact content hash。

### 9.3 `RawArtifact`

| 欄位 | 型別 | 規則 |
|---|---|---|
| `artifact_id` | `UUID` | 必填；不得在 model 內隨機產生 |
| `request` | `FetchRequest` | 完整保留請求 metadata |
| `http_status` | `int | None` | HTTP 來源 100～599；非 HTTP 來源可為 null |
| `retrieved_at` | `AwareDatetime` | 必填，轉 Asia/Taipei |
| `content_hash` | `str` | **原始 bytes** 的 lowercase SHA-256，恰 64 個 hex |
| `mime_type` | non-empty `str` | 不做來源專用白名單 |
| `raw_uri` | non-empty `str` | Raw 實體位置；本輪不解析、不開啟 |
| `license_snapshot_id` | `UUID` | 必填；fixture 也使用固定測試 UUID，不得設 null |
| `source_run_id` | `UUID` | 必填；固定輸入，不自動產生 |
| `retry_count` | integer `>= 0` | 首次成功可為 0 |

`content_hash` 不得代表 canonical rows、標題＋摘要或 model dump；其唯一語意是原始 bytes SHA-256。

### 9.4 `NormalizationIssue`

這是 `NormalizedBatch.normalization_errors` 的結構化元素，不得以自由文字陣列取代。

| 欄位 | 型別 | 規則 |
|---|---|---|
| `code` | non-empty `str` | 穩定、可機器判讀的錯誤碼 |
| `message` | non-empty `str` | 人類可讀訊息，不含 secret |
| `row_index` | `int | None` | row-level 時 `>= 0`；batch-level 可為 null |
| `evidence` | JSON object | 可重現證據；預設空 object，不含 secret |

### 9.5 `NormalizedBatch`

| 欄位 | 型別 | 規則 |
|---|---|---|
| `artifact_id` | `UUID` | 只保存來源 RawArtifact ID，不內嵌或修改 Raw |
| `dataset_id` | non-empty `str` | 必須明確保留 |
| `rows` | tuple of JSON objects | canonical payload；預設空 tuple |
| `row_count` | integer `>= 0` | 必須精確等於 `len(rows)` |
| `normalization_errors` | tuple of `NormalizationIssue` | 預設空 tuple，可同時含多項 |

允許 `rows=()` 且有 errors，代表 normalize 未產生 canonical row；這不影響已存在的 `RawArtifact`。R04 不實作 normalize 函式，也不把錯誤寫回 RawArtifact。

### 9.6 `SourceHealth`

| 欄位 | 型別 | 規則 |
|---|---|---|
| `source_id` | non-empty `str` | 來源 ID |
| `dataset_id` | non-empty `str` | 資料集 ID |
| `checked_at` | `AwareDatetime` | 必填、轉 Asia/Taipei，不得 default now |
| `healthy` | `bool` | 不用字串狀態代替 |
| `message` | non-empty `str | None` | 可選的人類訊息；純空白拒絕 |
| `evidence` | JSON object | 可重現證據；預設空 object，不含 secret |

SourceHealth 不觸發 healthcheck、不發 request，只攜帶結果。

### 9.7 Public export

`src/hotstock/domain/__init__.py` 只新增 §9 的五個公開 model export；原有 16 個公開名稱不得刪除、改名或換值。`acquisition.py` 自己的 `__all__` 也只列五個 model，不把 private validator、secret fragments 或 Pydantic `JsonValue` 當穩定 API。

## 10. R04 單元測試要求

`tests/unit/domain/test_acquisition.py` 至少涵蓋下列類別；不得只測 happy path。

### 10.1 共通契約

- 五個 model 都拒絕 extra field。
- 五個 model 都拒絕欄位重新賦值。
- `model_dump(mode="json")` 全部可 `json.dumps(allow_nan=False)`。
- import 不讀檔、不取現在時間、不連網。
- 原始 mutable input 與 dump 回傳值被修改後，模型內容不變。
- 直接修改公開 JSON 欄位的根層與巢狀回傳物，不得污染下一次讀取或 `model_dump()`，也不得注入 secret。

### 10.2 JSON 與 secret

- 合法巢狀 object／array／scalar 通過。
- bytes、set、tuple、object、非字串 key、NaN、正負 Infinity 各有拒絕測試。
- 根層與巢狀的 `password`、`passwd`、`secret`、`api_key`、`api-key`、`apiKey`、`token`、`access_token`、`authorization`、`cookie`、`private_key`、`credential` 被拒絕。
- JSON 欄位不得標成 `Any`；mypy strict 必須實際分析 acquisition module。

### 10.3 `FetchRequest`／`RawArtifact`

- request 可保存固定 source、dataset 與 request JSON。
- RawArtifact 在沒有 NormalizedBatch 時可獨立建立。
- `license_snapshot_id` 或 `source_run_id` 缺少時拒絕。
- fixture 使用固定 UUID 的 license snapshot 可通過，不提供特殊 null bypass。
- malformed／uppercase／過短／過長／非 hex content hash 拒絕。
- hash 正向案例以固定 raw bytes 計算 `hashlib.sha256(raw).hexdigest()`，並與欄位相等。
- `http_status=None` 可供非 HTTP；99、600 與非 integer 拒絕。
- `retry_count=0` 通過，負數拒絕。
- naive `retrieved_at` 拒絕；UTC aware 輸入轉 Asia/Taipei 同一瞬間。

### 10.4 Normalize 解耦

- `row_count == len(rows)` 正向與反向測試。
- empty rows＋一個 `NormalizationIssue` 可建立。
- `row_index=None` 與 `row_index=0` 都合法，負數拒絕。
- 建立錯誤 batch 前後，原 RawArtifact dump 完全相同。
- 同一組固定輸入建立兩次，JSON dump 完全相同。

### 10.5 `SourceHealth`

- healthy true／false 均可表示。
- naive `checked_at` 拒絕，UTC aware 正規化。
- `message=None` 合法，空字串／純空白拒絕。
- evidence 走同一套 JSON／secret 驗證。

### 10.6 Export 與 regression

- `from hotstock.domain import ...` 可取得五個新名稱。
- `hotstock.domain.__all__` 保留全部既有名稱且恰新增五個。
- 既有 132 tests 全部繼續通過。
- wheel 內包含 `hotstock/domain/acquisition.py`，不含 legacy module。
