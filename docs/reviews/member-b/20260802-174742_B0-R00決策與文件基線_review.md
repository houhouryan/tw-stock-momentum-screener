### 2.2 後續固定的本地 commit 規則

專案經理核准以下規則，自本報告起適用：

1. 工程師完成一輪後先停止，不先 commit。
2. 工作報告最後出現 REPORT-COMPLETE 後，審查者才開始檢查。
3. 只有新檢查報告判定 PASS 且最後出現 REVIEW-COMPLETE，工程師才可建立該輪的本地收尾 commit。
4. 每輪原則上建立一個收尾 commit，內容包含該輪成果、該輪工作報告與對應檢查報告。
5. 若檢查未通過，先依修改指南修正並重新送審；未取得 PASS 前不得 commit。
6. 後續錯誤一律用新 commit 修正，不得 amend 或 squash 已有稽核紀錄。
7. 工程師不得 push、merge 或 rebase。push 由專案經理自行處理；merge 仍須另行取得明確指示。
8. commit 後若出現非預期檔案或工作樹未乾淨，不得自行擴大提交範圍，應停止並在下一份工作報告揭露。

### 7.4 pyproject.toml 的必要內容

1. requires-python 必須是大於等於 3.12 且小於 3.13。
2. 使用 src layout。
3. 明確指定 build backend；本輪採 Hatchling。
4. wheel package 明確指向 src/hotstock，避免把舊 src/*.py 打進新套件。
5. runtime direct dependencies 只能是：
   - pydantic
   - PyYAML
   - requests
   - typer
   - numpy
   - pandas
6. dev dependency group 加入：
   - ruff
   - mypy
   - pytest
   - types-PyYAML
   - types-requests
   - pandas-stubs
7. uv.lock 必須由 uv 解析產生，不得手工編輯。
8. pyproject.toml 與 uv.lock 是新系統依賴的唯一來源。

建議結構方向：

~~~toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "hotstock-tw"
version = "0.1.0"
requires-python = ">=3.12,<3.13"
dependencies = [
  # 僅 §7.4 核准的六個 runtime direct dependencies
]

[dependency-groups]
dev = [
  # 僅 §7.4 核准的開發工具與型別 stub
]

[tool.hatch.build.targets.wheel]
packages = ["src/hotstock"]
~~~

版本約束屬可逆的局部實作細節，可由 uv 依 Python 3.12 相容性解析並在 lockfile 固定；不得為追求最新版而加入未核准套件。若解析器顯示核准套件彼此無法相容，保留完整錯誤、將工作報告標為 BLOCKED，不可任意刪除核准依賴。

### 7.7 必須執行並附在工作報告的驗證

~~~bash
git branch --show-current
git rev-parse HEAD
uv lock --check
uv sync --frozen
uv run python -c "import hotstock; print(hotstock.__name__)"
git diff --check
git diff --stat
git status --short
~~~

另外附上以下靜態核對的命令與結果：

~~~bash
rg -n "feedparser|flask|gunicorn|instructor|openai|anthropic|scikit-learn|sklearn" pyproject.toml src/hotstock README.md
rg -n "from src|import src|src\\.db|src\\.sources|src\\.pipeline|run_news" src/hotstock
find src/hotstock -maxdepth 3 -type f -print
~~~

rg 無符合項時通常回傳 exit 1；工作報告要把「無符合項」與命令失敗區分清楚，不得只寫全部 exit 0。

為證明 import 沒有檔案副作用，至少做到：

1. 在新建的暫存工作目錄中列出 import 前檔案。
2. 從該目錄執行已安裝 package 的 import。
3. 再列出 import 後檔案。
4. 證明工作目錄沒有新增 DB、設定、log 或其他產物。
5. 同時目視附上 src/hotstock/__init__.py 全部行為的說明；本輪該檔應足夠小，可確定沒有網路與 DB 呼叫。

不得為了這項驗證改用會刪除 repo 資料的命令。暫存目錄只用系統安全方式建立，驗證後可保留或安全清理。
