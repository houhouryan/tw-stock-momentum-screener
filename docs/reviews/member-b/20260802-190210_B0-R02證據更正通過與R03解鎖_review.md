## 9. B0-R03 error 精確契約

### 9.1 最小公開介面

`src/hotstock/domain/errors.py` 建立：

- `ErrorCode(StrEnum)`
- `HotstockError(Exception)`
- 只為安全 JSON context 所需的私有驗證 helper／型別

`ErrorCode` 恰有七值：

```text
SOURCE_TRANSIENT
SOURCE_PERMANENT
DATA_QUALITY
PIT_VIOLATION
MODEL_OUTPUT
CONFIG_INVALID
INFRASTRUCTURE
```

member 名與 `.value` 都使用上述大寫字串。

### 9.2 `HotstockError`

建構介面固定表達：

```text
error_code: ErrorCode
message: str
context: Mapping[str, JSON-safe value] | None
```

要求：

- `message` 必須非空。
- `context` 預設為空，不使用 mutable default。
- `context` 只接受可由標準庫 `json.dumps(..., allow_nan=False)` 序列化的值。
- 拒絕非字串 key、任意物件、bytes、set、NaN、Infinity。
- 遞迴檢查巢狀 dict 的 key；key 經小寫並移除 `-`、`_` 後，只要是或包含 `password`、`passwd`、`secret`、`token`、`apikey`、`authorization`、`cookie`、`privatekey`、`credential`，即拒絕。
- 建構後保存 defensive copy；呼叫端後續修改原 dict 不得改變 exception 內資料。
- `str(error)` 與預設例外訊息只顯示 `message`，不得把 context 自動印入 log。
- 提供 `to_dict()`，輸出恰含 `error_code`、`message`、`context`，且整體可 JSON 序列化。
- 不在 R03 實作 retry、通知、HTTP status mapping 或 adapter 專用 subclass。

七類的處理行為仍由後續 orchestration 實作；R03 只凍結分類與安全攜帶資訊的契約。

### 10.3 時區與 invariant

- datetime 使用 Pydantic `AwareDatetime` 或等效嚴格驗證。
- naive datetime 一律拒絕，不得靜默視為 UTC。
- 已帶時區的 datetime 明確正規化為 `ZoneInfo("Asia/Taipei")` 後保存。
- `event_date` 保持純 `date`，不得轉成午夜 datetime。
- `system_available_from == first_seen_at`。
- `retrieved_at >= first_seen_at`。
- `pit_mode == system` 時，`available_from == system_available_from`。
- `pit_mode == public` 時，`public_available_from` 不得為 null，且 `available_from == public_available_from`。
- 不得使用 `max(published_at, first_seen_at)` 或任何方式把 public/system 兩個時間合併。
- 不得從 `published_at` 自動推定可信度；呼叫端必須明確傳入 public time。
- 不讀取 `datetime.now()`、系統日期或環境設定。

這裡只驗證 metadata 自身一致性，不實作 as-of 查詢、revision 選擇、21:25 manifest 或決策時間 leakage 判斷。

- 不 re-export 私有驗證 helper。
